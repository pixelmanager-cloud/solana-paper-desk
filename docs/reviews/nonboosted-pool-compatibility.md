# Narrow profile1 canonical pool compatibility

Explicit `paper_token_profile_version=1` now supports canonical Token-2022 LP mints only when exactly82 bytes, initialized with decimals9, no extensions or freeze authority, pool mint authority, and zero circulating supply. All existing canonical pool/LP PDA, vault, global/dynamic fees, base-token and control checks remain. Legacy profile0 behavior is preserved.

For profile1, admit fee-bearing pools only when the exact integer identity `virtual_quote_reserves + protocol_fees + creator_fees == 0` proves no boost. Use `quote_reserve_raw = effective_quote_reserve_raw = spendable_quote_reserve_raw = gross_quote_reserve_raw - protocol_fees - creator_fees`, subtracting exactly once. Reject zero/negative spendable balance, invalid effective u64 balance and every nonzero derived boost. Signed virtual reserves are retained and never cast unsigned. Original raw snapshot/hash is unchanged; the verifier returns gross, fees, signed virtual, derived boost and effective/net quantities separately. Ingestion checks their equivalence, exposes gross/fee/virtual amounts separately, and provides net through existing `reserve_lamports`, `reserve_sol` and spot-price fields. Shared replay feeds entry, held exit, valuation and sizing the same net semantics. No local fee deduction is applied again to provider quote output.

Primary evidence: official `@pump-fun/pump-swap-sdk`2.1.0 git `0bc59090bbd0b8d6c27b8df72d52e30bfc069c3b`, checked against pinned package integrity in `desk/schemas/fee_sdk_manifest.json`. [SDK LP ATA derivation](https://unpkg.com/@pump-fun/pump-swap-sdk@2.1.0/src/sdk/pda.ts) uses Token-2022. [SDK sell math](https://unpkg.com/@pump-fun/pump-swap-sdk@2.1.0/src/sdk/sell.ts) prices with gross+signed virtual and limits payouts using gross-fee buckets. The [official fee/reserve documentation](https://github.com/pump-fun/pump-public-docs/blob/2293f9a66c654e9fe82dc5e8f4618538f24bb35f/docs/VIRTUAL_QUOTE_RESERVES_FEE_ADJUSTMENT.md) establishes derived boost and nonboosted equivalence. Initial zero-virtual-with-fees wording was superseded by this verified identity; that case remains blocked.
