# Disconnected common-bank journal (slice 2)

Base: `b4cbfaf588412cbd49a94f66b12abfa3f5b1c9a1` (accepted PR82 design).

`desk/common_bank_journal.py` installs an immutable run/plan journal in an existing evidence database. It requires an existing SEALED admission with the original shared ceiling exactly 18, the exact completed research source, legacy mint policy, raw verified initialization frontier, canonical base-vault membership and no fixed canonical bank. It never creates/adopts a budget or converts legacy sources. A UNIQUE budget binding prevents restarting under another capture ID.

The source-discovery profile deliberately freezes only the original SEALED source's raw discovery revision; it does not adopt a later ownership head or continuation frontier. P is independently derived, F is sorted raw initialization inventory (including closed accounts), and U is canonical P followed by sorted F minus P, bounded at 100. Exact source/descriptor hashes, planned source configuration, canonical database paths and device/inode identities, projections and evidence references are frozen and rederived on every operation. Planned `ApprovedSource` configuration is an identity binding, not proof that a source/transport is authenticated or approved for a new union receipt profile.

Lock order is research worker, ownership invocation, ownership request. Acquisition is nonblocking; research read guard holds the exact source stable. Database identity is checked before and after each operation. A PID/thread-bound session expires on exit. No nested public lock-taking persistence API is called. The only existing-module hook is `HistoryProgress.inspect_admission(connection, identity)`: the existing admission validator extracted as a static read-only validator in the caller's transaction. Its previous `_admission` wrapper delegates to it; validation is unchanged for production callers.

The journal audits exact owned schema/trigger SQL and existing admission/page/counter column profiles, rejecting unreviewed triggers on those existing tables. WITHOUT ROWID tables and BEFORE INSERT conflict checks block replace deletion; update/delete triggers protect descriptors and events. The installation also claims an otherwise-zero SQLite application_id (`0x43424A31`). Missing metadata/schema after installation cannot silently initialize again. Existing nonzero unrelated application IDs are rejected, not migrated. This marker is new header metadata; original pages, admissions, sources, history and canonical records remain unchanged. As with existing local persistence, a trusted OS owner able to rewrite the entire database/header or replace lock files is outside SQLite trigger authentication; this is not a cryptographic hostile-owner boundary.

`reserve_stage` supports only the initial fixed `genesis/getGenesisHash/[]` intent. It verifies the immutable fence and lower bound (four setup charges plus at least one mint page and one page per frontier account). The existing shared counter increment and immutable ordinal-1 PENDING intent are committed in the SAME SQLite transaction, with FULL synchronous rollback-journal durability. The insertion checks its charge witness. Neither a transaction nor this module invokes provider I/O. A failure before commit rolls both back. A committed PENDING intent is terminal uncertainty on restart, with no retry, refund, successor stage or replacement capture ID. Later legitimate shared-counter consumption is allowed; rewinding below the committed intent fails closed.

No DONE/completion/provider/canonical bank/head/receipt migration or issuance API is implemented. There is no dependency on worker01's unfinished common_bank_view API. Further reviewed slices must bind the validated union response and clock, implement immutable successful stage transitions without replaying uncertain requests, and coordinate bank/head publication and receipt-kind migration. The initial intent cannot execute those tasks. All exposed eligibility/ownership/chain authentication flags remain false. Synthetic fixtures prove persistence contracts only, not live source acceptance or OWN-2/3 completion.
