Reviewed baseline: `7b05a68147a1f13819d6283ab5fe77bad78c2f95` (PR56 integrated through `745622f`). Read the accepted lifecycle/trace/native reports, raw capture, ownership acquisition/snapshot/continuation and protected receipt contracts, readiness and task queue. This document changes no requirements, code, schemas or authorization. Coordinator update: PR57 is accepted at integration `6477670` with a TradeEvent-only allowlist; newer CreateEvent shapes remain unapproved. This report does not duplicate its schema changes. All current approvals remain false.

**Finding:** standard finalized `getTransaction` plus *authenticated, slot-applicable executable semantics* can support a proof of narrow fresh-account token transitions without historical account bytes. It cannot by itself satisfy the current graduation requirements for independent transaction-bound raw pre/post bytes, complete CPI return/privilege traces or arbitrary parent/intermediate effects. Public IDLs, outer success and matching net balances are insufficient. The next useful implementation is a disconnected transaction/log/return witness join followed by explicit semantic proof obligations; fetching old account bytes through `minContextSlot` cannot work.

## Obtainable completion path and contract decisions

1. **Implement the zero-RPC witness join first**, disconnected: signed-message verification, strict frame/inventory/log/return binding, and separate callee program-return versus final syscall-outcome obligations. Reject caught/ambiguous outcomes; do not set success from log counts. Preserve all control witnesses and reuse accepted PR57 without additional schema work. This immediately turns existing unstructured logs/returns into reviewable evidence without new collection.
2. **Require an executable semantics manifest before positive proofs:** program ID/loader/binary digest, audited handler and caller implementation, runtime/features, effective slot interval and source/capture refs. Prove critical-call error propagation or every post-log failure obligation. For fresh mint/ATAs, use verified System/Token-2022 transitions to prove initialization, exact extensions/roles, issuance, metadata/mint revocation, then distribution; reject unsupported branches. No authenticated program-slot manifest is currently present, so this remains a prerequisite, not an asserted feasible success on the saved sample. Check that prerequisite before spending on history; if absent, at most the bounded deployment-feasibility capture is useful, then stop rather than chase unavailable S bytes.
3. **Anchor actual raw state at obtainable T and replay complete history to it.** Discover the full initialization frontier, persist one finalized bank of mint + all required token accounts (existing bound: at most99 accounts plus mint), freeze T and exhaust slot-bounded mint/account histories through T. Match raw controls, supply and amounts to actual T bytes, including later supply changes. Never substitute slot454452430 confirmed state for S, enforce a fictional10^15 current supply, or ignore burns/transient controls. More/new accounts or unresolved pages/operations stop the proof. Existing snapshot/continuation code is legacy-only and rejects Token-2022: a future dedicated reviewed research contract is required, not bypassing those policies.
4. **Review the evidence contract explicitly.** A proposed ownership-control certificate should distinguish observed raw state at T, mathematically derived birth state predicates, specific proved effect obligations and unresolved economic/entry evidence. The present S/signature-bound raw endpoint and independent prestate requirements cannot accept that certificate. Changing to a proved equivalent obligation is a coordinator/reviewer decision with adversarial tests, not a boolean override; if exact independent transaction-level S bytes and full syscall/privilege traces remain mandatory, the saved sample cannot graduate through standard RPC. Prior account-write capture or exact historical ledger/bank execution replay is necessary. Ordinary Geyser/account-write streams may help future endpoints with transaction/write-version binding, but do not inherently expose individual CPI returns, seed arrays or intermediate effects.

## Request budget: bounded opportunity, not a completeness promise

Saved diagnostic usage is **2/18**, and this review/replay adds **0**. A future authorized attempt must reuse that immutable admission/counter, reserve before every request, persist exact requests/responses and terminal failures, never automatically retry, hide setup/chunks, refresh an old cutoff, or create a new ID to escape ambiguity. `RawTransactionCapture` currently permits only one diagnostic transaction per admission; multi-record witness capture needs a separately reviewed contract. `source_id`/hashes and a private receipt ledger establish local provenance, not Solana truth. The existing pool bridge's four-stage genesis/slot/GMA/block-time flow is pool-scoped and cannot issue launch acceptance receipts.

| Prospective additional method attempts | Upper bound / stop rule |
| --- | --- |
| Approved-source genesis and finalized floor | 1 getGenesisHash +1 getSlot; only approved already-saved request witnesses reduce new calls |
| Birth block inclusion/order | 1 getBlock(S); metadata never supplies historical account bytes |
| Program/header/ALT/config metadata batches | At most2 getMultipleAccounts; exact account/response bounds, no unbounded executable download hidden here |
| Actual ownership bank T + clock | 1 getMultipleAccounts +1 getBlockTime(T); reject frontier>99 or missing/contradictory state, preserve returned T |
| Full histories, raw follow-ups, extra ordering, uncached executable/deployment/config/funding evidence | Every page/follow-up/chunk counts; at most9 remaining attempts after the above7 and existing2 |

Thus `2 + 7 + H_mint + ΣH_accounts + H_config/deploy/funding + N_raw + B_extra + C_binary + R_other ≤18`. An illustrative small frontier can spend2 mint pages,4 account pages across two accounts,2 raw follow-ups and1 extra ordering block: total18, **only if all ranges exhaust and all other prerequisites are already independently evidenced**. This leaves no requests for missing binaries, configuration histories, additional accounts or pool/exit RPC evidence; they must replace allotted attempts or the attempt remains incomplete. Existing ordering bound stays at most2 blocks including the birth block. Provider-specific full history pages are not standard Solana RPC; reuse their persisted filter/exhaustion contracts, not a caller completeness flag. Standard signature-history fallback generally costs substantially more. Metadata batches are not a promise that whole ELF binaries fit the transport's2 MiB response bound or the pool ledger's64 KiB evidence contract.

**Unavailable from standard RPC:** arbitrary past-slot account bytes; immediately-before/after-transaction byte snapshots; final individual CPI syscall return codes/AccountMeta privileges/PDA seed arrays; arbitrary intermediate parent writes; old overwritten ProgramData/global/fee state without archives. `getAccountInfo`/GMA select a current commitment bank and merely require its slot≥minContextSlot; `getFeeForMessage` and simulation also use selected current banks and cannot reconstruct the old launch bank. No number of repeated requests within18 repairs these omissions. [R1,R4,R5]
