# Critical path to one supervised live-data paper entry

Source inspected: **`b449b922e68d19cba45953d4ab815677d1c3cbb9`**, integration/cloud-wave1 (`b449b92`). This is a source/design review, not a provider run or readiness declaration. Only this document changes. The remote branch advanced during inspection; findings and validation below belong to this exact base, not an unreviewed later head.

**There is currently no executable provider-evidence → eligible decision → paper entry path.** `decision_runner.assess()` always returns REJECT; `entry_evidence.evaluate()` always returns eligibility false with unresolved transfer/bundle/route/strategy gates; `engine.transition()` independently rejects every nonsynthetic entry with `LIVE_FEATURE_ADAPTER_NOT_READY`. These are deliberate gates, not switches to disable for a demo. A normalized JSON file asserting safe flags is not a live adapter.

The shortest honest target is one coordinator-selected, actually eligible supported candidate, one durable simulated buy, ongoing fresh marks, a fresh exact-size proof for one full exit, and a restart proving the same position/outcomes. Selection and supervision may limit dispatch to one candidate; they cannot waive any evidence, strategy, age, cost or route requirement. Worker07 owns whether an obtainable supported launch/ownership candidate can satisfy acquisition within the existing budget. This report consumes that dependency; it does not repeat seed searches or propose admitting Token-2022 to obtain a positive result.

## Missing contracts, by consumer

### 1. Source-bound current feature snapshot

Proposed new module/API, **not present**: `desk/live_features.py::build_candidate_snapshot(source, revision, store, now, config)`. Start read-only and reject-only. Its output should be a versioned diagnostic with value/unknown/source hashes per field, exact mint/pool/program/slot/time scope, replay identity and blocking reasons. It must not return a valid market event when required fields are missing, and must not take completeness/approval booleans from caller JSON.

The builder must supply the full existing `model.validate_event()` contract; these groups have distinct evidence requirements:

| Engine inputs | Required derivation; missing means blocked |

| `mint_revoked`, `freeze_revoked`, `extensions_safe`, `token_evidence` | Replay exact current mint account and control policy; explicit absence differs from unknown. Preserve ten-second token freshness and current Token-2022 exclusion. |
| `lp_verified`, `reserve_sol`, `reserve_tokens`, `pool_fee_bps`, `price_at` | Replay atomic pool/vault/LP/global/dynamic-fee snapshot; define net usable reserves and exact fee schedule for the admitted route. | `sol_usd`, `market_cap_usd` | Bound price source, time, units and mint supply valuation; no configured synthetic SOL/USD or asserted cap substituted for live observations. |
| `top10_pct`, `dev_pct`, `bundle_pct`, `cluster_pct`, `fresh_wallet_ratio`, `holder_at`, `bundle_evidence` | Complete relevant holder/transfer/control history plus verified vault/service labels, creator bindings and funding evidence. Strategy currently requires graduated PumpSwap, market cap $50,000–$2,000,000 and liquidity at least $8,000. That is future reviewed integration, not a change authorized by this report. Preserve original decisions and evidence revisions. A historical report's old `observed_at` must not be edited to make a current decision look fresh.

### 2. Exact quantity, wallet, proof and fill contract

`security.sellability_gate()` presently accepts a normalized `sell_simulation` dictionary with exact `quantity_tokens`, matching `mint`/`wallet`/`taker`, transaction/route hashes, slot, ten-second observation time, three true flags and positive `net_proceeds_sol`. It does **not** load and recompute those flags from persisted evidence. Its comment explicitly delegates trust to a future adapter. It cannot become the authority boundary merely because a dictionary satisfies that schema.

`simulate_sell()` returns `diagnostic_sell_simulation`, `amount_raw`, atomic effects and account controls, not this engine proof. `simulate_roundtrip()` returns `unsigned_buy_partial_sell_diagnostic` and sells only the buy minimum; surplus may remain. Neither can be relabeled as `sell_simulation` or have `transaction_policy_ok` set true by a mapper. A future proof builder must replay/bind raw request/route/compiled bytes/lookup/simulation/pool inputs, validate full policy, wallet/holding identities, exact debit and net proceeds, and expire proofs at application time. Hash-shaped strings are insufficient.

The engine currently computes Decimal model quantities using `strategy.swap_quote()`, whereas simulations consume integer raw amounts. Specify token decimals, deterministic raw-unit rounding and the final paper quantity **before** requesting size-specific evidence. Bind entry SOL amount, bought quantity, holding/scenario, position/event identity, exact exit quantity, slot/time and source revision; reject different decimals, one-unit mismatch or residual inventory not accounted for.

Paper inventory is not on-chain inventory. The public holder chosen by `screen.screen()` is a representative diagnostic identity, not the eventual paper position's wallet. `simulate_sell()` requires a real funded public wallet holding the amount; a hypothetical paper buy does not create that holding. The future demonstration must define and verify an unsigned sequential hypothetical buy/sell scenario or another independently reviewed inventory model, preserving initial-state/authority and quantity bindings. Never claim the position owns chain tokens, use a representative holder's proof as wallet-specific acceptance, or add signing/broadcasting.

`engine.transition()` records a constant-product research buy with configured fixed fee. `engine.sell()` caps model proceeds by supplied simulation net proceeds, but quantities/price impact remain modeled. Entry cost budgeting reserves five fixed fees and explicitly excludes rent. Define conservation of raw inventory/cost basis, network/priority fees, rent paid/refunded, failure cost and partial inventory; avoid deducting a fee twice when the atomic native delta already includes it. A first paper demo reports modeled accounting with measured bound evidence and hypotheses; it does not report actual executed chain fills or profitability.

### 3. Position observation versus action proof

There is a concrete partial-exit contract conflict: `manage_position()` first calls `position_sellability()` for the **entire** current quantity, then a take-profit rung calls `sell()` using a fraction of `initial_qty` with the **same** event proof. `sellability_gate()` demands exact equality for both. One real proof cannot cover both different sizes. `test_cloud_ledger_restart.test_full_position_proof_cannot_authorize_partial_rung` verifies rejection, not working live ladder exits.

The smallest first demonstration should use a full exit, where valuation and action sizes coincide, after an actual policy trigger or an explicit operator LIQUIDATE request followed by fresh evidence. Operator control changes mode; it does not sell without a market observation/proof. Do not fabricate danger, prices or a threshold crossing. Ladder triggers must remain blocked when their exact proof is absent. Before partial exits, separate a full-position valuation proof from a distinct action-quantity proof and requote each rung; do not weaken exact-size matching.

`monitor.tick()` is already the safe no-provider outage fallback. The future bounded refresh driver must evaluate open positions before new-entry work, keep EXIT_ONLY latched after unresolved exits, and avoid silently RESUME-ing after a proof recovers. Refresh requests need an explicit bounded durable accounting contract; do not reset/fork the original 18-RPC investigation allowance or create uncharged diagnostic admissions. Budget exhaustion is an honest blocked observation, not permission to infer a fill.

### 4. Durable join and restart reconciliation

Proposed future component, **not present**: a supervised one-candidate driver with a durable work record linking source/admission, decision policy+revision, feature version/hash, proof hashes, config/implementation hash, position and intended ledger `event_id`. Raw evidence must be durable before eligibility; accepted intent must be recoverable before applying a fill. `Ledger.apply()` already provides the final atomic event/outcome/state commit.

Decision journal and paper ledger are separate SQLite files. Do not assume one transaction spans both or use a watermark that loses a pending intent. A deterministic event identity plus retry/reconciliation/outbox protocol must ensure: crash before intent causes no fill; crash after intent but before ledger commit retries only after freshness validation; crash after ledger commit but before driver acknowledgement discovers the existing event and does not fill again. Redelivery with changed bytes remains an error. A stale pending proof must block a new fill while preserving already committed original events.

On restart, read the immutable experiment identity and last committed state/outcomes first; reconcile pending work to ledger events, expire old marks through `monitor.tick()`, and obtain fresh exit evidence before any new fill. There is no external chain order to reconcile because nothing was signed/submitted. Reconciliation concerns saved paper inventory, costs, work/evidence and liveness. Config/code drift requires a new experiment; explicit migration is a separate reviewed contract. Keep original databases and historical decisions.
