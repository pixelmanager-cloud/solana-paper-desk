## Concrete obligation

Require bound, distinct, existing legacy SPL base/WSOL vaults. Independently compare the sell's raw discriminator/layout/ordered named accounts against the pinned PumpSwap schema and exact checked instruction receipt; enforce fixed program identities. Retain the exact enclosing Jupiter/Pump frames as unresolved effect context rather than assuming they do nothing. Every other supplied instruction mentioning a vault must be an exact legacy Transfer/TransferChecked directly under the bound Pump sell, with a unique numeric instruction path, expected mint/authority/source/destination role and checked decimals where applicable. Unknown programs, mint/burn/approve/close/sync operations and malformed or extra accounts reject, including zero-valued operations. Base input sums and minimum user output also bind the raw sell arguments. Recipient bindings are existing diagnostic evidence, not newly granted permission.

Compute signed per-vault changes once per path, treating self-transfers as zero net change. Compare them to provider-reported pre/post raw token amounts, retaining individual token and lamport residuals. Bind both endpoint metadata identities/decimals and the post amount to exact 165-byte initialized legacy account bytes, mint, pool authority, program ownership and lamports. Invalid COptions, delegates/allowances, explicit close authorities, frozen state and unknown layouts reject. Never infer a missing endpoint from zero lamports.

The WSOL quote vault must have native COption Some, decimals9 and a raw native reserve. Post lamports minus that reserve must equal post token amount. Pre lamports minus the **observed post reserve** must equal pre token amount, and lamport delta must match transfer delta. This tests a constant-reserve equation; it does **not** fabricate historical pre bytes or prove that the reserve/control state never changed transiently. The non-native base vault must have native COption None and unchanged lamports.

Bounds: 64 unique resolved keys, 256 supplied instruction rows, 64 ordered accounts per row, 16-character canonical instruction paths, 1644-character instruction base64, 64 rows per token endpoint, exactly key-count post accounts/native balance vectors, and exactly165 decoded vault bytes. All numeric balances/indices are strict integer u64; raw amounts are canonical bounded decimal strings, not floats or coerced booleans. Source inputs and public records are not mutated.
