# Bounded busy-history processing

Base: reviewed PR203 `aff78b38ecb4f9f51518cf8f92ce5a0122d4ed2d` on accepted `ee07b89dcb43dd79fc961eee89a5e05cb7caee4f`. The PR203 dependency is explicit; do not cherry-pick it twice.

New entry preparation writes `history_first_paper_preparation_v3` with `feature_semantics_version=2`. Its feature calculation reads repeatable original manifest/response references one page at a time. It retains at most 256 transaction hashes/identities/timestamps and 1,024 supported trade operands; decoded observation counts are capped at 256 per record and 4,096 total. Every original record, event, request, response, cursor, ordering and timestamp is validated. No page/record/request ceiling is increased: eight feature pages, 256 records, 128KiB per record, 2MiB per retained page and the existing 18-request investigation ceiling remain. Preparation stays 18 seconds, with seven fresh requests reserved for Kraken and the existing handoff/freshness requirements.

The old 2MiB aggregate ceiling represented a materialized history working set. Streaming semantics replace that working set with page-local decoding and bounded operands; they do not retain all raw pages or decoded trees. The existing invocation byte cache is separately bounded and stores immutable bytes only. Retained hashes and original saved pages remain mandatory; no normalized feature input or completeness flag replaces them. Partial provider queries remain incomplete and cannot emit MEASURED_WINDOW or authorize entry. Missing evidence, contradictory order/time, malformed inputs and known hazards still reject.

Existing v2 preparation intents explicitly select legacy feature semantics 1, including the original 2MiB aggregate rejection. Their existing NO_ENTRY receipts are replayed unchanged; new calculation does not rehabilitate old rejected scans. A historical fixture uses that original version deliberately and verifies original publication/replay. New v3 dispositions still use the existing immutable rejection table and receipt format, with semantics bound through their original intent hash.
