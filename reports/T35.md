# T35 — Batched on-chain portfolio marks (`paper_portfolio_mark_source_version: 1`)

Branch `cloud/T35`, BASE `origin/cloud/T16G` + merge of `origin/integration/r1`. `desk/` changed: the implementation hash changes; rotate store sets. Decision followed: the held-mark TTL is NOT relaxed.

## What
- `desk/portfolio_marks.py` (new, pure): flag + pool-fee-hypothesis validation, reserve-implied pricing (parity with `tools/ops/held_watcher.implied_ratio`: orientation, decimals, pool fee, PumpSwap creator fee, virtual quote reserves, Token-2022 transfer fee from retained mint evidence), derived vault ATAs, one `getMultipleAccounts` key list (pool + base vault + quote vault per position), response parsing with per-position verification against the pool account, same-slot pair rule, strict `portfolio_marks` event.
- `desk/engine.py`: the event kind (flag required, otherwise "unknown event kind" as before) writes only `portfolio_mark_value/at/source`; `valuation()` feeds equity, the `STALE_PORTFOLIO` gate and day rollover. `mark_at`/`mark_value`, exits, watchdog and every SELL fill are untouched; a marks event cannot cure a blocked exit; a partial sale drops the stale portfolio mark; older observations never replace newer.
- `desk/paper_cycle.py`: `fulfill_quotes(..., pre_decision)` refreshes before planning and again after the quote reads; a positions-less monitoring cycle refreshes at the start of a held pass; each refresh is one charged monitoring request (checked before/after), retained as original evidence, applied as a ledger event, and any failure only leaves marks stale. Its own 5 s read bound is excluded from the 10 s entry deadline.
- `desk/paper_monitor_service.py`: refresh cycle before the exit legs (its failure never stops the legs).
- `desk/monitoring_budget.py`: one additive request shape for the batched call (accepted only when the flag is on and the key list equals the checkpoint's derived list).
- `desk/paper_concurrency.py`: with the flag the relaxed TTL key is not required, and the start-of-tick age estimate (meaningless once marks refresh in-cycle) is skipped.
- Out-of-OWNS edits, flagged: `desk/paper_cycle.py`, `desk/monitoring_budget.py`, `desk/paper_concurrency.py`. They were necessary for the 10 s rule and for charging the batched read; `held_watcher.py` is not touched (math duplicated, parity tested).

## Limitations (honest)
- The reserve-implied mark ignores pool protocol/creator fee balances held in the vaults (not visible in a vault-only read) and uses the operator fee hypothesis in config; it is a valuation estimate, not an executable price.
- The fake chain is synthetic (real PDAs/ATAs and pool layout, invented balances); no live RPC. Real `getMultipleAccounts` latency is not measured; the entry cycle can now run up to about 10 s plus two 5 s refreshes.
- A non-transient transport failure code on a marks read (for example `RESPONSE_INVALID`) latches the monitoring allowance via the existing `_latching_failure` rule; connection resets, timeouts and 408/429/5xx do not. Parse/verification problems in the answer do not latch.
- `RESERVE_PASSES`/monitoring reserve arithmetic was not retuned for the 2 extra requests per entry and 1 per held pass.
- Pool-fee hypothesis is one value for all positions.
