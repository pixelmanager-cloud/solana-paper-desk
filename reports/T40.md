# T40 — Candidate feature store (as-of features)

Branch `cloud/T40`, base `origin/integration/r1`. Paper only; no `desk/` change (implementation hash unchanged). No provider access.

## What changed
- `tools/research/features.py`: append-only `features.sqlite` (rows per `(mint, as_of, feature_set_version)` with per-feature provenance, conflicts table, ingest runs, UPDATE/DELETE triggers), `init/ingest/verify/export-jsonl/shadow-features` CLI.
- Sources (all read-only): ledger market events + outcomes, discovery hints (via `funnel_report.discovery_hints`), dispatcher journal, counterfactual samples, decision journal (+ research scans for mint mapping).
- `deploy/fresh/desk-features.service` + `.timer` (offline research unit with T39-style CPU/IO/memory limits).
- `tests/test_features.py` (36 tests), `docs/research/FEATURES.md`, one line in the expected-unit set of `tests/test_ops_healthcheck.py`.

## Evidence
- RED on BASE: the module and units do not exist there (`ModuleNotFoundError: tools.research.features`, missing `desk-features.*`).
- Tests use the real writers: `Ledger.apply` + `engine.transition` (real outcomes and reject reasons), the dispatcher DDL, `counterfactual.init/add_candidate`, and one end-to-end test on the real stores of a dispatched paper entry (actual discovery frame, journal, ledger, research DB).
- Adversarial: look-ahead stamps (holder/price/flow/token/bundle/graduated), missing measurement time, evidence after `--now`, corrupt values, tampered rows (`verify`), conflicting re-ingest, symlink/hardlink/missing inputs, existing/symlinked output, input stores byte-identical after ingest, order independence.
- Mutation: 50 single-point mutants (logic + unit/timer directives). 4 survive and are equivalent: the second look-ahead guard in `_market_event` (Collector.add drops the same value with the same counter), `O_NOFOLLOW` on `export_jsonl` (`O_EXCL` already refuses a symlink), `BEGIN IMMEDIATE` vs `BEGIN` (single writer), and a redundant role check once the source check exists.
- Commands: `.venv/bin/python -m unittest tests.test_features tests.test_ops_healthcheck` (all OK).

## Limitations
- T33 regime metrics are not read (no such evidence in this base). The T27 `--features` format has one as-of per mint, so shadow variants only see the first recorded event's features; time-varying rows go through the JSONL export.
- Decision-journal rows carry no time in the observed schema, so most are skipped and counted.
- The unit was not loaded in a real systemd (`systemd-analyze verify` + a dry run on the VPS needed); the `mode=ro` WAL read under `ReadOnlyPaths` follows the counterfactual unit's pattern.
