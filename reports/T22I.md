# T22I — T22H regression in the retirement-receipt modules + small hold gaps

## Findings
The queue's diagnosis (a pre-transport `DEADLINE_EXCEEDED`) is only half of it. Two causes, both fixed in `desk/history_progress.py`:
1. **The 28/21/10... receipt errors.** `test_paper_preparation_retirement` builds the historical production state through the real
   interfaces: an oversized response (`RESPONSE_OVERSIZED`, a latching retained original) used to leave the reservation
   `RETRYABLE_ERROR`, attempts 1. T22H made that failure propagate with the checkpoint left `PENDING`, so the receipts' exact-state proof
   ("Exact initial failed preparation reservation required") no longer matched. Fix: when the failure carries a RETAINED, readable failed
   attempt original that is NOT proven transient, the checkpoint is marked `RETRYABLE_ERROR` and the error STILL PROPAGATES, so the pass is
   classified and held by its real cause (nothing becomes closable; the state carries no evidence, so a later cycle that finds it holds).
   An original that is missing, unreadable, not a `paper_read_attempt_v1`, or not a failed attempt does not mark anything.
2. **Item 1 (pre-transport deadline).** `PaperReadError('DEADLINE_EXCEEDED')` with no evidence hash, EXACT class `PaperReadError`
   (a subclass is not accepted), is the pager's `RETRYABLE_ERROR` (`_pre_transport_transient`). Only that code: it is the only code
   `PaperHistorySource` raises after the reservation and before transport that is transient. Every other evidence-less failure (bare
   OSError, digest conflict, cached request mismatch, binding/reservation/request codes, TLS, `TRANSPORT_ERROR` without an original,
   free-text ValueError) still propagates and holds.

## Other items
2. **Hold-file write failure.** `_hold_dispatch` tries two independent durable locations (beside the journal, then beside the evidence
   database); `_held` checks both with `lexists`. If both fail, `DISPATCH_HOLD_NOT_DURABLE: ...` is printed to stderr and recorded, and
   every further `dispatch()` in the process raises `DispatchHoldFailed` (fail closed). Limitation: that refusal is per process; a new
   process has nothing durable to read (by definition both mechanisms failed) and relies on the 900 s owner/latching-evidence proof.
3. **Swallowed exceptions.** A failure inside `classify` writes a hold (`DISPATCH_CLASSIFY_FAILED:<type>`); a failure inside
   `_close_dispatch` writes a hold (`DISPATCH_CLOSE_FAILED:<type>`) and leaves the intent unresolved. Note this makes an *expected* close
   refusal (store still latched) a hold too, as the task asked.
4. `recover_abandoned` checks sentinels with `os.path.lexists` (dangling symlink holds).
5. Closure `_consistent` now matches publish: INVESTIGATION needs a scan with `after == 18`; CYCLE needs a scan charged exactly 18;
   FEATURE_HISTORY_PAGE_LIMIT needs 8 distinct RETAINED `getTransactionsForAddress` attempt originals among the closure's references
   (charges alone no longer count). `tests/test_t22h_holds.py::test_the_conditions_themselves` was adapted (history-page case moved to
   `tests/test_t22i.py`).
