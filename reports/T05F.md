## Findings and fixes
1. **Owner check** - the check compared file owners with the euid of the (root) process, so it could never PASS on the VPS. New `--expect-owner USER|UID` (default: owner of `--data`, source reported); `_live_findings` compares against that. Blockers read `LIVE_<what>:OWNER_<found>_EXPECTED_<uid>`; the report carries `expected_owner: {uid, source}`. Unknown user = REFUSED. Injectable `tool._stat` / `tool._getpwnam`; tests simulate a service user that is not the running uid.
2. **Fresh store set** - fail-closed behaviour kept, no bypass. New `blocker_details` names exactly what is missing (`paper-scheduler.lock` relative to `--data`, the dispatcher journal) and which step creates it (`tools.ops.fresh_start apply`, T13F pre-creates the lock and activates the journal). `JOURNAL_ABSENT` is now also raised by the parent when the journal file is absent even if a stage failed earlier (e.g. no `--taker`). The missing-required-store refusal also names the bootstrap.
3. **macOS** - the child hook no longer assumes `/proc/self/fd`: `fd_path()` uses `/proc` on Linux, `fcntl.F_GETPATH` on macOS, and raises (hook refuses the mutation: fail closed) anywhere else. The helper is a separate string (`FD_PATH_HELPER`) so it is unit-tested per platform with a fake `fcntl`; end-to-end tests drive the real child hook with a valid, an outside, a closed and a fake-unsupported-platform `dir_fd`. NOT run on a real Mac from here.
   - **Root / CI**: tests that run the whole tool need the private mount namespace: EITHER euid 0 OR unprivileged user namespaces (`unshare --mount --map-root-user`); no sudo is used. Verified in this worker: works as root and as uid 65534 (kernel allows user namespaces). The guard tests in `NO_NAMESPACE_TESTS` always run (also on macOS); the others skip with the explicit reason "REQUIRES a private mount namespace (euid 0 or unprivileged user namespaces ...)". On GitHub Actions `ubuntu-latest` they run only if the image allows unprivileged user namespaces (newer Ubuntu images restrict them through AppArmor and then they skip); this is UNVERIFIED here. A job that needs them can relax `kernel.apparmor_restrict_unprivileged_userns` or run as root.
4. **`_pending` failed open** - a read error returned `[]` ("nothing pending"). It now raises `PendingUnreadable` and the run gets blocker `PENDING_UNREADABLE` (`pending_null_pass_ids_readable: false`). A fresh evidence store without the `paper_observation_passes` table is correctly "nothing pending" (checked via `sqlite_master`), so fresh sets are not blocked by this.
5. **Live-file guards**
   - Verified here: a plain `mode=ro` open of a clean WAL store CREATES `-wal`/`-shm` and they persist after close; as root they would be root-owned beside a `solana-desk` store. Fix (same rule as `tools.ops.status`, T02F): `immutable=1` ONLY for a WAL-mode file (database header byte 18 == 2) with no `-wal` beside it (no sidecars created; exact because nothing can be pending); a WAL store that has a `-wal` uses `mode=ro` (sidecars already exist; immutable would silently drop uncheckpointed rows - tested); a rollback-journal store such as `provider-pacing.sqlite` (rewritten every ~2 s) is NEVER opened immutable (tested with a connect spy). `copy.files[].read_mode` is `IMMUTABLE_QUIET_WAL` or `READ_ONLY`. An earlier version of this branch used immutable for any store without `-wal`/`-journal`, which would have been unsafe for the pacing store; corrected in the last commit.
   - Any sidecar still created under `--data` is a blocker `LIVE_SIDECAR_CREATED:<rel>`; any other new file `LIVE_FILE_CREATED:<rel>` (status BLOCKED).
   - `live_sources_unchanged` now compares size, mtime AND sha256 of every source (and size+sha256 of its `-wal`). A same-size/same-mtime modification is detected (test).
   - A drift or finding downgrades only `PASS` to `BLOCKED`; a `GUARD_VIOLATION` stays a violation (exit 3).
6. **Minor** - docstring corrected (only `paths.*.device`, `paths.*.inode` and the config copy's path are excluded; store paths and the journal path ARE compared); `sys.dont_write_bytecode = True` at the very top of the module.

## Remaining limitations
- macOS behaviour is covered by unit tests with a fake `fcntl` and by skip logic; it was not executed on macOS.
- `python -m tools.ops.preflight_dryrun` still lets the loader cache the tool module's own `.pyc` (the flag executes after that); everything imported afterwards is not cached (tested).
- `immutable=1` assumes a quiesced store when no `-wal`/`-journal` exists; a writer that starts mid-copy is caught only by the before/after sha256 check (`LIVE_SOURCE_CHANGED_DURING_RUN`).
- Owner check covers files only (as before), not directories.
- Earlier T05 limitations stand (copies are sequential; identities of copies differ from live files; hostile release code could bypass the audit hook; SIGKILL leaves the workdir).
