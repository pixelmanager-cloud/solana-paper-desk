## What changed
- `deploy/fresh/desk-counterfactual.service`: `CPUQuota=100%`, `CPUWeight=20`, `IOWeight=20`, `Nice=10`, `IOSchedulingClass=idle` (existing `MemoryMax=256M`, `TasksMax=32` kept and now pinned by a test).

- `tools/ops/healthcheck.py`: new `research_cpu:<unit>` check (`--cpu-state FILE`). WARN when a research unit runs at >= 90 % of its CPUQuota for 3 consecutive checks (`research_cpu_fraction`, `research_cpu_consecutive` thresholds), or has no CPUQuota. `research_cpu_state` WARN when the state file is a symlink/unreadable/unwritable.
- `deploy/fresh/desk-healthcheck.service`: passes `--cpu-state <STATE_DIR>/cpu-state.json` (STATE_DIR is already its ReadWritePaths).
- `docs/ops/OPERATIONS_24x7.md`: alert-table rows, "Resource isolation and reading per-unit usage" (`systemd-cgtop`, `systemctl show -p CPUUsageNSec,MemoryCurrent,...`).
- Tests in `tests/test_ops_healthcheck.py`: 3 unit-invariant tests in `UnitTemplateTests`, 20 in `ResearchCpuTests`.

## Limitations
- No `desk-fill-realism-worker.service` template exists in this branch; the invariant test and the healthcheck cover it automatically if one is added (the test requires `desk-counterfactual` and checks the worker only when present). I did not invent one.
- Units were not loaded into a real systemd (as with all templates); run `systemd-analyze verify` on the VPS. CPU/IO controllers need cgroup v2 with the cpu and io controllers delegated; `IOSchedulingClass=idle` only helps with an IO scheduler that honours it (not `none`/NVMe on some kernels).
- A hard `CPUQuota` means usage can never really exceed the quota, so "exceeds quota" is implemented as "at >= 90 % of quota" (saturated). Sampling is per health-check run (5 min cadence), not continuous.

## For the coordinator
- `tools/ops/healthcheck.py` and `deploy/fresh/desk-healthcheck.service` are outside the listed OWNS but the requested WARN cannot exist without them; both edits are minimal and additive (no `desk/` change, no trading unit touched).
- The state file `<STATE_DIR>/cpu-state.json` must be writable by the healthcheck user (it is, via the unit's ReadWritePaths). Without `--cpu-state` the check is off, so existing deployments of the old unit text keep working.
- Conservative choice: the saturation fraction is 0.9 of the quota; adjust with `--threshold research_cpu_fraction=...`.
