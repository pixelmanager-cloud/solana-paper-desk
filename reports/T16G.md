# T16G — Concurrency: bounded held latency, rollover, wiring

Branch `cloud/T16G`, BASE `origin/cloud/T16F` + merge of `origin/integration/r1`. `desk/` changed, so the implementation hash changes; rotate store sets.

## What changed (per item)
1. **Wiring.** Merge conflict in `deploy/fresh/desk-paper-held-cycle.service` resolved to `--pool-fee-bps <POOL_FEE_BPS>` plus `--wall-seconds 64`. `tools/ops/fresh_start.py` held argv carries `--wall-seconds 64`; the stale "held 10 s pass" comment is fixed. `tests.test_ops_fresh_start_wiring` passes.
2. **Bounded held latency.** `tools/paper_entry_dispatcher.py`: `_HeldCadence.checkpoint(next_phase_seconds)` runs before acquisition, intake and the preparation+cycle. It runs one in-process held pass (`_held_pass`, never raises; the intent is already latched) only when `paper_concurrency.checkpoint_due(...)` says the next uninterruptible phase plus the legs would exceed `HELD_MAX_GAP_SECONDS` (120). Flat book or flag off: never. Locks are free between phases, so this does not hit the T16F finding that a pass cannot run inside a phase.
3. **Rollover.** New versioned opt-in `paper_rollover_after_mark_version: 1` (engine `rollover_after_mark`, requires the concurrent flag and the portfolio TTL; invalid values or a missing dependency refuse at load). A held event that refreshed its own mark re-tests rollover on the updated book, so the held pass's final leg rolls the day (`DAY_ROLLOVER_AFTER_FRESH_MARKS`). Tested for full book / no candidate, `EXIT_ONLY`, running book, a stale other mark (stays deferred), loss-counter reset, key absent unchanged.
4. **Entry estimate.** `ENTRY_SECONDS` = acquisition 12 + intake 10 + preparation 18 + cycle 12 = 52 (`ENTRY_PHASES`). The old assertion `== 30.0` in `tests/test_paper_concurrency.py` was loosened on purpose to 52.0 (it left acquisition and intake out); this is stated in the test and commit.
5. **Restart.** `ThreePositionRestart`: 3 open positions; a crash mid-leg (reservation without outcome) gives `RECOVERY_REQUIRED` with 0 requests, and an entry is refused before any charge; an interrupted entry (crash after the durable intent) refuses a retry with no new charges or fills.
- TTL key `paper_portfolio_mark_ttl_seconds` stays behind its flag; no example config sets it (verified by grep); semantics unchanged.

## Limitations (honest)
- Two clocks. The synthetic wire fixtures tie trade times to the data clock `f.at`, which cannot jump between phases of one dispatch (any jump gave `HISTORY_RECOVERY_REQUIRED`) nor by 52 s before it. So the latency proof runs the cadence on a separate wall clock advanced by the phase budgets, while engine freshness at the decision is covered by the existing 30 s modelled jump. Phase figures (acquisition 12, intake 10) are conservative planning numbers, not live measurements.
- The cycle phase (about 30 s) stays uninterruptible, so the gap bound is 120 s plus at most that phase if the estimate is wrong.
- Pure held passes without the new rule still defer rollover; the new rule is opt-in.
- `tests/test_paper_entry_dispatcher.py`: `append_distinct_migration` gained a `seed=17` keyword (default behaviour unchanged) to build more than one distinct candidate.
- Held checkpoints spend monitoring allowance (5 requests per position per pass).
