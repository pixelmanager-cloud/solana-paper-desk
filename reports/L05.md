# L05 — lean runner, systemd unit, health

Branch `cloud/L05`, BASE `origin/integration/r1`. L01–L04 had only claim commits, so the runner is built against the spec
interfaces (duck-typed) and tested with fakes; nothing under `desk/` was touched or imported.

## Commits / files
`lean/runner.py`, `lean/__main__.py`, `deploy/lean/desk-lean.service`, `docs/lean/README.md`, `tests/lean/test_runner.py`.
`lean/` and `tests/lean/` have no `__init__.py` here (L01 owns them); namespace packages work and L01's `__init__` is compatible.

## What it does
Two threads (candidates; positions every <=10 s with ONE batched marks read), per-candidate/per-position failure isolation,
halt only on AccountingHalt / store write failure (entries stop, held monitoring continues) / kill-switch file, `code_version` +
`strategy_version` on every row, atomic health JSON, SIGTERM/SIGINT graceful stop, `python -m lean [--once]`.

## Tests (11, fixtures only)
End-to-end with fakes: 20 candidates (5 screen rejects, 2 malformed, 1 provider error, 1 quote timeout), portfolio cap, entries,
STOP and TAKE_PROFIT exits, provider outage mid-run, cursor (no reprocessing), invariants and EXECUTION_UNVERIFIED on all fills,
exit-quote outage keeps the position open and retries, duplicate mint, accounting halt, store write failure, kill switch on/off,
stop joins both loops + final health, a loop bug does not kill the other loop, `reserve_mark` math/typed failures, one batched read for N positions.
Command: `python -W error::ResourceWarning -m unittest tests.lean.test_runner` → 11 OK.
Mutations (isolation removed, kill switch ignored, halt ignored, per-position marks, provider-error branch removed) each turn a test red;
two initially survived and the tests were strengthened.

## Limitations / for the coordinator
* **Not integrated with the real L01–L04 yet**: attribute names (`.enter/.size_sol`, `.exit/.fraction`, candidate `cursor`, position `qty_raw/vault_base/vault_quote`,
  fills recorded via generic `record('fill', …)`) are the adaptation points; `python -m lean` imports the real modules lazily and is untested end to end.
* Marks use pool vault balances, which assumes positions expose their vault pubkeys; Kraken/SOL-USD is passed to `screen` but the runner does not use it itself.
* Entry sizing probes a Jupiter quote of `entry_probe_sol`; exact sizing is the strategy's.
* No real systemd run; the unit follows the repo's hardening pattern (no ReadOnlyPaths on the discovery dir because WAL reads need L03's immutable fallback).
* Full desk suite not run (desk untouched). `lean/` is outside the desk hash domain.
