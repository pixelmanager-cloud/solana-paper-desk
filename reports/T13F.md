# T13F — fresh-start unit wiring fixes

Branch `cloud/T13F`, BASE `integration/r1` (T13 merged). Touches only `tools/ops/fresh_start.py` and `tests/test_ops_fresh_start*.py`
(`desk/**` untouched, so no runtime-hash change). Synthetic fixtures only; no systemd, network or credentials.

## What changed, per finding
1. **Dashboard.** `desk-dashboard` now emits `DESK_PAPER_SCHEDULER_IDENTITY` and `DESK_PAPER_LEDGER_DB=<root>/paper-ledger.sqlite`
   (plus the existing `..._LOCK`). `apply` also forces every created file to 0600 / dir 0700 regardless of umask, because
   `desk.backup.selected_paper_ledger` (used by `/api/paper`) rejects a ledger readable by others. Test: `Jobs.once()` against the new root with the emitted env
   leases the lock and returns `False`; the same call without the identity raises `Reviewed scheduler inode identity required` (the old failure);
   `selected_paper_ledger(root)` resolves the ledger, also under a 022 and a 000 umask.
2. **Full drop-ins.** `python -m tools.ops.fresh_start render-dropins --root R --out DIR [--marker TEXT]` reads the applied manifest and writes
   `DIR/<unit>.conf`, one per unit (6 units incl. backup). Each has: marker as first line; `[Unit]` `ConditionPathExists=` reset then the new store
   path (entry→journal, held/monitor→ledger, decisions→research; the four templates that carry an old-path condition); `[Service]` `Environment=` reset
   then ours; `ReadWritePaths=<root>` (+ shared pacing dir for entry/held, + backup dir for backup); `ExecStart=` reset then the full-venv interpreter
   line. Quoting: `%`→`%%`, `$`→`$$` (ExecStart only), quotes/backslashes escaped; the single intentional specifier `%d/provider-keys.json` is kept.
   Refuses: existing/symlinked `--out`, missing/invalid manifest, a scheduler lock whose inode no longer matches the manifest. Tests apply an independent
   mini-model of systemd merge/word rules to the real `deploy/*.service` templates and prove: old ConditionPathExists and ExecStart are gone, ExecStart and
   Environment round-trip exactly (including a root path containing a space, `%d`, quotes and `$HOME`), mutation of each rule turns a test red.
   **Install name for T11F:** `<unit>.service.d/70-fresh-store.conf` (printed in each file and in the command output). Its `unit_arguments` JSON
   shape is unchanged (`units.<name-without-.service>.{environment,argv}`; argv without interpreter); the new per-unit sections are in `manifest.unit_sections`.
3. **Service user.** `apply`/`rotate` take `--service-user` (default `solana-desk`) and `--chown`. They refuse, before creating anything, unless the effective user is
   the service user or root with `--chown <service user>`; with chown every created entry (root, dirs, stores, WAL/SHM, locks, manifest) is `lchown`ed,
   then ownership and modes are re-verified (a failure raises and the root is retained, never reused). Real-chown tests run when the suite runs as root (they ran here).
4. **verify_flat / rotate.** Takes the old ledger's `.paper-cycle.lock` non-blocking (refuse if busy, **never creates** the lock file), held through the check **and** the
   bootstrap (a spy inside `apply` proves it). Refuses on: open position/`exit_blocked`/pending exit, mode other than RUNNING/ENTRY_PAUSED, dispatcher intent without a
   result, any `paper_observation_passes.outcome_hash IS NULL`, any monitoring reservation without an outcome, a non-empty `-wal` on ledger, evidence or journal. Roots not created by
   this tool: `--old-ledger/--old-evidence/--old-journal` (absolute, no symlinks; all three needed without a manifest). The approved plan hash now includes the flat proof, recomputed
   under the lock; `--execute` without the exact hash refuses before creating anything. Old root stays byte-identical (`tree_digest`).
5. **Held cycle.** The held unit keeps `--dependency-blocker RUNTIME_REVIEW_AND_PATH_BINDINGS_REQUIRED` (the deploy template's own) unless planned with `--enable-held`; the plan
   `notes` say which, and the choice is inside the approved hash.
6. **Backup.** `desk-backup` runs `tools.ops.backup` via a short `python -c` that adds a UTC-dated destination (the tool refuses an existing destination) with
   `--expect-count 5` and `--backup-dir` (default `/var/backups/solana-desk/fresh-<root name>`, must exist 0700 service-owned before the timer runs; outside the root). `desk.backup` cannot be
   used: it requires launches/raw/active-paper stores the fresh set lacks. The test runs the emitted code for real against the applied root and checks the 5-database manifest.

## Limitations
- No real systemd was available: drop-in semantics are checked against an independent model of the documented rules, not `systemd-analyze verify`. Run that once on the VPS before cutover.
- `ReadWritePaths` of a missing backup dir makes the backup unit fail loudly (namespace error); creating that directory is an operator step.
- `rotate` refuses an old ledger with no `.paper-cycle.lock` file (cannot prove quiescence) rather than creating one in an old root. Old dispatcher "retired" receipts are not modelled; any intent without a result refuses.
- The held unit does not monitor positions until re-planned with `--enable-held`; that is deliberate and visible, but it is one more step before enabling entries.
- Pacing database: its directory is made writable for entry/held; if the coordinator moves the shared pacing DB, re-plan.

## For the coordinator
- T11F should install `DIR/<unit>.conf` unchanged as `<unit>.service.d/70-fresh-store.conf`; `--marker` lets it stamp its own rollback marker. It must not re-escape `%d`. The `70-` file resets `Environment=`, so it overrides anything a `60-` drop-in set.
- Operator commands change: `apply`/`rotate --execute` need `--service-user solana-desk` (run as that user) or `--chown solana-desk` as root. `rotate` plan hashes now differ from before (flat proof is bound).
- No production stores or hash domain touched.
