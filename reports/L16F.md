## What changed, per review item
1. **Merge blocker — AST no-signing test.** One module-level walker `forbidden_hits(source, filename)` in `tests/lean/test_route_check.py`
   is used on every `lean/*.py` AND by its own self-tests. It flags only CALLS of a forbidden bare name, ATTRIBUTE access, IMPORTS
   (`import x`, `from x import y`, `from pkg import module`), plus a forbidden RPC method name passed as a string argument of a call
   (`rpc('sendTransaction', ...)`, the one way to broadcast through the generic RPC; `providers.READ_ONLY_RPC` also refuses it at runtime).
   Parameters (`ast.arg`), keyword arguments, local names, lambda parameters, docstrings and string constants in deny-list literals are NOT
   hits. Evidence for the bug: the shipped walker flagged `def f(sign): return sign` and `sign = 1` (output of the old logic:
   `['sign', 'sign']`). Self-tests: 13 offender kinds must fire, 9 benign kinds must not.
2. **Count once per trade; transient errors are not NOT_ROUTABLE.**
   - `RouteChecker.on_fill/on_quote_error` take `trade=` (entry: candidate id; exit: the opening fill id; the runner hooks pass them).
     The first conclusive attempt of a trade side is the check; later attempts write nothing (durable: it reads the store, so a restart does
     not repeat it; the failed quotes remain in `errors`). A trade that sold after N failed passes is ONE `NOT_ROUTABLE` exit.
   - `analyze_error` now returns `conclusive`: true only for non-transient failures that are evidence about the route (a provider
     `errorCode`, or a plain 4xx other than 408/429). Transient errors (429, timeout, 5xx), `AUTH_REJECTED`, redirects, our own bad argument,
     unparseable bodies and a stored response we could not read are `INCONCLUSIVE`: at most one row per trade side, shown as
     `inconclusive` in the summary, never in the routable percentage.
3. **`UNSUPPORTED_MARKERS` -> `UNSUPPORTED_ERROR_CODES`** (frozenset, EXACT case-sensitive match on the provider's own `errorCode`):
   `INSUFFICIENT_FUNDS`, `INSUFFICIENT_BALANCE`, `TAKER_NOT_FUNDED`, `TAKER_ACCOUNT_NOT_FOUND`. The old substring match over the whole
   body disabled the check on any route error that merely mentioned a balance or a simulation (tested with
   "no route: pool balance too low", `SIMULATION_FAILED`, lower-case `insufficient_funds`, `NO_FUNDS_ROUTE`).
4. **Config.** `RouteChecker` refuses a non-object config and a non-boolean `enabled` (`"false"` used to be truthy); `lean.__main__.load_config`
   validates the same at load (`ConfigError`); `_unsupported` uses the store's public `code_version` / `strategy_version` (a test
   store exposing only the public surface proves `_versions` is no longer called); `lean.example.json` ships `"route_check": {"enabled": false}`.

Hook edits (inside the L16 delimiters only): `lean/runner.py` (4 calls pass `trade=`), `lean/__main__.py` (+4 lines config check).
Changed existing assertions (reason in the test and the commit): `test_malformed_stored_observation_is_recorded_not_raised` now expects
`INCONCLUSIVE` (was `NOT_ROUTABLE`): our own failure to read the stored response is not evidence about the route.
`test_e2e_route_check` scenario B now expects ONE `NOT_ROUTABLE` exit (was one per retried pass) and its setUp enables the check explicitly
because the shipped example is off.

## Limitations / for the coordinator
- "First conclusive attempt is the check" means a trade whose route was gone at the first sell attempt counts as not routable even if it
  sold a minute later; the later success adds nothing. This is the conservative reading of "count once per trade".
- The exact funded-taker error codes are my assumption of Jupiter's vocabulary (not verifiable offline). If the live endpoint names them
  differently the check simply never self-disables; edit `UNSUPPORTED_ERROR_CODES` after the first live observation.
- The `NO_SWAP_INSTRUCTION` outcome is still treated as conclusive; if live responses are serialized transactions rather than instructions
  (limitation from L16) every trade would read NOT_ROUTABLE until that one predicate is adjusted.
- The walker is a test-only guard; the runtime guard remains `providers.READ_ONLY_RPC` (no send/simulate method can be called through `rpc`).
