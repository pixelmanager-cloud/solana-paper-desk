# L06 — lean reports

Base `origin/integration/r1`. Owns `lean/report.py`, `tests/lean/test_report.py` (plus the empty package markers
`lean/__init__.py` and `tests/lean/__init__.py`, which L01 also creates: identical empty files merge cleanly).
Fixtures only; no network, no keys; nothing under `desk/` touched or imported.

## What it does
`python -m lean.report --db lean.sqlite --out-dir DIR [--counterfactual counterfactual.sqlite] [--horizon 3600]`
writes `lean-report-<UTC stamp>.html` (self-contained: inline CSS, no script, no external reference, light/dark) and
`.json` (strict JSON, `allow_nan=False`), 0600, exclusive create, symlink-refusing; exit 2 with a JSON error otherwise.
Sections: funnel (candidates -> screened -> passed -> entered), rejection reasons, trades (closed/open/flagged/anomalies,
per-trade table, hold-time distribution), PnL per `strategy_version`, exit-reason breakdown (n, PnL, return, hold),
errors by code, versions, and rejected mints vs forward price from T26's `counterfactual.sqlite`
(+5m baseline never re-baselined, `POOL_DEAD` = -100%, missing baseline/horizon counted not guessed, same convention
as `docs/research/COUNTERFACTUAL.md`). Every n < 30 is flagged `INSUFFICIENT_SAMPLE`; profitability verdict is
`NOT_ASSESSED`; banner says PAPER ONLY / EXECUTION_UNVERIFIED.

## Read-only
Store opened `mode=ro` + `PRAGMA query_only`; `immutable=1` only for a WAL-header file with no `-wal` sidecar (the shared
T02F/T42 rule, re-implemented locally so `lean/` does not import `tools/` or `desk/`). Tests: no byte of the store or
its directory changes (rollback and WAL stores), an INSERT through the report connection fails, symlink/missing refused.

## Isolation / robustness
A section that fails becomes `status: ERROR` (counterfactual store missing or horizon unsampled) and the rest still
renders. Unreadable rows are counted in `skipped` (non-JSON, non-object, unknown kind) and never stop the report.
A fill that cannot be read, a sell without a position, or a sell exceeding the position is recorded as an anomaly; the
trade is excluded from PnL (never silently scored). Open trades are listed, never scored. Hostile mint/reason/strategy
strings are HTML-escaped (tested). Row cap 2 000 000 per table (reported as `truncated_tables`); per-trade table capped
at 5 000 rows in the output.

## Tests / mutation
32 tests in `tests/lean/test_report.py` (`python -m unittest discover -s tests/lean -t .`): funnel, PnL/return/hold,
partial-exit ladder, re-entry, anomalies, strategy grouping and the exact 29/30 sample boundary, both store layouts,
read-only guarantees, counterfactual maths and failure modes, CLI output rules. 13 single-line mutants (fee handling,
sample threshold, dead-pool value, escaping, latest-screen rule, time ordering, baseline validity, over-sell check,
scored rule, horizon check, exclusive create, symlink check) all killed. New files, so no RED-on-BASE to show.

## Limitations — for the coordinator
- **L01 store schema did not exist when this was written.** The report reads a documented contract (module docstring):
  generic `records|events(kind,payload,strategy_version,code_version,at)` or typed `candidates|screens|decisions|fills|
  errors|observations` tables with a JSON `payload` or plain columns; field names `mint|token|token_mint`,
  `side`, `qty|quantity|tokens`, `sol|sol_amount|notional_sol` (fee excluded), `fee_sol|fee`, `reason|exit_reason`,
  `passed`, `reasons`. **Reconcile with L01 after merge** (one-line alias changes in `pick(...)` / `TYPED_TABLES`); if L01
  stores fee inside `sol`, cost/proceeds are off by the fee.
- Funnel "screened/passed" need `screen` events (a `decision` with stage screen is not used); "entered" = distinct mints
  with a buy fill. `exited` is shown as closed trades.
- No equity curve / drawdown (needs mark data not in the contract); realized PnL of closed trades only.
- Counterfactual join is by mint; a mint rejected under several reasons appears in each reason group.
