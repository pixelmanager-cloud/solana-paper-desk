## Review items
1. **Re-screen cost.**
   - *Portfolio first, no I/O.* Before any re-screen, `strategy.portfolio_blockers(portfolio, cfg, mint)` is asked. A mint it refuses (MAX_POSITIONS while the book is full, COOLDOWN, ENTRY_THROTTLE, loss pause) is skipped for free, stays listed, and spends neither a provider call nor an hourly-cap token. The portfolio is built once per pass and rebuilt only after a re-screen could have changed it. Blocked mints are not counted against `watch_max_per_pass`, so they cannot starve the others. E2E: with `max_positions=1` and the book full for 1300 s, the number of `getTokenLargestAccounts` (screen-only) calls does not change, there is no `watch_rescreen` event and `watch_skipped_portfolio` > 3; when the held position stops out, the watched mint is re-screened and entered.
   - *After the fresh scan.* `_l14_pass` runs after the pump scan (extra sources too). E2E: a new candidate is handled before an overdue re-screen in the same pass.
   - *Hard cap + documentation.* `watch_max_rescreens_per_hour` (default 120), counted from the persisted `watch_rescreen` events of the last hour, so a restart cannot reset it. Calls per re-screen: 2 Helius `getMultipleAccounts` + 1 `getTokenLargestAccounts` (with `holder_check`; SOL/USD is the runner's 30 s cached value) and, if it passes and wants to buy, 2 Jupiter quotes: at the default cap at most 360 Helius + 240 Jupiter calls per hour, whatever the list length. In the `watchlist.py` docstring and in `config/lean/lean.example.json`.
2. **Per-source funnel in `report.py`.** `summary['sources']` + an HTML section "Funnel per source" (candidates, screened, passed, entered, rejected, failed, watched, re-screens, entered after watch, watch-ended by reason). `sources.funnel_by_source` now takes a `Store` or a read-only connection and STREAMS the tables (no row cap).
3. **Any fill ends the watch.** `Watchlist.has_fill(mint)` (any buy or sell in the store) is checked before every re-screen and in `after_handle`. E2E: the BUY is committed, the watchlist's bookkeeping "dies" (`BaseException`), a new process starts with the entry still listed: it is ended `ENTERED` without a re-screen and there is exactly one buy even though the cooldown is 1 s.
4. **`watch_hours` vs `max_age_seconds`.** `watch_hours` default is now 2 (= the screen's 7200 s) and `load_config` raises `ConfigError` when an ENABLED watchlist asks for more than `screen.max_age_seconds` (`check_window`). The effective deadline is the earlier of `first rejection + watch_hours` and `migration + max_age_seconds`, so an old mint expires before any wasted screen; `TOO_OLD` (alone or beside soft reasons) is labelled `EXPIRED`, not `HAZARD`; any real hazard beside it still wins.
5. **No capped reads.** The `limit=100000` ascending reads (the oldest rows) are gone: `Store.rows_after(table, after_id, ...)` (additive method in `lean/store.py`) + `sources.iter_rows` page through any table size; the "latest decision" is the last row of a paged read; the funnel streams SQL. Tests: tiny pages still find the newest `watch_end` events; the funnel works through a patched `Store.rows` that raises; across a whole e2e run + report no `Store.rows` call asks for more than 1000 rows.
6. **Hook shape.** Two `# --- L14 hook ---` blocks in `runner.py` (3 statements in `__init__`, one 5-line method) plus one inserted line in `candidate_pass`; everything else is in `lean/watchlist.py` (`install`, `after_scan`). `install` wraps the runner's `_isolated` and `store.add_candidate` at instance level (source tag, `after_handle`), so no existing line was edited. The only changed existing lines in `lean/` vs `integration/r1` are the `Runner.__init__` signature (`extra_sources=None, watchlist=None`) and the last `build_runner` call argument (`**l14`). A test asserts each block is at most 30 lines.
7. **New AMM sources: NOT DONE, TODO.** I could not verify any Raydium CPMM / Meteora DAMM v2 layout. My attempt to reach a public RPC from this session was refused by the environment's permission layer (and cloud workers may not make provider calls), I did not work around it, and there is still no captured account for these programs in the repo. A decoder from memory would be unverified, and a wrong decode becomes a wrong paper entry. `build_sources` keeps refusing those types with `SOURCE_TYPE_UNSUPPORTED`. The `lean/sources.py` docstring lists what is needed (a real captured pool + vault accounts with provenance, a pure decoder, a pool-kind switch in the screen and the mark, signature polling, never `getProgramAccounts`) and the cost estimate. Someone with a verified fixture can add them without touching the rest.

## Limitations
- Only the pump graduation source exists (see item 7).
- Instance-level wrapping of `_isolated` / `store.add_candidate` is deliberate (to keep the runner diff to insertions) but is "monkey patching" a reader should know about; `install` is the single place.
- The hourly cap counts re-screens, not provider calls; the per-re-screen call count in the docstring is for the default screen config.
- After a restart every watched mint is due at once; the per-pass bound and the hourly cap spread them out.
