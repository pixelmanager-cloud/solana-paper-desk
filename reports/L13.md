## What changed and why
New module `lean/wallet_signals.py` (docs: `docs/lean/WALLET_SIGNALS.md`, example `config/lean/wallet_signals.example.json`).
- **Per screened candidate (PASS or REJECT) one `observations(kind='wallet_signals')` row**: `bundle_score`, `sniper_count`,
  `same_slot_buyers`, `bundled_supply_pct`, funding clusters, `smart_buyers_count`, `calls`, and `unavailable` (every null has a
  reason). L12 is not in the base, so this is its own row; when L12 lands the headline figures (`_meta_summary` keys) can be copied
  into its features row.
- **Data**: read-only RPC through the existing `Helius.rpc`: `getSignaturesForAddress(pool)` back to the graduation slot (2 pages),
  `getTokenSupply`, `getTransaction` (jsonParsed) for the earliest 6 window transactions, and for the earliest 3 buyers
  `getSignaturesForAddress(wallet, before=first buy)` + `getTransaction` of the OLDEST prior signature (funding transfer = 1 hop).
  A buy is a transaction in which the pool's balance of the mint fell and a non-pool owner's rose.
- **Smart wallets**: `wallet_buy` / `wallet_outcome` append-only events (the store schema is untouched, so `lean_wallets` is the
  view `WalletSignals.wallet_table()`); outcome from L07 `path_mark` rows (first hit of 2x or 0.3x), else this desk's own closed trade,
  else UNKNOWN after 12 h. Smart = >= 2 wins and Laplace score >= 0.7. Look-ahead safe: a row only uses outcomes recorded before it;
  `smart_asof_event_id` is stored.
- **Low-priority lane**: `LowLaneLimiter` (own bucket 1 req/s + a token of the shared Helius main-lane bucket; `shed()` hook refuses
  before taking a token) via `build_low_lane_helius` (one attempt per request). Hard cap `max_calls` (16) per candidate, a
  `CALL_CAP` / `CREDIT_SHED` stop keeps what was learned. Own thread (`run_loop`); work is found from the store (no queue).
- **Hooks** (all additive): `lean/runner.py` +11 lines (`wallet_signals=None` argument, one thread in `run()`, a health key only when
  enabled, marked `# --- L13 hook ---`), `lean/__main__.py` +18 (config key `wallet_signals: null`, strict validation at load, builder),
  `tests/lean/fakeworld.py` +3 (`extra_rpc` hook), `config/lean/lean.example.json` +1 (`"wallet_signals": null`, required by the
  existing "example lists every key" test). `desk/` untouched.

## Limitations / assumptions
- **Shared funding is not ownership.** Exchange hot wallets create false clusters; `ignore_funders` is empty by default (no list
  of hubs is shipped; we cannot verify one offline). `bundle_score` is a lower bound (6 transactions, 3 funding lookups).
- Funding = sender of a System-program transfer in the OLDEST of the <= 10 signatures before the first buy; a wallet with >= 10
  earlier transactions is `FUNDING_HISTORY_TRUNCATED`, a wallet funded by a token swap/other program shows `NO_FUNDING_TRANSFER`.
- Order inside a slot is the RPC's order (newest first); "earliest" depends on it. The window is by SLOT (`window_s` / 0.4 s), anchored
  at the candidate's graduation slot, not at the discovery receive time.
- A hot token with > 2000 pool signatures since graduation gives `WINDOW_START_NOT_REACHED` (all window figures null) rather than a guess.
- Pool owner = `candidate.pool` (PumpSwap vault accounts are owned by the pool PDA). Raydium/Meteora pools (L14) need their own owner.
- Router or aggregator accounts that receive tokens first would be counted as buyers; not special-cased.
- The jsonParsed shapes follow the public Solana RPC format and the repo's fixtures; they were NOT verified against live Helius
  (no live access). A parse error is a per-transaction skip (`tx_skipped`), never a crash.
- L07 is not in the base: the `path_mark` contract (`meta.price_sol`, `path_end`) is taken from `origin/cloud/L07:lean/paths.py`.
- Wallet records need many tokens to mean anything; at ~1 resolved token per wallet nobody is "smart" for days.

## For the coordinator
- **Low lane.** There was no shared low-priority lane, so `LowLaneLimiter` lives in this module (own 1 req/s bucket + the shared
  main-lane bucket). L15's credit tracker should pass `shed=` to `build_low_lane_helius` / `WalletSignals`. L12/L07 could reuse it.
  Judgement call: the low lane draws from the MAIN bucket (not the exit lane) so it can slow screening by <= 10 %, never exits.
- **Cost.** <= 16 requests per candidate, 12 for a typical bundled launch; at 30 candidates/hour that is ~360 requests/hour. Helius credit
  prices differ per method (I assumed 1 credit per standard RPC call, not the enhanced API); set `max_calls` / `funding_wallets`
  lower or `"wallet_signals": null` to stop it.
- **Store access.** The module reads events/candidates with direct SQL through `store.db` under `store._lock` (the public `rows()`
  has no `id >` filter). A small additive `Store.events_after(kinds, after_id)` would remove that coupling; I did not touch `store.py`.
- **Config.** `lean.example.json` gained `"wallet_signals": null` (off). Enable with the object from `wallet_signals.example.json`.
- **Raw bytes.** Default `retain_raw: signatures` keeps only the (small) signature pages; `all` is ~tens of KB per transaction.
- Merge order: independent of L10/L11/L12; conflicts are only possible in the 3 shared files (runner/__main__/fakeworld), each with a
  delimited additive hunk.
