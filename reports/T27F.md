## Findings and fixes
1. **True bracket.** The old `[worst, best]` was not a bracket: on the BASE module the flat path reports `[-0.0015, -0.0015]` and the pump path `[+0.0763, +0.0763]`, both "unambiguous", while an independent engine run reproduces real histories at -0.0261 (a stop crossed and recovered / gapped through) and +0.1509 (rungs and peak inside a gap), outside both. New `bracket_trade` enumerates, with the REAL engine, every way the live engine could have observed a gap under ONE printed assumption (up to `max_intra_marks`=3 extra marks, any order/time, each at a pool price inside `[(1-X)*min(a,b), (1+X)*max(a,b)]`, X=`excursion_fraction`=0.30, `lo = 0` across a dead sample or at a death, depth of the earlier sample, fills at the observed price). A dynamic program over engine states marks only the prices where an engine threshold triggers (current stop, the +15% touch, the highest price at which a time-stop still fills, the next rung, the trailing level, the extremes) and the time-stop / max-hold deadlines, and returns the minimum and maximum PnL with the shortest mark sequence reaching each (`worst_path`/`best_path`). It covers a stop crossed and recovered, several rungs on one gap (the engine sells one rung per mark), an unknown peak for the trailing level, and deadlines inside a gap. A trade whose bounds differ is AMBIGUOUS; `ambiguous_share` is reported per variant/part. `max_intra_marks=0` collapses to the nominal run, and the nominal run must lie inside the bracket (checked per trade; a violation is an error).
2. **Parity against real events.** `replay_ledger` / `--parity-ledger L` replays the RECORDED events of a strict-mode ledger through the shadow's own engine path with the ledger's saved config and compares every decision with what the real `Ledger.apply` recorded (exit 3 on mismatch; quote-mode ledgers are refused because they need recorded quotes). The fixture is built by the real writer (entry, ladder, stop, a pause control and a second mint, non-trivial fills/rejects); tampering one recorded decision is detected. The old self-comparison test was replaced.
3. **Selection effects.** Nothing is dropped silently: `selection` counts `no_sample_rows`, `truncated_paths`, `dead_before_baseline`, `no_priced_sample`, `baseline_not_priced`, evaluated, plus `failed_or_missed_gaps`, `transient_death`, `terminal_death`, with a `funnel` of the totals remaining after each exclusion stage (the stages add up to the candidate count; tested). The +5m sample is required to enter. Horizon-end trades and entry rejects are counted per variant; `--include-truncated` evaluates incomplete paths on request (flagged `truncated_included`). A truncated enumeration (event budget) is reported, never guessed.
4. **POOL_DEAD.** A death is terminal only if no priced sample follows it; a closed vault that reappears is a gap with `lo = 0`, never -100% (same rule as T26F's metrics). A terminal death brackets the unknown death time: worst = whole position lost, best = the engine stops out / hits a time-stop deadline before the pool dies (replayed exactly by the oracle).
5. **Ranking.** Holdout only, minimum 30 holdout trades (`--min-trades`), ordered by the lower bound of the Bonferroni-corrected bootstrap CI of the mean return over the worst-case bounds (`rank_rows`; unranked variants follow with the reason). The bootstrap uses `max(4000, 40/alpha)` resamples (cap 100,000) and interpolated quantiles: at alpha = 0.05/1000 the old index collapsed to the single smallest resample.
6. **Features.** The T26F classification is joined and every part is split by it (`BOUGHT`, `REJECTED:<stage>:<primary code>`, `NOT_DISPATCHED`, `UNKNOWN`; a trade appears in exactly one group). `--features` requires `{mint: {"as_of": epoch, ...}}`, rejects unknown fields and features observed after the path ends, and applies a candidate's features only from `as_of` on; earlier entry decisions are refused (`FEATURES_NOT_YET_KNOWN`) and never run the engine with unknown features. Neutral defaults and assumptions are printed in the output (`neutral_features`, `assumptions`).
7. **Carry timers.** The `carry` model fed the last sample at a deadline as if fresh (`price_at = deadline`), sidestepping `price_ttl_seconds`; it is removed. Time exits inside a gap are now bracketed at unknown prices and make the trade AMBIGUOUS; documented (the live monitor is assumed to keep marks fresh within the TTL).
8. **Opening stores.** All reads go through `counterfactual._connect(..., readonly=True)` (T02F rule: immutable only for a quiet WAL file, `mode=ro` otherwise, `query_only`, symlinks refused); tested that a quiet WAL store gets no `-wal`/`-shm` and the store bytes are unchanged.
9. **`migrated_at`.** T26F's store records the discovery receive time only, so ages are labelled `since migration HINT RECEIPT` (`age_basis`).

## Limitations (honest)
- The bracket is only as good as its stated assumption: a path that moves further than `excursion_fraction` between samples, or a live engine that observes more than `max_intra_marks` extra marks, is outside it. With 5-minute-to-6-hour gaps the bracket is wide and most trades are AMBIGUOUS; that is the honest answer, and the nominal mean is printed next to it (it is NOT a bound). The default 0.30 / 3 are choices, not measurements; print and vary them.
- Intra-gap marks use the pool depth of the earlier sample; fills are at the observed price (no extra intra-gap slippage model); one candidate at a time (no portfolio effects).
- Cost is roughly 0.05-1 s per candidate and variant at 3 marks (more for long volatile paths); the event budget `MAX_ENGINE_EVENTS` (20,000 per candidate) reports truncation instead of guessing. Lower `max_intra_marks` for big grids.
- Ledger parity covers strict-mode ledgers only; quote-execution ledgers cannot be replayed from events alone.
- A candidate's primary rejection code is used for the outcome split; a trade rejected for several reasons is not double counted (T26F's own report counts it per code).
- Existing grid files gained explicit `excursion_fraction`/`max_intra_marks` entries (reformatted JSON).
