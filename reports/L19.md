# L19 — Selection learner: entry-time features -> outcome labels -> proposed screen rules

BASE: `origin/integration/r1` (it has L07R2 + LINT1) with `origin/cloud/L12F` (feature rows) and `origin/cloud/L08BF` (replay/tune on `paths.sqlite`) merged.
L12F conflicted with LINT1 in `runner.py`, `__main__.py`, `report.py`, `lean.example.json`, `fakeworld.py`: both sides were kept (hook blocks side by side;
`held_risk_report` and `features_report` are separate functions again; the example config keeps every LINT1 key plus `features`, disabled). Two existing e2e
tests needed the LINT1 example config neutralised where they model neither the latency fills nor L11's low-lane probes (`test_e2e_features`, `test_e2e_replay`:
`execution` None, `held_risk` disabled); the same one-line fix is pushed to `cloud/L08BF`. `desk/` untouched. Paper only, read-only, no network.

## What was built
1. **`lean/labels.py`** — one label per hazard-free candidate with a recorded path (entered or not), from the `path_marks` at/after the start, with the live mark
   (`adapters.mark` of the path's reference quantity, over the reference cost): `RUG` (mark <= -80% within 1 h, OR spendable quote reserve down >= 70%, OR the pool
   is gone), `WIN` (the first take-profit rung, +40%, before the stop line), `LOSS` (the stop line first), `FLAT`. Also `max_up`, `max_down`, `t_max_up`,
   `t_max_down`, `t_event`, `rug_cause`, `end_return`, `label_version` (1). Precedence by time: a rug beats an EARLIER stop, never an earlier win; same mark = RUG.
   The win/stop lines come from the live `StrategyConfig` (`LabelConfig.from_strategy`). The label is a pure function of the marks; duplicates across recorder
   files collapse to the first start (`LABEL_DUPLICATE` counted).
2. **No lookahead (`learn.features_known_at`).** A `features` row (read from the observation `meta`, never `raw`) is used only if `screen_at <= decision + 1 s` and
   `collected_at <= decision + max_lag_s` (default 300 s: the enrichment runs a few seconds after the screen), where decision = the path's start. Anything later is
   dropped and counted (`FEATURES_AFTER_DECISION`); marks never become features; an unknown value never matches a rule condition.
3. **`lean/learn.py`** — stdlib only. Per-feature quantile tables (n, rug rate, win rate with Wilson 95% intervals, mean forward return, mean simulated PnL,
   INSUFFICIENT flags), median feature per label ("winners vs rugs"), and a greedy rule miner: REJECT rules of 1 condition (`feature > t` / `<= t`, `t` a decile of
   the mine window) or 2 (a pair is kept only if it beats BOTH of its parts), maximising the expected PnL per candidate under the live exit rules (the replay of
   L08BF on each path, first-mark entry; rejecting a candidate replaces its PnL by 0). Minimum support `min_n` (50) rejected candidates, INSUFFICIENT below it;
   a rule that rejects > 80% of the candidates is "stop trading", not selection, and is refused.
4. **Walk-forward, never choosing on confirm.** Oldest 50% mines (top 25 by gain), middle 25% selects (support, positive gain, one-sided t <= -1.645, at most 3
   rules, each adding rejected candidates and gain), newest 25% confirms the chosen SET as a whole (>= `min_confirm` (30) rejected, positive gain, t <= -2.326): it
   cannot pick or drop a rule. Statuses: `NO_RULE_FOUND`, `NO_SELECTED_RULE`, `NOT_CONFIRMED`, `CONFIRMED_NO_DIRECTORY_GIVEN`, `WRITTEN`.
5. **Output.** `config/lean/proposals/<ts>-selection.json` (never overwritten, status `SELECTION_PROPOSAL_NOT_APPLIED`, `never_applied_automatically`): the rule list, its
   diff against the current screen (`selection_rules` from `[]`), the three windows' evidence, counts, thresholds and `requires_runner_change` (including
   `wait_for_enrichment:<fields>` for rules on features that only exist after the screen). `render_section(result)` is the HTML section "What winners vs rugs looked like
   at entry" (a fragment), `render_html` a standalone page, CLI `python -m lean.learn --db lean.sqlite --paths-db paths.sqlite [--paths-db archive ...] --out-dir D --now N`.

  pre-start marks ignored, the stop-line edge (0.04% either side: a 50 bps haircut flips it), config validation, a real `PathStore` file with carried-over duplicates.
* `test_learn.py` (53): Wilson / t maths, the look-ahead guard (rows after the decision, screened after it, the lag knob), windows and embargo, `evaluate` against hand
  arithmetic, planted single and pair rules recovered, minimum support, "stops trading" refused, pairs beat both parts, select flags, the confirm window never chooses
  (changing only it leaves candidates and selection identical), PURE NOISE: 40 seeded datasets and none is confirmed, AND some of them do reach the confirm gate with a
  positive but insignificant gain (so the gate is what stops them), proposal file contents / no overwrite / symlink refused, tables, escaping.
* `test_e2e_learn.py` (8): the real runner + L12F recorder + L07R2 recorder on fakeworld, two worlds of 100 launches (dev shares 0.5-30%). PLANTED: dev > 15% rugs (97%),
  the rest win or lose small; NOISE: outcomes independent of every feature. Every path gets the label of the family that made it; the planted rule `dev_holding_pct >
  15.6` is mined, selected (t = -1.8) and confirmed (13 rejected, all rugs) and a proposal is written; the noise world gives `NO_SELECTED_RULE`; a planted late feature
  row (perfectly predictive, collected after the decision) is not used; both databases are byte-identical afterwards.

* Mutations (single replacement, labels + learn + e2e): 30 mutants, 30 killed (`/tmp/l19_mutate.py`): mark haircut, pre-start marks, rug window, gross liquidity, rug/win/stop
  precedence, dead-pool cause, duplicate labels / references, collected_at / screen_at checks, selecting on confirm, confirm gate / significance, select significance and minimum,
  mine minimum, stop-trading rules, pair rule, embargo, unknown values matching, non-enterable candidates, gain sign, proposal overwrite, redundant greedy rules, features read
  after the decision, t sign, Wilson clipping, proposal status.

## Limitations
- Production minimums (50 mine/select rejected, 30 confirm) need a few hundred recorded candidates per window; below that the tool says INSUFFICIENT / NO_RULE_FOUND and writes
  nothing. The tests use smaller minimums (the maths is identical).
- Per-candidate PnL is a replay of ONE path on a fresh portfolio (no cash / position-cap contention), with the pool-fee assumption of the replay (default 30 bps in
  `ReplayConfig`, the learner passes `--pool-fee-bps`, default 25 = the runner's). It is a simulation (EXECUTION_UNVERIFIED); latency fills (L10) and rug handling (L11) are not modelled.
- Features come from the L12F row (<= 3 extra calls); dev / holder / graduation figures are as of a few seconds after the screen. A rule on them cannot be applied live without
  the runner waiting for that enrichment (the proposal says so). `top10_pct` / `top1_pct` / `dev_holding_pct` etc. are the ones L12F can fill.
- Selection bias remains: the best of <= 25 mined rules is chosen on one window and confirmed on one look.
- Shadow mode (item 5, optional) is NOT implemented: it needs the runner to evaluate rules on rows that exist only after the enrichment thread has run.
