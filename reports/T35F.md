# T35F — Portfolio-marks fixes (from the T35 review), folded with T16H

Branch `cloud/T35F`, BASE `origin/cloud/T16H` (built on T35) + merge of `origin/integration/r1` (already up to date). `desk/` changed: the implementation hash changes; rotate store sets.

## Per item
1. **(HIGH) Real timing.** `tests/test_portfolio_marks_pipeline.py` no longer freezes time: `time.time`/`monotonic` are live simulated clocks, advanced per request by realistic durations (Helius 0.1 s per T36, Jupiter quote 0.6 s, Kraken 2 s, price probe 0.5 s) and by the entry's own 2 s sleep. The 4-position test asserts freshness at the ENTRY DECISION: for each of the 3 entries with positions, the decision event's `ts` minus the last marks event's `observed_at` is <= 10 s, the valuation mark of every previously open position is <= 10 s old at that `ts`, time really elapsed (> 3 s per entry), and the second refresh is after the first. The old self-comparison (`last['ts'] - last['observed_at']`) is gone.
2. **(HIGH) No latch from a valuation-only read.** `MonitoringBudget._valuation_only` recognises the 3N-key read (method, exact options, key count a multiple of 3) and `retain_outcome` skips the `SOURCE_FAILURE` latch for it. Tested for every failure class: `TRANSPORT_ERROR`, `UNCLASSIFIED_ERROR`, `TLS_ERROR`, HTTP 400/403/429, `RESPONSE_INVALID`, `RESPONSE_OVERSIZED`, `RPC_ERROR`: charged once with the typed `failure_code` retained, `blocked` stays NULL, marks stale, ordinary `STALE_PORTFOLIO` reject, gate clear, and a real held leg (5 monitoring requests) still runs. The 7-key snapshot and other shapes still latch (unit-tested).
3. **(MED) Deadline accounting.** The marks read now runs INSIDE the 10 s cycle budget: bounded by `min(5 s, remaining)`, skipped (`PORTFOLIO_MARKS_DEADLINE`, nothing charged) under 3 s; `budget.start +=` removed. `entry_seconds(cfg)` adds the two refreshes; `plan_legs(..., refresh_seconds)` and `checkpoint_due(..., refresh_seconds)` count the pass refresh (2.5 s) against `--wall-seconds` and the held gap; the monitor service and dispatcher pass it.
4. **(MED) Reserve.** `RESERVE_PASSES` 12 -> 29: the shipped timer is `OnUnitInactiveSec=120`, so a pass starts at most every 120 + 7.8 s, ceil(3600/127.8) = 29 per hour (12 assumed a five-minute cadence). `monitoring_required(N, marks=True)` = 29 x (5N + 1) + 2: N=4 -> 611, N=8 -> 1191, both inside 3600; flag-off N=1 is 145 (was 60). Existing assertions that encoded 12/60 were retuned on purpose with the reason in the test; the dispatcher fixtures with the legacy 60/hour allowance patch the old value explicitly.
5. **(MED) Model marks vs liquidation.** New versioned `paper_portfolio_mark_source_version: 2` (optional `paper_portfolio_mark_max_divergence`, default "0.03", refused for version 1). Model marks still feed exposure, sizing and the freshness gates; `peak_equity`, `day_start_equity` and the daily drawdown/pause/liquidation use `engine.equity(state, guard=...)`: the executable mark unless the model mark is within the bound. Tests: a divergent low model mark cannot liquidate under v2 but does under v1; a divergent high mark cannot inflate the peak; day start after rollover uses the guarded value; an executable decline still liquidates; boundary exactly at 3 % keeps the model.
6. **(MED) TTL doc.** Every recommendation of `paper_portfolio_mark_ttl_seconds` is gone from `docs/MULTI_POSITION.md`.
7. **(LOW) One rollover rule.** `engine._roll_day` is the only place that rolls the day (a structural test counts one assignment and four references). The marks-event rollover is now behind `paper_rollover_after_mark_version: 1` (previously unconditional), the same flag as the after-own-mark rollover. Tests and the T16H rollover tests carry the flag.
8. **(LOW) Closed vault.** A null pool/vault account marks the position at zero with `reason` `POOL_CLOSED`/`VAULT_CLOSED` (stored as `portfolio_mark_reason`; the event validator requires value 0 and a known code) instead of staying stale. Golden: `tests/golden/portfolio_marks_off_identity.json` was generated by running `tests/golden/off_identity_scenario.py` on a worktree of `origin/integration/r1` before this branch's code; the test reruns it here and requires the identical state digest, outcome digest and no `portfolio_mark*` keys.

## Limitations (honest)
- The simulated clocks are test-side: request durations are assumptions (Helius 0.1 s per T36, which is not merged here; the repository's current pacing is slower), and the fake chain's balances are invented. A real Helius answer with 3N accounts has not been measured.
- With current 2 s Helius pacing the two refreshes plus the cycle's reads can approach the 10 s cycle budget; if the budget is short the refresh is skipped and the entry ends as a normal `STALE_PORTFOLIO` reject (never a latch).
- A 429 on the marks read arms the provider pacing backoff, which delays the next requests, including held legs; it does not latch monitoring.
- Zero for a closed vault is a valuation estimate (conservative direction); a transient null at `confirmed` commitment would also read as closed until the next refresh.
- The divergence guard compares against the latest executable mark even when that mark is old; an old executable mark with a diverged model mark therefore uses the old value for risk equity (the stated rule).
- Version 1 behaviour is unchanged except that the marks-event rollover now needs the rollover flag.
