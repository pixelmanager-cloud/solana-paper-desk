## What changed and why
- **Units (`deploy/fresh/`)**: same unit names as today (so `tools.ops.cutover` drop-ins apply) with `<FRESH_ROOT>`, `<RELEASE_DIR>`,
  `<CONFIG>`, `<SCHEDULER_IDENTITY>`, `<PACING_DB>`, `<DISCOVERY_DB>`, ... placeholders matching T13's layout
  (`research/evidence/paper-ledger/paper-decisions.sqlite`, `entry-dispatch/dispatch.sqlite`, `paper-scheduler.lock`).
  Discovery: `Restart=always` + start limit (the code caps `listen` at 86400 s and exits 0; budgets are persistent, a restart resets nothing).
  Boot-enabled: discovery, dashboard (loopback), held timer, decisions timer, backup timer, healthcheck timer, daily summary timer.
  `[Install]` on every timer; entry timer and monitor timer are documented manual-enable.
- **T09 F8/F11 fold-in**: entry `TimeoutStartSec=600`, held `120`; `DESK_PAPER_SCHEDULER_IDENTITY` on every scheduler unit and
  `ConditionPathExists` on the pre-created lock (not recreated: its inode is pinned); `DESK_PROVIDER_PACING_DB` on entry/held; entry has
  `--execute --systemd-credentials`; entry/held/monitor share one config and ledger; no `--dependency-blocker`.
- **`tools.ops.healthcheck`**: read-only (every DB `mode=ro`; only `systemctl show` is run; optional `--out` report), one JSON line,
  exit 2 on CRITICAL. Checks: unit state/NRestarts, timer tick recency, discovery frame/event freshness, ledger mode/unresolved exits/
  mark age/max hold/missing checkpoint, NULL observation passes, monitoring headroom/latch/pending, pacing blocked/orphaned slot, disk, backup age.
  A failing probe is itself CRITICAL, never skipped.
- **`tools.ops.notify`**: journal notifier + state file (0600, atomic); optional Telegram only if `telegram.json` exists in systemd credentials;
  de-dup, escalation, reminders (1 h CRITICAL / 6 h WARN), `RESOLVED`, 12 messages/h cap, failed delivery retried, redaction, daily summary
  (mode, cash, realized PnL, open positions, 24 h buy/sell fills, blockers).
- **Docs**: alert table with operator responses, install order, timeouts, limitations.

## Limitations (honest)
- Never loaded by a real systemd/journald or sent to a real Telegram; `LastTriggerUSec` parsing assumes `--timestamp=utc` output.
- `desk.backup` cannot back up the fresh set (requires `launches/raw/active-paper.sqlite`), so the backup unit depends on T03's `tools.ops.backup`
  (separate branch; flags per its code: `--data --destination --label`) and its manifest `created_utc`. Shared pacing/discovery stores are not in the snapshots.
- Investigation daily/lifetime budget is not probed; the monitoring cap is a configurable threshold (3600) because the stored `cap` column does not show the activated allowance.
- The healthcheck reports problems; it cannot fix the latches it detects (NULL pass F1, monitoring `SOURCE_FAILURE` F2, orphaned pacing slot F6). Those need T01/T08 and coordinator action.
- Held cadence 2 min and monitor/decisions timings are my choices, not measured.
