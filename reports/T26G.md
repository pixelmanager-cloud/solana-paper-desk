# T26G — Two remaining classification bugs in the counterfactual (plus the null-pool backoff)

Branch `cloud/T26G`. BASE `origin/cloud/T26F`, then `origin/integration/r1` merged in (merge commit on the branch;
it brings T01's `desk/paper_cycle_no_entry`). Owns `tools/research/counterfactual.py`, `tests/test_counterfactual.py`;
nothing under `desk/` was edited (imported only).

## What changed and why
1. **(HIGH) Latches are no longer filter rejections.** A BLOCKED `paper_cycle_v1` result is
   `REJECTED:OBSERVATIONS:<code>` only when every blocker is in T01's `desk.paper_cycle_no_entry.NORMAL`
   (imported, not copied), **or** a `paper_cycle_no_entry` row exists for the result's scan, **or** the result carries a
   well-formed `terminal_receipt_hash` (see judgement call). Anything else is class `UNRESOLVED` with the blocker codes
   and detail `LATCH_NOT_A_NORMAL_REJECTION` (`LATCH_EVIDENCE_UNREADABLE` when an `--evidence-db` was given but could not
   be read). The report shows them as separate `UNRESOLVED:<code>` groups, never under `REJECTED:*`. A mixed set
   (NORMAL + non-NORMAL blocker) is UNRESOLVED. UNRESOLVED is never final, so a `paper_cycle_no_entry` row that appears
   later reclassifies the candidate (a new append-only outcome row; the earlier row is kept).
   `OutcomeReader`, `_outcome`, `ingest`, `refresh_outcomes` and the CLI (`ingest --evidence-db`) accept the read-only
   evidence store; an absent `paper_cycle_no_entry` table is "no rows", an unreadable store proves nothing.
2. **(MED) Decision-store results are provisional.** `_is_final`: a `source=DECISIONS` rejection becomes final only after
   the dispatch window plus grace has closed (same rule as NOT_DISPATCHED); until then every pass re-reads it. Priority
   stays ledger BUY > journal > decision, so a decision REJECT followed by a ledger BUY gives BOUGHT. Typed journal
   rejections and BUY remain immediately final.
3. **(LOW) Null-pool backoff.** `null_pool_delay(attempts, *, last, migrated, grace)`: base 60 s doubling to 15 min as
   before, but capped so the next try is no later than the start of the next sample window, and every 30 s
   (`NULL_POOL_IN_WINDOW`) while the previous try lies inside a window `[migrated+h, migrated+h+grace]`. The old pure
   doubling tried at +10, +70, +190, +430 s and so missed the +5m window (300..420 s) entirely.
   `null_pool_delay(attempts)` keeps its old meaning. Cost is bounded: at most 5 in-window tries per window.

## Judgement call (please veto if wrong)
The task text says "everything else is UNRESOLVED". A cycle result that carries `terminal_receipt_hash` was certified
terminal by `paper_cycle` itself (`certify_intrinsic`, e.g. a MAYHEM_POOL hazard rejection) and is not a latch, so it
stays a rejection; treating the desk's own correct hazard rejections as UNRESOLVED would hide exactly what the
counterfactual study needs. Only a 64-hex value counts; the receipt is not re-verified against the evidence store here.
Removing the `certified` term in `classify_result` restores the literal reading.

## Limitations
* Without `--evidence-db` a latch is classified from its blocker list only (NORMAL or not); a retired pass whose blocker is
  not in `NORMAL` and that has no certified receipt stays UNRESOLVED unless the evidence store is supplied.
* The coordinator must pass `--evidence-db` in the counterfactual service/ingest unit for rows-based proof.
* `terminal_receipt_hash` is trusted as written in the dispatcher journal (which the dispatcher itself validates).
* No live data; schedule timings are arithmetic on fixtures.
