## What changed
1. **Catch-all.** `_read_chunked`'s `except Exception` now returns `classify_exception(error)` instead of a blanket `TRANSPORT_ERROR`: network exceptions stay transient; `ValueError`/`AttributeError`/`RuntimeError` become `UNCLASSIFIED_ERROR`, certificate failures `TLS_ERROR` — both latch. (Test drives the real `_read_chunked` with a genuine chunked `HTTPResponse` whose body read fails.)
2. **Missing/recreated lock file = owner unknown.** `_lock_holders` returns `None` (fail closed) for a missing lock file. New `_deleted_lock_holders`: scans `<PROC_ROOT>/<pid>/fd` for another process holding the lock file's DELETED inode (the unlinked/recreated-file hazard); any holder, or an unreadable same-user process table, blocks abandonment. `_owner_gone` requires both checks for both lock files. The T09 test now creates the lock files like `run_once` does, so it exercises the real owner check.
3. **macOS/portable tests.** `LOCK_TABLE` and `PROC_ROOT` are module constants (injectable). The four tests that need the real `/proc/locks` are `skipUnless(Linux)` with a stated reason; the `Abandonment` fixture injects an empty table/tree on non-Linux hosts, and new portable tests drive the same logic with fixture lock tables and fake `/proc` trees (foreign holder blocks, only-ourselves resolves, missing file, recreated file with a live holder on the old inode, unreadable tree). Linux CI still runs the real-/proc tests.
4. **None-status scope.** `None` is now reserved for `CoordinatorRPCError`: an `HTTPError` (or response) with a non-int status is recorded as status `-1`, which latches. The predicate keeps `None` transient; the record is the narrowing point (test checks the retained `http_status`).
5. **Handoff after a kill.** Chose the CRITICAL path (not abandonment): allowance-version-3 contexts bind every receipt to the context hash, and fresh-start stores have none. `snapshot()` now adds `health: "CRITICAL"` and `operator_guidance` (archive the store set and start a fresh one with a new config version) when the pending orphan sits in a handoff context; the blocker stays `MONITORING_OUTCOME_PENDING`, nothing is refunded or rewritten.

## Limitations
- `_deleted_lock_holders` skips process directories it cannot read when they belong to another user; a root-owned process holding an unlinked lock file of a service user is a residual risk (needs root to have the file open). The ctime-based "recreated" heuristic was rejected: reservation times come from an injectable clock and cannot be compared with file times.
- Handoff (v3) orphans still block permanently; the report is now explicit (CRITICAL + guidance) but nothing resolves them.
- Scanning `/proc/*/fd` happens only when an orphan exists; bounded at 65536 pids.

## For the coordinator
- Hash domain: `desk/` changed → rotate to a fresh store set; no pins written. Fresh stores never have handoff contexts.
- Lock files `<evidence>.ownership-invocation.lock` and `<ledger>.paper-cycle.lock` must not be deleted by operators or backup tooling while services have orphans pending: a missing file now blocks abandonment (fail closed).
