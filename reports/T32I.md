## What changed
1. **(BLOCKER) preflight vs seal.** `_live_findings` accepted only `mode & 0o022 == 0` for external store directories, so the sealed
   `$OLD` / `$OLD/discovery` (`root:solana-desk 1770`) gave `LIVE_external_*_dir:MODE_1770`. New `_sealed_dir`: a directory that is
   root-owned, has the service group (the group of `--data`), the sticky bit and no other bits is accepted. Everything else (service-user
   owned, no sticky, any other bit, a foreign group, 0777) still blocks. New e2e runs the RUNBOOK's seal for real and then the REAL
   `preflight_dryrun.main` (copies, mount namespace, child; nothing stubbed) with the RUNBOOK step-6 arguments: `PASS`, no findings. On the
   base the same test reports `LIVE_external_pacing_db_dir:MODE_1770_LINKS_3` and `LIVE_external_discovery_db_dir:MODE_1770_LINKS_2`.
2. **(HIGH) pacing schema upgrade.** New RUNBOOK step `7a3`: `systemctl is-active` on every writer (must be inactive/failed), then
   `runuser -u solana-desk -- $PY -m desk.provider_pacing --upgrade $PACING` from `cd $REL`, with the one-way-door text (older code raises
   `PACING_DATABASE_INVALID`; do not use it if you may fall back to the old stack; never reset the database). The rollback sentence names 7a2
   and 7a3. The e2e runs the command as written against a production-shaped database (Kraken migration receipt present, no `pacing_reclaims`):
   `PACING_UPGRADED`, every existing row unchanged, the new table is append-only, a second run says `PACING_ALREADY_UPGRADED`, the strict
   schema check and `pacing_policy plan` still accept the database.
3. **T36 composition.** One policy step: T32H's `7a2` (`## 6b` dropped; a test counts the pacing-policy headings and commands).
   `DEFAULT_WRITERS` now covers monitor, decisions, backup, healthcheck, counterfactual, held-watcher, continuous discovery and the T42 daily
   report (plus the existing entry, held, fill-realism, dashboard). `tests/test_ops_pacing_writers.py` recomputes the required set from the
   `deploy/fresh` templates (any non-comment line reaching the pacing store, or run through `tools.paper_scheduler`, `tools.ops.backup`,
   `tools.ops.healthcheck`, plus the timers/paths that start them) and from `fresh_start.unit_arguments` (units with
   `DESK_PROVIDER_PACING_DB`), so a new template that touches the store fails the test until it is listed.
4. **(MED) evidence files.** `SEAL_PATTERNS` now include `*.json` and `*.jsonl`. Locks are still never touched (a `telegram.json.lock` is
   asserted untouched). The e2e fixture holds 12 JSON/JSONL evidence files that end up `0440 root:solana-desk` and in the manifest.
5. **(LOW) rotate manifest.** The rotate step now shows both seal commands with a new manifest path
   (`seal-manifest-rotate-<next version>.json`); the e2e runs them and proves the same path is refused the second time.
6. **(LOW) rotate seal mode.** `shared_dirs` is only the directories that hold a `--shared-path`; the root is no longer always included, so
   a root sealed without `--shared-path` is `0550` (and with only `discovery/continuous.sqlite` shared only `discovery/` is `1770`).
7. **(LOW) portability.** `SealArchiveTests` compare gid with the parent directory's gid, not `os.getegid()`.
