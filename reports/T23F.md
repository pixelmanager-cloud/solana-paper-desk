## Limitations (honest)
- A forked child inherits the holder fd (CLOEXEC only protects exec), so a parent killed while a forked child lives looks alive until the child exits. Nothing in the desk forks while holding a slot.
- An OLD-code owner takes no holder lock, so with old and new code mixed an old-code grant older than 60 s would look "gone"; the upgrade step is therefore only to be run after every unit runs the new code.
- Reclaim needs write access to the pacing directory (the holder lock file); a read-only caller simply gets "not reclaimed" and keeps refusing.
- Item 4b above and the scheduler pre-check in item 5 need files outside OWNS.
