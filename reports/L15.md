## Behaviour
- **Credit tracker.**
  - Counts every HTTP attempt per provider and method (attempts come from the response `meta`, or from `ProviderError.meta` on a failure), so retries and 503s cost credits.
  - Credits come from `ops.credit_costs`, merged over defaults: Helius 1 per request and 10 for `getProgramAccounts`; Jupiter and Kraken 0. These are ESTIMATES, and the health JSON says so.
  - Usage is snapshotted into the store (`events` kind `credit_usage`, at most once a minute plus a forced flush at stop) and restored on start for the same UTC month. A new month starts at zero.
  - Projection = month-to-date + (last-24h rate) × (seconds left in the month). It needs ≥10 minutes of data, otherwise `INSUFFICIENT_DATA`, and it never sheds on that.
  - With `credit_budget_month` set and the projection above it, `allow(lane)` returns False for the low-priority lanes `paths`, `features` and `wallet_signals`. Hysteresis: shedding stops below 90% of the budget. One `CREDIT_SHED` row is written per lane and episode. Screening and exit lanes always get True.
- **Watchdog.**
  - Armed when systemd sets `WATCHDOG_USEC`. It pings `WATCHDOG=1` every half-timeout (1–60 s), only while BOTH heartbeats are younger than `watchdog_stale_s` (default 180), and sends `STOPPING=1` on stop.
  - A stale loop withholds the ping and writes one `WATCHDOG_STALL` row (re-reported only after a recovery). systemd then restarts the unit, which `Restart=on-failure` covers.
  - The candidate loop also beats after every candidate and the position loop after every position, so a long but progressing pass does not trip it.
  - Without an `ops` block but with an armed systemd watchdog, `build_runner` creates a pinger-only Ops (`watchdog_only_config`: no metering, no regime, no rows), so the unit's `WatchdogSec=` can never kill a healthy runner on an old config.
- **Regime log.** Every `regime_interval_s` (300) one `observations(kind='regime')` row:
  - SOL/USD from the runner's own cached value (the same Kraken limiter);
  - the 1h and 24h changes against the log's own earlier stored samples, `null` unless a sample lies within max(2 intervals, 5% of the window) of the wanted time (10 min for 1h, 72 min for 24h); never extrapolated, and continuing across restarts;
  - candidates stored in the last hour (and per hour once ≥10 minutes were observed).
  - A provider failure is recorded in the row and never raised. No decision code reads these rows (a test greps the runner and strategy sources).
- **Morning report.** `<out>/YYYY-MM-DD.html` + `.json` (KST date of the run), built with the L06 `report.build/render_html`. An existing page is kept. The directory is created 0700 and a symlinked directory is refused. With `--grid FILE` and `lean.tune` (L08) importable it also writes `YYYY-MM-DD-replay.html` (from `tune.main(... --calibrate ...)`) and links it; any L08 failure is noted in the page and never blocks the main report. The service runs sandboxed with `PrivateNetwork=true` and no credentials.

## Tests
`python -m unittest discover -s tests/lean -t .` → **345 tests, OK, rc=0** (three consecutive runs), including `test_e2e_real`. New: `test_ops.py` (49), `test_regime.py` (12), `test_e2e_ops.py` (6).

`test_e2e_ops.py` uses the real runner, providers, store, regime log and credit tracker, with only HTTP faked by `fakeworld` (a moving Kraken price is layered on top).
- **Counting.** The tracker's counts equal what the fake world served, including the 503 outage attempts.
- **Shedding.** A small budget sheds the data lanes while trading continues: the five expected entries happen, and no extra rows are written beyond the two `CREDIT_SHED` rows.
- **Regime.** Rows arrive every ~5 minutes and the 1h change is `null` before ~50 minutes and ≈9.45% at 1.5 h.
- **Watchdog.** Real AF_UNIX `NOTIFY_SOCKET` datagrams. Pings flow while both loops are fresh; a position loop that stops beating withholds them, produces one `WATCHDOG_STALL`, and recovers.
- **Restart.** A new process on the same state continues the credit usage and the regime history.
- **Non-intrusive.** The paper fills are IDENTICAL with ops disabled.
- **Pinger-only mode.** A runner with no ops block but an armed systemd watchdog still gets pings and writes no regime or credit rows.
- **Slow pass.** A 100 s-per-candidate pass over a 120 s stale limit keeps the watchdog fed.

Mutations tried (each turned at least one test red, then was restored): `allow()` always True; ping regardless of stale heartbeats; attempts ignored (failed and successful calls); credit restore on start disabled; no shedding hysteresis; 1h change inverted; reference tolerance removed; morning report overwriting an existing page; position-loop beat removed from the runner; candidate-loop per-candidate beat removed (first survived, so I added the slow-pass test, which now kills it); `screening` added to the shed lanes.

## Remaining limitations (honest)
- Credit costs are ESTIMATES, not measured. Calibrate `ops.credit_costs` against the Helius dashboard; the projection is only as good as the table. Jupiter and Kraken are counted but free.
- Nothing in the lean desk currently asks `allow('paths'|'features'|'wallet_signals')`: those lanes belong to L07/L12/L13, which are not merged here. Shedding is therefore effective only once they call `runner.ops.credits.allow(lane)` before spending (documented in the README). The counters, projection, rows and health are live now.
- Past the budget there is no shedding of screening or exits by design, so a runaway screening rate is visible (`status: SHEDDING`) but not throttled.
- A crash loses up to `credit_flush_s` (60 s) of credit counts; downtime inside the 24 h window lowers the projected rate.
- `candidates_1h` counts candidates the runner stored, so it is the intake rate only while the runner is up.
- The 24h SOL/USD change appears only after a day of runtime (own samples, no external OHLC call).
- `systemd-analyze verify` only complains that `/opt/solana-desk/.venv/bin/python` is missing in this sandbox; the units were not started here.
