# L10 — Latency-aware fills + realistic costs

Branch `cloud/L10`, BASE `origin/cloud/L09`. PAPER ONLY, nothing signs or sends. `desk/` untouched (`git diff origin/cloud/L09 -- desk/` is empty).

## What changed
New `lean/execution.py` (all logic), plus small clearly delimited `# --- L10 hook ---` blocks (each under 30 lines) in `lean/runner.py`, `lean/__main__.py`, `lean/adapters.py` and `lean/report.py`, and `"execution": null` in `config/lean/lean.example.json` (additive). New example `config/lean/lean.execution.example.json` shows the model ON.

**Config.** `lean.json` key `execution`: absent or null = today's instant fills (existing behaviour and `test_e2e_real` unchanged). An object turns the model on; unknown keys are refused. Keys (money in SOL, stored as lamports): `exec_delay_s` (3), `priority_fee_sol` (0.0001), `jito_tip_sol` (0.0001), `ata_rent_sol` (0.00203928), `exit_requote_attempts` (5), `exit_requote_gap_s` (1). `exec_delay_s` must be <= `price_ttl_seconds - 2`, else startup refuses (otherwise every exit would be BLOCKED as a stale mark).

**BUY.** q0 is the decision quote. After `exec_delay_s` the same spend is re-quoted (q1). Fill = the worse (fewer tokens). If q1 is better, the fill stays q0 with tax 0. If q1 is worse, the sell leg for the tokens now held is re-quoted and the strategy's own `entry_decision` is re-run on that round trip, so the cost cap is enforced on the latency-adjusted quotes. No route on q1, a failed sell-leg re-quote, a broken cost cap, or an unreadable Token-2022 mint all record a decision `ENTRY_ABORTED_LATENCY` with reasons (`Q1_UNAVAILABLE:<code>`, `LATENCY_<reason>`, `TRANSFER_FEE_UNREADABLE`) and skip. No `errors` row, no halt; counter `entry_aborted_latency` in health.

**SELL.** After the delay the exact quantity is re-quoted and the fill is always q1. The final exit decision runs on q1. If q1 cannot be had (bounded `exit_requote_attempts`, and only inside the mark's freshness window), the position stays open, the `ProviderError` is recorded by the existing isolation, and the exit is retried on the next position pass with a fresh mark ("retry until a quote exists", spread across passes so the exit lane is never blocked).

**Both quotes + latency tax.** Every fill's `position_state` row (written in the SAME transaction as the fill) has key `execution`: `q0_ref/q0_out`, `q1_ref/q1_out`, `fill` (`q0|q1`), `fill_ref/fill_out`, `delay_s`, `latency_tax_bps = (q0_out - fill_out) / q0_out * 10000` (on the output of the same input; positive = worse than the decision, negative = a better exit), and the fee breakdown.

**Cost model.** Priority fee + Jito tip are added to the paper config fee (`Execution.pcfg`), which also feeds the net marks, so the strategy sees the cost it pays. ATA rent is paid in the first buy's fee (cash really leaves) and refunded in the proceeds of the full close; the adapter keeps the remaining rent out of the strategy's cost basis (so a stop or take-profit is not skewed by 2.5% on a small position). The refund and the haircut are recomputed into `realized_lamports`, so `paper.apply_fill` and `check_invariants` still reconcile. Token-2022 transfer fee: bps from the mint account the screen loaded (TLV type 1, larger of older/newer, cap ignored; legacy mints = 0). A buy delivers `qty*(1-bps)`, a sell is haircut by the same bps; bps is stored in the position state.

**Report.** `lean.report` gets an `execution` section (JSON + HTML): latency-tax n/p50/p90/mean/max per side, entries aborted by reason, and fees in SOL (base, priority, tip, ATA rent paid/refunded/outstanding, transfer-fee loss, trading-fee total), with the usual `INSUFFICIENT_SAMPLE` flag under 30.

## Limitations (honest)
- The delay is a real `sleep` inside the pass. Positions that exit in the same pass are handled one after another, so the Nth exit waits (N-1)*delay extra; with 4 positions, 9 s at the 3 s default. Still within the 10 s mark window per exit, but a stale mark can BLOCK a later exit in the same pass, which is then retried next tick (visible as extra pass latency, never a lost exit). The candidate loop runs in its own thread, so entries do not delay exits.
- ATA rent is assumed refunded on a full close (the bot closes the empty account). Token-2022 accounts with extensions need more rent; `ata_rent_sol` is one number per run.
- The strategy's round-trip cost cap still uses `fixed_fee_sol` (0.00005), not the priority fee, tip or rent; rent is a temporary lock-up, but priority fee + tip (0.0003 SOL per round trip) are not in the cap. Only the re-quote cost-cap check is added. Raising `fixed_fee_sol` in the strategy config is the knob if wanted (a different strategy_version).
- Equity (daily-loss stop) counts rent as a cost until it is refunded: marks exclude rent, cash does not (about 0.002 SOL per open position).
- The transfer-fee cap (`maximum_fee`) and the epoch switch are ignored (conservative). The sell haircut scales proceeds linearly with the fee (approximation). With screen profile 2 a mint with a TransferFeeConfig is rejected by the screen today, so this path is exercised by unit tests and a patched e2e only.
- q1 is a second quote of the same route, not a real transaction landing; it does not model failed or dropped transactions, MEV, or partial fills. Fills stay EXECUTION_UNVERIFIED.
- Not modelled: ATA creation fee beyond rent, Token-2022 transfer hooks, price impact of our own order on q1 beyond what the quote already contains.
