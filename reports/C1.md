# C1 — Offline exit-rule optimizer

Branch `cloud/C1`, BASE `origin/integration/r1`. New modules only: `lean/replay.py`, `lean/tune.py`, tests `test_replay.py`, `test_tune.py`, `test_e2e_replay.py`. No runner hook, no config key, no `desk/`, no network. PAPER ONLY, offline, read-only.

`python -m lean.tune --lean-db lean.sqlite --paths-db paths.sqlite --grid grid.json --out-dir DIR [--strategy f.json] [--fees f.json] [--max-paths N]`

## What it does
1. **Replay (`lean/replay.py`).** Reads `paths`, `path_marks`, `path_gaps`, `path_ends` from `paths.sqlite` and every `paths-*.sqlite` archive beside it, plain `mode=ro` (+ `query_only`); a path carried across a rollover is ONE path (marks united by timestamp). For every path a hypothetical entry (`entry.size_sol`, default 0.2) is replayed under a policy; every decision is the REAL `strategy.exit_decision` on the REAL `adapters.mark` of the stored raw `base_raw`/`quote_raw` (called only through `_net_mark`, so the coordinator's M1 mark-model change is a one-place edit).
   - *Costs:* the PumpSwap fee TIER per side at that mark's market cap (`quote*supply/base` in lamports) from `fixtures/mainnet-dynamic-fees.json` (lp + protocol + creator bps: 125 bps below 420 SOL, 120 bps at 420-1,470 SOL, ... down to ~0.30% at the top tier), 50 bps adverse slippage per leg, 0.00025 SOL per fill. `costs.fee_model: "flat"` reproduces the live runner's flat `pool_fee_bps` for calibration.
   - *Fills:* at the NEXT mark after the trigger (`lag` 1, default) or at the trigger mark (`lag` 0). A path that ends with the position open is closed at its last mark (reason `PATH_END`, counted per policy).
   - *Missing data:* `path_gaps` are never filled; decisions exist only at marks that were really read; `ACCOUNT_MISSING` / `MALFORMED` marks are dropped; `EMPTY_POOL` is a drained pool = mark 0 and the fill still pays its fee; a fill that crosses a recorded gap is counted (`fills_across_a_gap`).
2. **Exit families** (all parameterised in `grid.json`, list values form a Cartesian grid): `live_ladder` (config ladder / stop / trailing / time stop; optional overrides), `full_tp`, `hold`, `tp_time_cap`, `trailing` (armed from the entry), `partial_tp_trail`. They are expressed as `StrategyConfig` copies + the starting position fields; `exit_decision` is never reimplemented. The single thing the replay sets itself is the stage of `partial_tp_trail` after its take-profit (to arm the trailing stop).
3. **Tuning (`lean/tune.py`).** Purged, time-blocked, expanding walk-forward: equal-count time blocks; fold j trains on blocks 0..j-1 minus every path whose observation window (embargo = `path_hours`) reaches into block j, and tests on block j. On the train set only: a centred-bootstrap p-value for "EV <= 0" per policy, Benjamini-Hochberg over the whole grid, best train EV among the BH-significant ones is selected (none = no selection). The test block is read once, for that policy only. The pooled out-of-sample series gets the headline bootstrap CI.
4. **Report** (`tune-report.html` / `tune-report.json`): per policy EV per trade, bootstrap CI, first/second half, p5, P(return <= -50%), exit reasons, PATH_END share, and the distribution of how far fills land past the trigger (p5 / median / p95 / worst), BH q-values; plus the walk-forward folds, the pooled OOS result and the calibration. The all-data table is labelled IN-SAMPLE and selects nothing.
5. **`proposal.json` only when** the pooled OOS CI lower bound is above zero net of costs with at least `min_oos_trades` (default 30) trades; otherwise the file `NO_PROPOSAL` states why (no fold selected, below the minimum, CI not above zero, insufficient data). A proposal says NEVER AUTOMATIC. Outputs are created exclusively, 0600; nothing is overwritten.
6. **Calibration.** The live ladder is replayed on the paths of positions the trader really held and compared, reason by reason, with the live exits read from `lean.sqlite` `position_state`; mismatches are listed, never hidden.

## Tests (one process): `python -m unittest discover -s tests/lean -t .`
- New: `test_replay.py` 27, `test_tune.py` 23, `test_e2e_replay.py` 5. Full lean suite on top of `integration/r1`: `Ran 1199 tests ... OK`, rc=0, ONE process (123 s), including `test_e2e_real` and the existing suites.
- E2E on fakeworld with the real runner + recorder (the `test_e2e_real` scenario: 20 candidates, a Helius outage, a restart): with live-equivalent costs and lag 0 the replay reproduces ALL 7 live exit reasons (STOP, TAKE_PROFIT x3 then TRAILING_STOP, TAKE_PROFIT then STOP, TIME_STOP); with the default tier costs and next-mark fills it still reproduces all 7; a mark model that is 12% low is caught (mismatches), so the check is not vacuous.
- Planted structure: a quick-spike-then-collapse dataset yields a `full_tp` proposal with the pooled OOS CI above zero; a symmetric random-walk dataset yields NO proposal (no policy survives BH in any fold); too little data and too few OOS trades are reported as such.
- Mutations I tried (each makes the suite RED, restored): fill at the decision mark instead of the next mark; the fee tier ignored; missing (ACCOUNT_MISSING/MALFORMED) marks used as data; selection looking at the test block; no BH; no embargo purge; no minimum OOS trades; a 10% wrong mark model; the overwrite guard removed (it survived at first, because `O_EXCL` also refuses; the test now also asserts the explicit error, and the mutant dies); gap crossings not counted. 10 of 10 killed.

## Limitations (honest)
- Single entry size and one hypothetical entry per path at its first usable mark; the live entry/screen/throttle/portfolio rules are NOT replayed (paths of rejected-but-hazard-free candidates are included, as recorded). `entered` live paths are not special in the optimisation.
- The final exit decision with a fresh quote (`quote_required` re-call) is not repeated at the fill mark (a 15 s old mark would be stale by the strategy's own TTL); the trigger decision and `after_fill` updates are used. Net-of-fee checks such as STUCK_POSITION are therefore not replayed.
- Marks are every `interval_s` (15 s by default) and the exit lag is one mark: sub-interval wicks are invisible, and a lag-1 fill on a 15 s grid is pessimistic against a real bot's seconds-scale latency (use `lag` 0 for the optimistic bound).
- A path with a 6 h horizon and the position still open is force-closed (`PATH_END`) at the last mark; its share is printed per policy.
- The bootstrap treats trades as independent; overlapping paths within the embargo are purged between train and test but correlated within a block (market regimes), so CIs are optimistic.
- Pure-Python and single-process: roughly (paths x policies x marks) decision calls; use `--max-paths` for quick runs. There is no multiprocessing.
- `adapters.mark` currently ignores `virtual_quote_reserves` (marks come out ~12% low, M1 is fixing it). The replay uses whatever `adapters.mark` does today; after M1 lands the calibration should be re-run and, if the mark model is a config switch, the grid will need the same setting (`_net_mark` is the one place).
- A plain `mode=ro` open of a WAL file can leave SQLite's `-wal`/`-shm` sidecars next to a database that had none; the data files are never modified (tested by hash and mtime).
