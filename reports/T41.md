## What changed
- `tools/research/daily_report.py` (new): one command builds `YYYY-MM-DD.html` (self-contained: inline CSS, no JS, no external assets, every dynamic string escaped) and `YYYY-MM-DD.json` in `--out-dir`. It imports and runs the existing read-only tools, nothing re-implemented: T29 `funnel_report.build`, T26 `counterfactual.report`, T27 `shadow_strategies` (`load_candidates`/`run`, with the T40 `--features` file when given), T10 `forward_eval.evaluate`, T14 `fill_realism_report.report`, `healthcheck.build_report` and `status.budgets_section` (health + budget usage).
- Each section is built independently: `OK`, `NOT_PROVIDED` (input missing) or `ERROR` (exception class + first 160 chars, escaped). One broken input never hides the others and an error is never presented as data.
- Top block: "what changed since the previous report" and "what to try next", computed by rules from the data and the previous day's JSON (no LLM): UNRESOLVED latch first, failing health, INSUFFICIENT_SAMPLE with the exact n, rejection groups (n>=30) whose mean forward return beats the bought baseline, shadow leaderboard (a variant is only a "candidate" when its holdout bootstrap CI lower bound > 0; unranked means keep collecting), partial fill-realism coverage. The page shows 10 lines per block; the JSON holds all.
- Everything is labelled PAPER ONLY / EXECUTION_UNVERIFIED / profitability NOT_ASSESSED; every sample size is shown and n < 30 is flagged INSUFFICIENT_SAMPLE.
- Output safety: files are created with `O_EXCL|O_NOFOLLOW` mode 0600; an existing day is never overwritten (`REPORT_EXISTS`, exit 2); a symlinked or missing out dir is refused; a failed JSON write removes the HTML so a day is never left half-written.
- `deploy/fresh/desk-daily-report.service` + `.timer`: daily 23:30 UTC (08:30 KST), `Persistent=true`. Service: no credentials, `RestrictAddressFamilies=AF_UNIX` (only `systemctl show`), write access only to `<STATE_DIR>`, stores read-only, `Nice=15`, idle IO, `CPUQuota=50%`, `MemoryMax=512M`, `TasksMax=32`. Placeholders are the README ones, so `render-units` conventions apply.
- `tests/test_ops_healthcheck.py`: one line only — the exact-set unit inventory (`test_all_expected_units_exist`) now includes the two new unit names.

## Limitations
- The "what to try next" rules are heuristics over small paper samples; they are prompts for a human, not conclusions. The counterfactual rule compares mean forward returns without a confidence interval; it only fires with n>=30 per group.
- Funnel is built from the discovery DB over `--lookback-days` (default 7); with no discovery/journal/research input the funnel section is NOT_PROVIDED, not zero.
- The real funnel is exercised through its fixture (hints passed directly); `collect()` itself was not run against a full fresh store set (no VPS access), so the exact `--root` layout names come from `tools/ops/fresh_start.py` (`paper-ledger.sqlite`, `evidence.sqlite`, `research.sqlite`, `paper-decisions.sqlite`, `entry-dispatch/dispatch.sqlite`) plus `counterfactual/counterfactual.sqlite` from the counterfactual unit.
- Health uses `systemctl show` (needs systemd); use `--no-systemd` elsewhere. Systemd hardening is not executable-verified here.
- T40 features are consumed only if a features file is passed; none is generated.
