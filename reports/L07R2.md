# L07R2: review fixes to the path recorder (its own database, outcomes from memory, run-mode only)

Branch `cloud/L07R2` is based on `origin/integration/r1`, which already contains L07R. `desk/` is untouched. PAPER
ONLY.

## Result
`python -m unittest discover -s tests/lean -t .` in one process: **369 tests, OK, real rc=0** (about 4.3 s).
- The e2e test still shows identical trading with the recorder on and off: the same fills, decisions, exits and cash.
- `lean.sqlite` is now also identical table by table between the two runs.
- 19 of 19 mutations were killed (table below).

## The review items
1. **CRITICAL: path rows in the accounting DB.** All path data now lives in its own `paths.sqlite`.
   - **Location and access:** it sits in the state dir (`paths.db`, default `<state-dir>/paths.sqlite`), with its own
     connection and lock (`lean.paths.PathStore`). It uses WAL with `synchronous=NORMAL`. There are no accounting
     triggers; it is append-only by convention, and a test traces every statement and finds only INSERTs.
   - **Tables:**
     - `paths(mint PK, candidate_id, start_ts, ends_ts, entered, stage, reason, screen_reasons, holders_checked,
       features JSON, target JSON, carried_from, code_version, strategy_version)`
     - `path_marks(mint, ts, slot, base_raw, quote_raw, net_sol, liquidity_sol, status)`, index on `(mint, ts)`
       (a test checks the query plan uses it)
     - `path_gaps(mint, ts, cause)`, index on `(mint, ts)`
     - `path_ends(mint, ts, why, marks, gaps)`
   - **Live paths:** the `paths` rows without a `path_ends` row. This replaces the `paths_active` event.
   - **Rotation:** when the file passes `paths.max_db_gb` (default 2), it is renamed to `paths-YYYYMMDD[-n].sqlite`
     and logged at WARNING. A fresh `paths.sqlite` carries over the live paths (`carried_from`). A fresh file must at
     least double its carried size before it rolls again.
   - **Disk guard (added):** below `paths.min_free_gb` of free disk (default 2), nothing is written and health counts
     `disk_low`.
   - **The trader's store:** `lean.sqlite` gets NO path rows. The e2e test checks this: every table count, every
     observation kind and every event kind is equal with the recorder on and off, and none contains "path".
   - `Store.add_observations` (added in L07R) is removed; `lean/store.py` is back to its pre-L07R content.
   - **Size per mark row:** measured at about 180 B, down from about 650 B. At about 420 live paths that is about
     18 MB/h, roughly 0.43 GB/day, so the file rolls over about every 4.6 days at 2 GB.
2. **HIGH: store I/O from the recorder.** The recorder never reads or locks `lean.sqlite`.
   - Its `_outcome` store scans are gone. The runner notes what happened in memory: the screen, the reasons of the
     pre-quote gate or round-trip decision, the BUY fill, and the error code from `_isolated`. These are one-line
     `# --- L07R hook (one line) ---` notes.
   - `lean.paths.outcome(...)` is a pure function that turns that note into the path's stage and reasons: screen,
     entry reasons, `ENTRY_FAILED:<code>`, `NOT_FILLED` or `ENTRIES_STOPPED`.
   - An entered path's quantity and cost come from the fill (`sol_lamports + fee_lamports` = the position's cost basis).
3. **Notifier and report.** Both only open `lean.sqlite`: the notifier's `latest_marks` scans `kind='marks'`, and the
   report counts `observations`. With item 1 they never meet a path row, and the table-by-table equality in the e2e
   test verifies it.
4. **Label bias.** The poll order now rotates. Each poll starts at the first path the previous poll skipped, so a shed
   or the time budget no longer always drops the newest paths.
   - Every skipped due mark gets a `path_gaps(mint, ts, cause)` row. Causes: `shed`, `HTTP_429`, `budget`, another
     provider code (e.g. `HTTP_503`, `RPC_ERROR`), `stopped`, `POLL_CALL_FAILED`.
   - Test: 150 pools with a budget for 2 calls. The newest 50 are skipped with cause `budget` on the first poll and
     marked on the next. With rotation removed, the test fails.
5. **`--once` and `--clear-halt`.** `build_runner` only stores a factory (`runner._l07r_build`).
   - `Runner.run()` builds the recorder, resumes it from `paths.sqlite` before the loops start
     (`l07r_start_paths()`), then starts its thread.
   - Tests check that `build_runner` plus the `--once` passes never create `paths.sqlite`, and that `main()` with
     `--once` or `--clear-halt` never calls `run()` or `l07r_start_paths()`.
6. **Health.** `health.json` → `paths.alive` reports whether the recorder thread is running. A test runs `run()` and
   sees it true while running and false after stop.
   - `stop` is checked between chunks and before every pacing sleep. The remaining due marks become `stopped` gaps.
7. **JSON-RPC -32005.** `Helius.rpc` now sheds the low lane on `-32005` through the new `Transport.shed_low_lane()`.
   This happens on any lane: a throttle answer on the main lane sheds the recorder too. Both cases are tested.
8. **Example config.** `paths.enabled` is true, with `"db": null` (= `<state-dir>/paths.sqlite`), `"max_db_gb": 2` and
   `"min_free_gb": 2`. When `paths` is absent, the recorder is disabled.

## Cost at the default settings (~70 recorded candidates/h)
The call cost is unchanged from L07R: about 420 live paths, 9 `getMultipleAccounts` calls per poll, so about
**2,160 Helius calls per hour** (0.6 req/s of the 2 req/s low lane). Storage is now about 18 MB/h, in `paths.sqlite`
only.

## Limitations
- Rolled-over archives are never deleted automatically. The disk guard stops writes below `min_free_gb`; deleting old
  `paths-*.sqlite` files is an operator task.
- Readers that span a rollover (L08, L19) should read `paths-*.sqlite` plus `paths.sqlite`. A carried path's marks are
  split across two files; its `paths` row exists in both, with `carried_from` set in the new one.
