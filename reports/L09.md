# L09: make the lean paper desk run end to end

Branch `cloud/L09` = `origin/integration/r1` + `origin/cloud/L01`…`L06` (merged in order, clean), then the integration
work below. `desk/` is untouched (`git diff origin/integration/r1 -- desk/` is empty). PAPER ONLY throughout.

## Result
`python -m unittest discover -s tests/lean -t .` in ONE process: **278 tests, OK, rc=0** (about 1.8 s).
The acceptance test `tests/lean/test_e2e_real.py` passes and kills 8 of 8 adapter/runner/report mutants (below).

## What changed
**Adapter layer (`lean/adapters.py`, new).** This is the one place where units and types are converted. It covers:
provider `Quote` → `paper.Quote` and `strategy.RoundTrip`; store `Position` + `position_state` → `strategy.Position`;
a `Portfolio` built from the store (cash, exposure, equity at the latest marks, cooldowns, loss streak, entry throttle,
day-start equity); `StrategyConfig` → `PaperConfig` and the screen config (the bands have one source); net marks in
Decimal SOL (constant product less the pool fee and the fixed fee); and `Decision.qty` → an int raw qty for
`paper.sell(qty_raw=)`, floored and never above the held quantity.

**Runner (`lean/runner.py`, rewritten on the real interfaces).**
- `scan_new` with L03's `read_cursor`/`write_cursor` (an int from 0). The cursor also advances past batches with no candidate.
- It passes a `Providers` object, not a dict. A separate exit lane is used for marks and exit quotes.
- Entries use the two-step protocol: a pre-quote gate, then a buy quote at the decided size, then a sell-leg quote
  for exactly the tokens the fill will hold, then the decision. Exits follow the same pattern: mark, then a sell quote
  for the exact raw qty, then the decision. `Decision.action` and `quote_required` are honoured.
- Fills go through `store.add_fill(paper.Fill)`. The position state is written in the same transaction: `open` with
  the pool/vault keys and initial qty, then `rung` / `closed` with the stage, stop, reason, cooldown and trade PnL.
  Peak and touched changes are persisted on HOLD.
- Screens, decisions, observations (all raw provider bytes, including error bodies) and errors use the typed helpers.
- Transient screening failures are retried in memory (3 attempts). `DISCOVERY_UNAVAILABLE` is retried on the next pass.
- Only an `AccountingHalt` or a store failure (`StoreError` / `sqlite3.Error`, including during candidate handling)
  halts. The halt is persisted in the store and survives restarts until `--clear-halt`.
- Startup runs `check_invariants` and `check_position_states`.
- `health.json` is written atomically: a unique `mkstemp` file, fsync, rename, under a lock. The counters are locked.
- The UTC-day loss baseline rolls over only when the marks are fresh.

**`__main__`.**
- A strict `lean.json`; `config/lean/lean.example.json` lists every key.
- The store is created on first start with `initial_cash_sol`.
- Keys are loaded via `providers.load_keys`, which accepts `HELIUS_API_KEY`/`JUPITER_API_KEY` and modes 0400/0440/0600.
  Keys are never printed.
- New `--clear-halt` option.

**Unit.**
- `Environment=LEAN_CODE_VERSION=` (filled at install).
- Added `CapabilityBoundingSet=`, `PrivateDevices`, `ProtectKernelTunables/Modules/Logs`,
  `SystemCallFilter=@system-service` and other safe hardening.
- `ReadWritePaths` is only the state dir.
- The read-only open of the live WAL discovery DB, through its existing `-wal`/`-shm`, is documented. A test opens it
  with a read-only `-shm` and a read-only directory.

**Fixes in the L01–L04 modules (reviewer findings folded in).**
- providers:
  - `get_multiple_accounts` returns the validated RPC result unchanged (`{'context','value':[{data:[b64,'base64']}]}`),
    the one shape L03 and the desk decoders read.
  - `parse_quote` requires `inputMint`/`outputMint`/`swapMode=ExactIn` to echo the request.
  - There is one process-wide limiter per provider and lane; the exit lane is a reserved 25% of Helius/Jupiter.
  - `acquire(deadline)` never sleeps past the call deadline (`RATE_LIMITED`).
  - HTTP error bodies are kept in `ProviderError.raw`.
  - Added the `PAPER_TAKER` constant: the desk's existing paper-quote taker, a valid pubkey, paper-only, never signs.
  - New tests: the RateLimiter lock (fails if the lock is removed; verified), and a 429 block blocking other callers
    bounded by their deadline.
- candidates:
  - Typed `DiscoveryUnavailable` (missing/locked/corrupt DB).
  - `ScanResult` is iterable, so `iter_new_candidates` can't drop `next_cursor`.
  - A holder-lookup failure is a typed transient reject (`HOLDERS_UNAVAILABLE`), not a pass.
  - Vault keys are added to the features.
- store:
  - New `position_state` table.
  - `PRAGMA recursive_triggers=ON`, so `INSERT OR REPLACE` can't bypass the append-only guards (tested; the test fails without it).
  - A failed create removes the half-made file.
  - `rows()` takes bound filters only.
  - Halt/state helpers.
- paper: `sell(..., qty_raw=)`, with a TP1 → TP2 → TP3 sequential test.
- strategy:
  - The sell leg must equal `sell_quote_tokens(buy)`, now floored to a raw unit, so price impact can't hide from the cost cap.
  - TP qty is floored to whole raw units.
  - `mark_at` is required.
  - New `roll_day_start` helper (resets at UTC midnight; deferred while marks are stale).

**Report (L06).**
- Reads the real store: `qty_raw`/`sol_lamports`/`fee_lamports` in lamports, `decisions.reasons` parsed as JSON, exit
  reasons from `position_state`.
- Generic `events` rows are not counted when a typed table covers their kind.
- Observation BLOBs are never selected (checked with an SQL trace).
- New "exited" funnel stage.

## The e2e scenario (`tests/lean/test_e2e_real.py`)
The test uses the real L01–L06 modules. Only `urllib`'s opener is faked: `tests/lean/fakeworld.py` answers Helius
JSON-RPC (base64 SPL/PumpSwap accounts), Jupiter `swap/v2/build` (shape of `fixtures/mainnet-roundtrip-simulation.json`,
constant-product with a 25 bps pool fee) and Kraken Trades. Discovery is a real discovery DB holding the desk's
migration transaction, re-keyed per token. It uses the default `lean-1` strategy config and 10 SOL. The run covers 20
candidates over about 75 fake minutes:
- **Rejected by the screen (6):** mint authority, freeze authority, outstanding LP, holder concentration, market cap
  above max, liquidity below min.
- **Skipped at entry:**
  - `COST_BUDGET` (a 6% route).
  - `MAX_POSITIONS` (5 candidates while 4 positions are open).
  - A Jupiter 400 no-route; its body is kept as an observation.
- **Entered: 7.**
  - **STOP:** 3 positions closed by the plain stop.
  - **TP1 → TP2 → TP3 → TRAILING_STOP:** one position. Each rung sells `floor(initial × fraction)` and the remainder
    closes exactly.
  - **TP1 then STOP:** one position, stopped at the raised stop of 1.0.
  - **TIME_STOP:** 2 positions.
- **Outage:** Helius answers 503 for about 35 s. During it, one screen fails and is retried on the next pass, then
  enters. One marks read fails, and exits wait. Nothing halts.
- **Restart:** a new process is started at T+1530 s on the same state dir, with 4 open positions (two past TP rungs).
  The state is identical before and after the restart. No rung fires twice: the ladder token has exactly 3
  TAKE_PROFIT fills and the TP1 token has exactly 1.
- **Invariants:** `check_invariants()` and `check_position_states()` pass after every tick, and the runner never halts.
- **Report:** the funnel reads 20/20/14/7/7. Overall PnL equals `store.realized()` (0.054478741 SOL), and every trade
  matches its closed `trade_pnl_lamports`. The exit-reason table reads STOP 4, TRAILING 1, TIME 2.

**Mutations.** Each one makes the e2e test fail:
- dropping `after_fill` (stage not persisted);
- taking the initial qty from the current position;
- the SOL quote leg in lamports;
- the mark in lamports;
- the sell leg not haircut;
- the peak not persisted on HOLD;
- the report reading lamports as SOL;
- the retry queue disabled.

## Limitations
- **Untested against the live services.** The Jupiter `swap/v2/build` and Helius shapes follow the repo's captured
  fixtures and docs. `PAPER_TAKER` is the desk's production paper taker; whether `build` needs it funded was not re-checked.
- **Mark accuracy.** Marks use the vault balances only (spendable SOL plus a configured 25 bps pool fee). They ignore
  `virtual_quote_reserves` and accrued protocol fees in the quote vault, so a boosted pool is marked slightly off.
  Exits always re-quote, so the fills themselves are exact.
- **Retries are in memory.** A transiently failed candidate is not retried after a restart, because a mint already in
  `candidates` is skipped.
- **Halts need an operator.** A persisted halt stops all new fills, exits included, until `--clear-halt`.
- **Read-only discovery open.** It relies on SQLite ≥ 3.22's read-only `-shm` fallback while discovery is writing. If
  the `-shm` is missing or uninitialised, the scan is `DISCOVERY_UNAVAILABLE` and is retried on the next pass.
- **Not run.** The full desk suite (about 25 minutes) was not run: `desk/` and the non-lean tests are untouched.
