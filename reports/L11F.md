## What changed, per review item
1. **UNSELLABLE valuation (HIGH).** A rug position whose exit is failing is valued at 0 unless an executable sell quote younger than
   `unsellable_value_ttl_s` (30 s) exists; never at the last good price or at cost. `HeldRisk._value` runs in `after_marks`, BEFORE the D1
   quote marks, so no doomed `quote:mark` request is made for it and `cost_basis_mints` stays empty (tests: no_route, gone pool + no route).
2. **Marks are the 3-tuple `(value, at, source)`** (source `held_risk`); `health.json` marks and the equity code work (the old code crashed
   `health()` with an IndexError: that was the 7 errors of the mechanical merge).
3. **D2's single path.** The module no longer sells, no longer has `manage()`, `_force_exit`, `_sell`, `_writeoff`, its own UNSELLABLE state or
   its own 6 h write-off clock (`unsellable_writeoff_s` is removed from the config). A trigger makes the exit wanted as `DANGER` inside
   `Runner._manage` (`S.exit_decision(..., danger=True)`: the strategy's own forced exit), so quote, fee, slippage, `_exit_failed` /
   `exit_failing_since` and `_write_off` are D2's. The reason is chosen by the detector: `_write_off` closes with `RUG_WRITEOFF` when the
   position state carries `rug_trigger`, else `UNEXITABLE` (unchanged). The trigger is stamped on the state (durable once saved).
   Rug exits and rug write-offs cool down like a STOP.
4. **Default off.** `held_risk.enabled` defaults to false; `build({})` returns None; the example config ships `"enabled": false`; `load_config`
   validates the object strictly (unknown keys such as the removed `unsellable_writeoff_s` are refused).
5. **Probes after the exit pass.** Position pass: marks -> `after_marks` (no I/O) -> quote marks -> exits -> `after_exits` (route probes + the batched
   account read). Findings act on the next pass. A fresh D1 quote mark (source `quote`) is reused as the probe result. Test: with a rug exit and a
   healthy position in the same pass, the rug's sell quote is the FIRST Jupiter request of that pass.
6. **Baseline.** The latest PASS `screen` decision no later than the opening fill's timestamp (not the oldest of 20 rows; not one after the BUY); fallback
   the first mark.
7. **POOL_GONE needs 2 consecutive missing reads** (`pool_gone_confirmations`, default 2; applies to the marks read AND to the pool-account check; a good
   read resets; one mark_at counts once; a read that did not happen neither counts nor resets). The counters are persisted events and **a trigger
   is now replayed** (the old replay counted triggers but lost them: after a restart a pending rug exit fell back to the ordinary strategy; test:
   `test_a_pending_trigger_survives_a_restart`, which fails with a STOP in that case). The event replay is paged (no 100000-row cap).

Also: report (`held_risk_report`) counts reasons `DANGER` and `RUG_WRITEOFF` and lists open rug exits that are failing now; `fakeworld` got
`pool_closed_until` (an additive one-read blip). Edits to shared files, all inside `# --- L11 hook ---` blocks except the necessary in-line ones:
`runner.py` (2 hook calls in `position_pass`, `rug` lookup + stamp at the top of `_manage`, `danger=bool(rug)` on the two `exit_decision` calls, the
cooldown argument and the write-off reason: in-line edits of D2 lines, minimal), `__main__.py` (config validation), `report.py`, `lean.example.json`.

## Limitations / for the coordinator
- Write-off timing is D2's `unexitable_after_s` (7200 s by default), no longer the old 6 h; the 120 s NO_ROUTE clock comes first.
- A rug position whose exit is failing counts as an open position for caps/exposure (cost basis in exposure) until D2 writes it off, as before.
- LIQUIDITY_DROP fires on a single read (as before; only POOL_GONE was asked to be confirmed). A bad single vault read could therefore force a
  `DANGER` exit at a fresh quote (a normal paper sell with fees, then the stop cooldown).
- The freeze check (account read) runs every 6th pass, so a migrated/closed pool is confirmed after ~2 x 6 passes (about 2 minutes at 10 s passes);
  the vault-missing path is much faster (2 reads).
- Reports/notify: `DANGER` is the exit reason of a forced rug exit (notify.py already has its label); the old `RUG_EXIT` name is gone.
- Not verified against live services (shapes follow the fakeworld fixtures).
