## What changed
1. **Incremental ingest (features).** Capped full rescans (`LIMIT 500000/1000000`) are gone.
   - New append-only, trigger-guarded `ingest_cursors(source, anchor, position, run_id)` (added with `CREATE TABLE IF NOT EXISTS` when a
     store is opened, so a store made before this change is upgraded in place; nothing is rewritten).
   - Sources with a cursor: `ledger.events` and `ledger.outcomes` (seq), `counterfactual.samples` and `decisions.decisions` (rowid).
   - Pages of 5000 rows read by iterating (no `fetchall` of a whole table; research scans are looked up per decision instead of loading
     500000 ids). At most 1000 pages per source per run; hitting it is counted (`page_bound_hit`, `skipped['PAGE_BOUND_HIT:<source>']`) and the
     next run continues from the cursor.
   - Outcomes are streamed in their own seq order next to the events. Every outcome of a page's events is attached to that page, so a
     bound ends a run between pages and can never store an event without its `reject_reasons`.
   - Rows and the cursor(s) covering them commit in ONE transaction per page (`Writer`); a crash loses neither.
   - `anchor` = the source's first row id. If the anchor differs or the cursor is past the end (source replaced/shrunk) the source is
     re-read from zero and `CURSOR_RESET_SOURCE_CHANGED` is counted. Old rows are never deleted.
   - A windowed run (`--since/--until`) neither reads nor writes cursors.
   - Small bounded sources (discovery hints, journal) are re-read whole and merged into the ledger page sharing their `(mint, as_of)` key;
     offering a subset of what a stored row already holds counts as `duplicate`, not `conflict`.
2. **Optional stores.** Only the ledger is required. A missing journal/research/decisions/discovery/counterfactual store is skipped and
   reported (`sources_unavailable`, `skipped['SOURCE_ABSENT:<name>']`), exit 0. Symlinks, hard links, corrupt files and missing tables still
   fail closed. A missing research store only loses the scan→mint fallback.
3. **Sample sizes.** "filters look non-harmful" needs at least one REJECTED group with n>=30. Otherwise
   `INSUFFICIENT_SAMPLE: every counterfactual group has n<30 (largest rejection group n=N)`.
4. **Features in the shadow section.** `--root` implies `<root>/features/features.sqlite` (`--features-store` overrides); `--features FILE` wins.
   The section result carries `features_label` (`source`, `mode` REAL_FEATURES_FOR_SOME_CANDIDATES / NEUTRAL_FEATURES_ONLY, real/neutral/total
   candidates, fields, `look_ahead_refused`) and the HTML says "real features for N of M candidates; neutral features for K". Store rows dated
   after a candidate's price path ends are dropped and counted; a missing store is neutral, not an error.
5. **Unit hardening.** Daily report: `ReadWritePaths=<STATE_DIR>/reports`, `PrivateNetwork=true`, `CPUWeight=20`, `IOWeight=20`.
   Error sections carry the exception class name only. Features unit lists `--counterfactual-store`.
6. **Open rule.** `healthcheck.ro`, `forward_eval._connect`, `fill_realism_report.report` use `funnel_report.open_mode`: `immutable=1` only
   for a quiet WAL file, `mode=ro` otherwise (so a live writer's WAL rows stay visible). Symlink/missing refusals unchanged.

## Limitations
- Cross-source rows at the same `(mint, as_of)` merge only for discovery/journal (into the ledger page). A decision or counterfactual sample at
  exactly the time of a stored ledger row is recorded in `feature_conflicts` (nothing lost, nothing overwritten) instead of merged.
- A ledger whose outcomes are not in event order (the real writer always writes them together) would have late outcomes counted
  (`OUTCOME_FOR_EARLIER_EVENT`) instead of attached.
- The 2M-event test takes ~35 s.
- systemd hardening (`PrivateNetwork` with `systemctl show` over AF_UNIX) is not executable-verified without systemd.
