# T02 — Read-only production status CLI

Branch `cloud/T02`, BASE `r1-base`. Owns `tools/ops/status.py`, `tests/test_ops_status.py` (no `desk/` edits, no `__init__.py` added; `tools/ops` stays a namespace package).

## What changed
`python -m tools.ops.status --data DIR --ledger PATH --config PATH [--release-dir DIR] [--systemd] [--check] [--last N]` prints one JSON report. Paper only, no network, never writes.

Sections: release identity (subprocess `python -I`, cwd=release dir, `implementation_hash`); ledger (table counts, event/outcome counts and max seq, state mode/cash/realized PnL/last_ts, positions, fill list with provenance and `execution_label`, metadata config_hash/implementation_hash, raw-file sha256 vs canonical digest, parsed file==stored config); observation passes (NULL vs resolved, NULL ids bounded to 50); dispatcher journal (last N intents/results with status/blockers); budgets (monitoring cap/window/used/pending reservations read from raw tables, ownership budgets and admission states); provider pacing (`next_at`, `blocked_until`, `high_water`, `pending`, waiters); store inventory (size, mtime, `quick_check` only with `--check`); `--systemd` (ActiveState, UnitFileState, Result, WorkingDirectory, DropInPaths via injectable runner); dashboard :8765 non-loopback flag via `ss`; `blockers` list (held position, mode != RUNNING, NULL passes, config differs from ledger, monitoring exhausted/pending, ownership budget exhausted, pacing blocked/pending, non-loopback dashboard, unreadable sections).

Fail-closed behaviour: every path must be absolute, symlink-free, regular, single-link. A section that cannot be read becomes `{"status":"ERROR"}`, adds `UNREADABLE_<SECTION>` and the process exits 2. A missing store is never created.

## Tests (`python -m unittest tests.test_ops_status`, 12 tests, all pass)
- Fail-first: on BASE the module does not exist, so the test module errors at import (RED, verified by moving `status.py` away); GREEN with the change.
- Mutation evidence (each makes the suite RED, restored afterwards): canonical-path check removed; `immutable` sidecar guard removed; NULL-pass blocker removed; non-loopback dashboard detection removed.
- Adversarial: symlinked ledger, hardlinked ledger, symlinked data dir, relative path, missing store, changed config file, exhausted monitoring budget, pacing `blocked_until`, non-loopback dashboard, byte+mtime identity of all files before/after.
- Fixtures use the repo's own creators (`Ledger`, `EvidenceStore`, `HistoryProgress`, `MonitoringBudget.provision`, `provider_pacing.initialize`, dispatcher `SCHEMAS`/`_guards`) and a fake runner for systemctl/ss/release probe. No provider keys, network or live data.

## Limitations (honest)
- WAL handling: a DB with no `-wal`/`-shm`/`-journal` sidecars is opened `immutable=1` so SQLite cannot create sidecars owned by the operator user (which could break the service user). If a writer starts between that check and the read, the snapshot could be inconsistent. If sidecars exist it uses `mode=ro` and a WAL reader may touch the `-shm` mtime (contents unchanged); the test excludes only that mtime.
- The fixture BUY carries no `EXECUTION_UNVERIFIED` label (synthetic engine path); the report shows `execution_label: null` rather than inventing one. Quote-execution fills that carry the label will show it.
- Positions report cost basis (`initial_cost_sol`, `cost_left_sol`), not a separate entry price; entry time is `opened_at`.
- `ss`/`systemctl` output parsing is tested only against fakes; real formats on the VPS are unverified.
- Config comparison is on parsed JSON and canonical digest; it does not re-run `load_config` validation, to avoid temp-file writes.
