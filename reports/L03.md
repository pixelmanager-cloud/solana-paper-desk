## Intake rules
- Discovery is opened read-only (`mode=ro`; `immutable=1` only for a quiet WAL file). The module has no write path.
- Frames are visited in `seq` order after the cursor.
  - A frame younger than `min_age_seconds` (default 300) stops the scan and the cursor stays before it, so it is picked up on a later scan.
  - A frame older than `max_age_seconds` (default 7200) is counted and skipped.
  - A frame whose bytes do not match its stored hash is counted as `altered` and never used. The cursor moves past it.
- Hint selection is the same rule the desk dispatcher uses, reimplemented without the dispatcher's gate imports:
  - `desk.decode.decode`;
  - exactly one `migrate` / `migrate_v2` identified instruction;
  - exactly one decoded `CompletePumpAmmMigrationEvent` as its depth-2 child;
  - the pool must equal the canonical PumpSwap pool derived from the mint.
- Garbage, no-op, ambiguous and non-SOL-quote frames are counted in `stats`, never raised. One candidate per mint per batch.

## Screening: checks, one candidate, no exceptions
- **Age and binding** are checked first, with no provider spend: `TOO_YOUNG`, `TOO_OLD`, `POOL_BINDING_INVALID`, `CANDIDATE_ADDRESS_INVALID`.
- **Provider calls** (3, plus 1 for holders):
  1. `kraken.sol_usd()`, skipped if the caller passes a cached `sol_usd`.
  2. `helius.get_multiple_accounts([mint, pool])`.
  3. `helius.get_multiple_accounts([base_vault, quote_vault, lp_mint])`.
  4. `helius.rpc('getTokenLargestAccounts', [mint])`, one call, only if every earlier check passed.
- **Mint** goes through `desk.security.mint_policy`, which gives the mint/freeze-authority, zero-supply, layout, program and Token-2022 profile-2 extension rules.
- **Pool** goes through `desk.pools.parse_pool`, plus:
  - the PDA and bump;
  - base mint = candidate, quote = SOL;
  - canonical creator, index 0, LP-mint PDA;
  - rejection of mayhem, cashback, holder-reward, mutable and overridden creator fee, and unknown layout;
  - overlap checks on the account identities.
- **Vaults**:
  - ATA derivation per owning token program;
  - `desk.security.holding_policy` (delegate, frozen, close authority, identity);
  - base-vault program equal to the mint's program;
  - quote vault on the legacy program.
- **LP mint**: supply must be 0, authority must be the pool, no freeze authority.
- **Snapshot slots**: the two snapshots must be within 16 slots.
- **Market**: SOL/USD times reserves.
  - Price follows the effective quote reserve (gross + virtual).
  - Liquidity is `2 × physical spendable SOL × SOL/USD`, so virtual reserves and accrued fees never count as liquidity.
  - Market cap is supply × spot price × SOL/USD.
  - Bounds come from `cfg` (defaults 50k–2M USD cap, 8k USD liquidity).
- **Holders**: top-1 and top-10 share of supply, excluding the pool's base vault; reject above `max_top10_pct` (default 60). A provider failure leaves `HOLDER_CONCENTRATION` UNKNOWN (recorded in `unknowns`) and does not reject. A malformed or over-supply answer rejects.
- **Isolation**:
  - Bad evidence gives reasons, never an exception.
  - A provider error carrying `code` and `transient` gives `Screen.error = {stage, code, transient}` and `passed=False`, and nothing more is spent on that candidate.
  - Any other exception becomes `SCREEN_INTERNAL_ERROR:<Type>` (no message text). `BaseException` (e.g. KeyboardInterrupt) is not swallowed.
- **Raw bytes** of every provider response are returned in `Screen.raw` for the store's observations.

## Deliberately NOT checked (vs the desk; also returned in `Screen.unknowns` on a pass)
Ownership and funding history; bundle detection; developer launch history; the global/dynamic fee-config accounts; sell-route simulation; flow/churn/momentum proxies; frame finality authentication. Also: Token-2022 vault/holder-account extension scans beyond what `holding_policy` and profile 2 already do.

## Remaining limitations
- The providers contract is assumed from the TASKS interface (`(parsed, raw_bytes, meta)`, `parsed` = RPC result object). L02 is not merged. If L02 returns a different `parsed` shape for `get_multiple_accounts` or `sol_usd`, only `_unwrap` and `_dec` need adjusting. `ProviderError` is detected by duck typing (`.code` str, `.transient` bool), not imported.
- The SOL/USD parse accepts a positive number/str/Decimal or a dict with `price`/`usd`/`sol_usd`/`value`.
- `max_top10_pct` default 60 is my choice, not a desk value. The lean strategy config (L04) should own it. `screen` reads config keys from a flat mapping or object attributes.
- `top10` is computed from `getTokenLargestAccounts` (the 20 largest accounts), so it is a lower bound on true concentration, and accounts rather than wallets.
- The snapshot is two RPC calls, not one atomic read; the slot-drift check bounds it (16 slots) but does not eliminate it.
- Liquidity counts only the SOL side; there is no price-impact or exit-quote check. That belongs to the strategy via the Jupiter quote.
