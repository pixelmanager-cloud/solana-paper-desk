## Required end-to-end test
`tests/test_ops_e2e_deploy.py` parses the fenced `$PY -m tools.ops.*` commands out of `docs/ops/RUNBOOK.md` (variables block included),
rewrites production paths to a temp tree once, and runs: stop writers -> archive backup (+verify) -> mark read-only -> `fresh_start
plan/apply` -> `render-units`/`render-dropins` -> install -> `cutover` dry run + `--apply` (fake systemctl; entry/monitor OFF and disabled)
-> healthcheck -> latch install -> read-only `entry_latch` -> entry enable -> `rollback --stop --disable` (+ a second rollback no-op).
Asserts: every command exits 0 (healthcheck: exactly CRITICAL `discovery_frames`+`backup` right after cutover, only `discovery_frames` after the
fresh backup unit's real command ran); started == intended set, enabled only after all starts, never entry/monitor timers; per unit the
effective ExecStart/Environment/WorkingDirectory/ConditionPathExists/TimeoutStartSec equal the manifest (independent mini systemd model);
no unit file or drop-in references the archived root except the shared pacing/discovery inputs and the pacing directory; no off-loopback bind;
rollback leaves no marked drop-in and no enabled unit. Sandbox-only adaptations are in `adapt()` (`--backup-dir`, the service user, cutover
`--unit-dir/--release-root/--journal`, `healthcheck --no-systemd`).

## Limitations (honest)
- Nothing here ran under a real systemd: `systemd-analyze verify` and a real `daemon-reload` on the VPS are still required.
- Steps for T02/T05/T06 (`status`, `preflight_dryrun`, `verify_cycle`) are prose in the RUNBOOK because those tools are not in this tree; the e2e cannot check their flags.
- The rotate procedure is documented but not exercised by the e2e (rotation itself is covered by `test_ops_fresh_start*`).
- `NRestarts` is cumulative: a unit that crashed repeatedly and then restarted cleanly reads OK until its next non-zero exit (item 13).
- The e2e's healthcheck run uses `--no-systemd`; unit-state checks are covered by `test_ops_healthcheck`.
- Item 16 as above. Unit `ReadWritePaths` are additive, so a stock base unit's wider paths would remain; the RUNBOOK installs the rendered set.

## For the coordinator
- New CLI surface: `fresh_start render-units --root R --out DIR --release-dir REL [--state-dir]`; `cutover cutover --enable --allow-monitor --allow-held-blocker`; `cutover rollback --disable`; `notify alert|daily --interval N`.
- `apply` now needs the backup dir's parent to exist (`/var/backups/solana-desk`, created by RUNBOOK step 3) and fails BEFORE creating anything otherwise.
- Cutover drop-ins for manifest-driven units now reset `Environment=`; anything the base unit set there is dropped, so the manifest must carry it (it does for the six known units).
- `notify` needs `ts` in the report and treats older than 2x interval as stale: if the healthcheck timer period differs from 300 s, pass `--interval` on `desk-healthcheck.service`'s `ExecStopPost` line.
- Decisions: held-blocker and monitor gates fail closed with explicit override flags; the latch drop-in is installed by the operator in step 9 (not by cutover) so entries cannot start before it exists; backup of the fresh set keeps `--expect-count 5` (an unexpected extra `*.sqlite` under the root makes the backup fail loudly).
