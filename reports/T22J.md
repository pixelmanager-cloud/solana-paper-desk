# T22J: last deploy blocker after merging T22I onto integration/r1

Branch `cloud/T22J`, BASE `origin/integration/r1` plus the reviewed T22I merge patch (commit `1cc0d8e`, applied cleanly with
`git apply --index`). Synthetic fixtures only. Nothing live was touched. No receipt module or receipt proof was edited.
`desk/provider_pacing.py` was not touched.

## Problem
In the merged tree the full suite, run in one process, gave 9 failures and 17 errors. T22H had narrowed
`HistoryProgress.advance` for every caller, and two T22H side effects broke reviewed modules.

## Changes (one commit each)
1. **(a) Strict classification is opt-in** (`db5a12a`).
   - `HistoryProgress.advance(key, rpc, *, strict=False)`. Only `desk/paper_cycle.py` `_history` passes `strict=True`; history_first's
     `prepare` calls `_history`, so it is strict too.
   - Every other pager caller keeps the exact pre-T22H contract: any `ValueError/KeyError/TypeError/IndexError/OSError` becomes the
     `RETRYABLE_ERROR` checkpoint, the reserved request stays spent, and a plain `snapshot` is returned. The callers are the ownership
     worker and acquisition, migration slot intake, and the paper history source's own callers. So
     `INTAKE_DEADLINE_BEFORE_TRANSPORT` is `RETRYABLE_ERROR` again.
   - The strict-probe tests (`test_history_laundering`, `test_t22i`) now pass `strict=True` explicitly.
   - `test_history_progress.test_failure_consumes_budget_and_keeps_checkpoint` is restored to its integration version (bare OSError
     gives RETRYABLE_ERROR on the shared pager). T22H's variant moved to `test_strict_failure_needs_a_transient_original`.
   - New `test_non_strict_callers_keep_the_shared_pager_contract` covers digest conflict, bare OSError, Key/Type/IndexError, TLS,
     `INTAKE_DEADLINE_BEFORE_TRANSPORT` and cached mismatch. Each must give RETRYABLE_ERROR with the charge kept.
2. **(b) Page-limit closure consistency** (`762eb91`).
   - The closure `_consistent` for `FEATURE_HISTORY_PAGE_LIMIT` now indexes each scan's attempt originals by charge with
     `paper_cycle_no_entry._index`, the same index publish uses; ambiguity is refused and becomes a hold. It counts only
     **successful** `getTransactionsForAddress` originals (`failure_code is None`, `http_status == 200`) inside
     `before+1..after`, and needs at least 8.
   - `close()` no longer relies on the caller's refs for this cause. history_first passes `()`, which is why the check always held.
     Instead it finds the pass's own attempt originals: pages written after the pass's intent page (`rowid >` the intent's rowid),
     bounded at 4096 per pass, never a whole-store scan. It binds them into the closure record, so every gate replays them in
     O(refs).
   - Result: a genuine history_first page limit closes FAILED_CHARGED. Seven pages, or charges with no originals, give INTEGRITY_HOLD.
   - The audit fixture `normal_blocker` now retains one successful original per charged history page, as the real transport does.
     Every assertion is unchanged. Two forged variants were added that must HOLD.
   - In `test_t22i`, the `ClosureConsistency.attempts` fixture records gained `failure_code: None, http_status: 200`, because genuine
     history originals are successful reads. A new test covers a failed 8th page, another scan's original, a ref beyond the charged
     range, and two originals for one charge: all HOLD.
3. **(c) The extra 5th attempt ref** (`516cdf0`).
   - Cause: T22H appended the failed read's `evidence_hash` to the shared `attempt_refs` list, which is also `result['attempt_refs']`.
     The HTTP 403 receipt fixture certifies exactly 4.
   - The original now goes to a closure-only `failure_refs` list, passed to `result_requires_hold`, `_close_unfinished` and
     `_close_failed`. The published result and `certify_intrinsic` see the pre-T22H inventory again.
   - The laundering protection is kept: the closure record still binds the failed original, and `HISTORY_RECOVERY_REQUIRED` /
     `HTTP_REJECTED` close only when that original proves the failure transient. The http403 proof does not count closure records.
4. **(d) Hold-file fallback gap** (`d7ecfcd`).
   - When both dispatch-hold files fail, `_hold_dispatch` also appends a `paper_dispatch_refusal_v1` line to the dispatcher's existing
     lock file `<journal>.dispatcher.lock` (`O_APPEND|O_NOFOLLOW`, fsync). That file already exists, so the write needs no new
     directory entry.
   - Every later process reads it at the start of `_dispatch` and raises `DispatchHoldFailed`, failing closed across ticks.
     `_held()` treats it as a hold, so recovery never abandons the intent.
   - A malformed, oversized or unreadable record fails closed (`DISPATCH_REFUSAL_RECORD_unreadable`).
   - If even that write fails, only the in-process refusal and the stderr reason remain (T22I behaviour), and stderr says so.
   - Clearing a refusal is a deliberate operator action: truncate the lock file while no dispatcher runs. The journal schema is
     validated exactly (`_read_journal`), so a journal row was not an option without a schema change.
   - Tests: the refusal survives a new process (in-process state cleared) and recovery past 900 s; the all-three-fail case;
     a malformed record.
5. **Probe table** (`82d1d0c`, `tests/test_t22j_probes.py`). The table runs through the REAL `run_once` (actual transport fixture)
   and the REAL history_first `prepare` (`tool.execute(live=True)` with a synthetic opener). Transport-level failures come from the
   opener. Source-level failures are raised inside the real `PaperHistorySource.__call__` after `advance` charged the reservation.
   HISTORY_BINDING_INVALID comes from the source's own binding check.

## Limitations
- The page-limit discovery reads at most 4096 pages written after the pass's intent page. A pass with more fails closed and holds.
  If the intent page already existed from an earlier identical save, its older rowid only widens the window.
- The dispatcher refusal record lives in the lock file. Deleting or recreating the lock file by hand drops it. If no durable write
  is possible at all (disk full), only the in-process refusal remains.
- Linux was not run here: the owner-proof lock table is injected in the tests, as before.
