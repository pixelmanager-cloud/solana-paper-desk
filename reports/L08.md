## What changed
- `lean/replay.py`
  - `load_paths(connection)` builds `Path`s from `observations` rows `path_start` / `path_mark` (contract in the module
    docstring). Corrupt marks (NaN/inf/<=0/bool/garbage price, garbage reserve), marks before start, duplicate timestamps,
    duplicate starts (first wins), marks without a start, <2 marks and bad decimals are skipped AND COUNTED, never repaired.
  - `replay(paths, strategy_cfg, replay_cfg)` merges all paths in time order into ONE portfolio and calls
    `lean.strategy.entry_decision` / `exit_decision` directly (two-step: pre-quote gate, then round-trip quotes; exit
    decision, then sell quote) and `lean.paper.buy/sell/apply_fill` for fills, so fee/slippage/accounting are the live ones
    (`paper_config()` derives them from the strategy config and refuses non-whole lamports/bps). Nothing is re-implemented.
  - `metrics()` — n, win rate, mean/median PnL per trade, max drawdown (SOL and fraction of start cash), profit factor
    (None + note when no losses). `OPEN_AT_END` positions are censored and excluded.
  - `calibrate(connection, cfg)` replays the config on the paths of tokens the live trader bought and compares ordered sell
    reasons; mismatches are listed (`EXIT_REASONS_DIFFER`, `NO_PATH`, `NOT_ENTERED_IN_REPLAY`), never hidden. A live position
    still open (typed `fills.qty_after > 0`) compares as a prefix.
- `lean/tune.py`
  - `tune(db, grid, split)` — grid keys are config names or `tp_ladder.<i>.<field>` (or a whole `tp_ladder`); product capped
    at 2000; invalid combinations (StrategyConfig refuses) are reported, value-duplicates of an existing config dropped; the
    base config is always evaluated first. Walk-forward split by path start time (older 70% in-sample, newest 30%
    out-of-sample, optional embargo), each side an independent portfolio from the same cash.
  - Ranking uses OUT-OF-SAMPLE total PnL only (then trade count); `INSUFFICIENT` below 50 OOS trades (`min_oos`) and always
    ranked after sufficient configs. In-sample numbers are reported, never ranked on.
  - Proposal `<proposals_dir>/<UTC ts>.json` (`status: PROPOSAL_NOT_APPLIED`, diff vs current strategy_version, full proposed
    config under a new `...-proposal-<ts>` version, evidence, warnings) only if a non-base, sufficient config beats the base
    OOS in total PnL AND has positive OOS mean, and the base itself is sufficient. Written O_EXCL; nothing reads it.
  - HTML (+JSON) report in the L06 style (same CSS and escaping helpers), CLI `python -m lean.tune --db --grid --out-dir
    [--proposals-dir] [--calibrate] --now <epoch>`. Opens the DB read-only (`open_ro`).

- Mutation evidence: 44 hand-written mutants across replay.py/tune.py (pool fee dropped on either leg, slippage/fee dropped
  from marks, entry timing, throttle, loss streak, day rollover, liquidation, realized accumulation, ladder stage/stop,
  peak/touched persistence, OPEN_AT_END value, second-decision quote check, loader first-wins/dup/corrupt handling,
  win-rate/median/drawdown/profit-factor, calibration leniency, ranking by in-sample or ignoring INSUFFICIENT, split
  off-by-one, proposal conditions, dedupe, overwrite, embargo boundary, immutable version, unescaped HTML): 42 killed,
  2 survive as EQUIVALENT mutants — (a) cooldown not recorded: a mint has exactly one path, so a cooldown can never
  block a later entry in a replay (kept for portfolio fidelity); (b) the `fraction >= 1` clamp: the strategy's sell qty is
  `min(qty, ...)`, so the fraction is already <= 1. 16 initial survivors were closed with oracle tests (independent
  constant-product/haircut arithmetic for fills and a bisected stop-boundary price), liquidation, touched/peak
  persistence, stuck-position, duplicate-mint, ranking and proposal scenarios.
- Calibration: `CalibrationTests` replays the default `lean-1` on paths of tokens "traded live" (events + typed fills in a
  real `Store`) and requires identical ordered exit reasons; a deliberate mismatch is reported with the reasons on both sides.
- No look-ahead: a test replaces the future of a path (crash / pump / truncated) and requires the identical trade.

## Remaining limitations (honest)
- Quotes are SYNTHESISED from the recorded spot price + SOL reserve (constant product, `pool_fee_bps` default 30, an
  assumption). Real Jupiter routes (multi-hop, different impact, creator fees) can differ. Calibration against live fills
  is the check; with real data it is the first thing to look at. `liquidity_sol` is assumed to be the SOL-side reserve; if
  L07 stores total (2x) liquidity, impact is understated.
- Entry at the first mark >= start (+`entry_delay_s`, default 0) is optimistic versus live latency; marks are ~15 s apart so
  stops can only fire at recorded marks (live checks every <=10 s). Gaps in a path are not filled.
- Screen features are taken once from `path_start` and kept static; the live trader may have seen different values.
- Ranking N configs on one OOS set is selection-biased (stated in every report). A proposal is a hypothesis for a forward
  paper run under a new strategy_version, not proof. Walk-forward uses a single split, not rolling folds.
- Dependencies not yet on integration/r1: L07 (`path_start`/`path_mark` writer) and L05 (writes `events kind='fill'` with
  `reason`). The loader/calibrator follow the contract in the docstrings; if L07/L05 use other field names, only
  `load_paths`/`live_sells` need adjusting.
- Dead-ish state kept deliberately: cooldowns (see equivalent mutant).
