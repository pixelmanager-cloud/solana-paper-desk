## Findings → changes
1. **MFE/MAE.** Rebuilt from journaled held `market` events (constant-product ledgers): for every event of the trade's mint with `opened_event_seq < seq <= closing_event_seq`, route available and `ts - price_at <= price_ttl`, the model mark `max(0, swap_quote(e, remaining_qty, 'sell', cfg) - fixed_fee)` is divided by the remaining cost (qty and cost shrink after partial sells, using sells that happened on earlier events). MFE = max ratio − 1, MAE = min ratio − 1. Per-trade values appear in `trades[]`, aggregates in `mfe_mae` (`mean_mfe`, `max_mfe`, `mean_mae`, `min_mae`). Status is explicit and detected per ledger: `OK`, `UNAVAILABLE_QUOTE_MODE` (config `paper_quote_execution_version == 1`; marks come from quotes that are not persisted for held events), `NO_HELD_MARKS` (constant-product trade with no usable held event).
2. **Pooled ordering.** Trades are ordered by `(closed_at, ledger realpath, outcome seq)`; ledger members are sorted by path, so argument order cannot change any number (test compares the full JSON for `[a,b]` vs `[b,a]`). Pooled baseline is explicit: `equity_baseline_sol` = the shared initial equity and `pooled_equity_model = SEQUENTIAL_SINGLE_BASELINE` (one curve, not N portfolios). Differing initial equity inside one config hash is refused.
3. **One snapshot.** Fingerprint (event/outcome count+max seq, state, metadata) taken before validation, again inside the single read transaction that loads all data, and again after; any difference → `LEDGER_CHANGED_DURING_EVAL`.
4. **Holdout.** Split on ENTRY time (`split_basis: ENTRY_TIME`, with a `split_note`): train = entered before the cut (may close after it), holdout = entered at/after. Holdout drawdown starts from equity at the cut = initial + PnL of all trades closed before the cut (`start_equity_sol` shown per block); train starts from initial.
5. **Code versions.** Rows are keyed by (config_hash, implementation_hash). `--pool-implementations` merges them and adds a `POOLED_IMPLEMENTATIONS` warning (JSON `warnings` + stderr). `--single-experiment` still refuses only differing config hashes.
6. **Concurrency.** Known-answer test: buy A, hold A, buy B, hold A, sell B, sell A.

## Limitations / for the coordinator
- **Production ledgers are quote-mode, so MFE/MAE will report `UNAVAILABLE_QUOTE_MODE` for the real experiment.** Fixing that needs held-position quote valuations to be journaled (a `desk/` change; natural fit for T14/T16), not more report code.
- MFE/MAE are model marks, no `sell_simulation` cap, so MFE can be overstated; they are not executable prices (EXECUTION_UNVERIFIED).
- Pooled ledgers that overlap in time are replayed on one sequential curve; do not read the pooled drawdown as a portfolio drawdown.
- Exit reasons are journal declarations (the validator does not check them).
- Trade rows are capped at 500 per experiment (`trades_truncated`).
