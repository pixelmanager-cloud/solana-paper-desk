## Root causes (all found by reproducing, one by instrumenting the real runner)
1. **A single failure leaked a process-wide patch into ~480 later tests.** The first failing test was `reclaim_orphans` raising `PACING_CLOCK_INVALID` (T23H). It happened inside the fixture pattern `h = Fixture(); h.setUp(); self.addCleanup(h.doCleanups)` (94 sites): when `h.setUp()` raised, `doCleanups` was never registered, so patches started in `h.setUp()` — notably `patch('socket.socket', side_effect=AssertionError('synthetic sources only'))` in `test_paper_cycle` — stayed active for the rest of the process. That produced the 71 "synthetic sources only", the asyncio `_ssock` errors (the loop could not create its socketpair), the `'BLOCKED' != 'COMPLETE'` and the `PACING_DATABASE_INVALID` cascades.
2. **Clock handling on the read-first path** (`provider_pacing.reclaim_orphans`): a fixture/host clock behind `high_water` or not a usable number raised from a gate that never calls `acquire()`. It now returns `[]` and changes nothing (T23H's tests, now green; acquire still fails closed loudly).
3. **The module-level holder registry `_HELD`** (T23G) keyed by path string only: now keyed by `(path, st_dev, st_ino, provider)`, entries carry pid and a committed flag; stale entries (file gone, other inode, forked child) are purged and their descriptors closed; a committed ticket the database no longer records is dropped (inode numbers are reused at once on ext4 — this failed on the runner, not locally); a new grant displaces any leftover entry for the same database and provider *before* taking the lock (it is stale by construction: acquire only grants while `pending` is NULL).
4. **Owner proof for monitoring abandonment never worked on GitHub runners** (these were the "18 errors" of the T25F merge). Instrumented the runner (temporary workflow, removed): `_deleted_lock_holders` returned `None` because a same-user helper `(sd-pam)` has an unreadable `/proc/<pid>/fd`, so every orphan was permanently "owner unknown". New rule: an unreadable process blocks only if the kernel lock table shows it holding a flock AND it runs as the lock file's owner (uid from `/proc/<pid>/status`, readable without fd access). Root daemons with their own locks and lock-less helpers no longer block. Residual risk documented in the docstring (a process of another user holding our deleted lock inode).
5. `test_allowance_upgrade` already passes on current integration (no change needed); `test_monitoring_classification` on Linux passes with the owner-proof fix and its injectable lock table/process tree.
