# T05 — Dry-run preflight harness against store copies

Branch `cloud/T05`, BASE `r1-base` (c1e22c2). Files: `tools/ops/preflight_dryrun.py`, `tests/test_ops_preflight_dryrun.py`, this report. Nothing under `desk/` changed, so the runtime implementation hash is unchanged.

## What it does
`python -m tools.ops.preflight_dryrun --data DIR --ledger NAME --config PATH --release-dir DIR --workdir /tmp/x [--keep] [--taker --amount-raw --pool-fee-bps]` (store names default to the production layout; override with `--research-db/--evidence-db/--pacing-db/--discovery-db/--journal`).

1. Refuses to start if `HELIUS_API_KEY`, `JUPITER_API_KEY`, `KRAKEN_API_KEY`, `KRAKEN_API_SECRET` or `CREDENTIALS_DIRECTORY` is set; requires canonical `--data`, non-existent canonical `--workdir` (not nested with data), release/python not under data; refuses symlinked dirs, symlinked or hard-linked `*.sqlite`.
2. Copies every `*.sqlite` (recursive) with the sqlite backup API from `mode=ro` sources into a 0700/0600 workdir, plus the config.
3. Runs a child (`python -I -B`, cwd = release dir, whitelist env, TMPDIR in workdir, `DESK_PROVIDER_PACING_DB` = the copy) inside a private **mount namespace** (`unshare --mount`) where the copy dir is bind-mounted over `--data`. Reason: the evidence store binds absolute sibling paths (e.g. the monitoring budget row names the ledger and the gate opens it), so a plain copy at another path makes the gate read the LIVE ledger. With the bind mount the live files are not visible to the child at all. Without namespaces the tool refuses unless `--no-namespace` (then `isolation: NONE`, and the guard turns such live reads into `GUARD_VIOLATION`).
4. Child audit hook records and refuses: network (connect/sendto/getaddrinfo/bind…), process creation, sqlite connects and file writes/mutations outside the workdir/data root. Violations are recorded even if the release code swallows the exception → status `GUARD_VIOLATION`, exit 3.
5. Stages: `gate` (monitor `_context` + `terminal.gate`), `preflight` (`plan` + `_preflight`, plus comparison of the activated journal context with a fresh plan; only device/inode and the config copy's path are excluded), `scheduler` (`tools.paper_scheduler` mode `entry` forced to `--plan`, with a lease lock created in the copy dir).
6. JSON report: status PASS/BLOCKED/GUARD_VIOLATION/REFUSED, `blockers`, gate result and mode/positions, `pending_null_pass_ids` (read from the COPY, ≤256), `refusal_reason`, `context_mismatch` + `journal_context_diff`, copy hashes, timing (copy/child/per stage/total), live permission findings, live sidecars created, `live_sources_unchanged`. Exit 0 PASS, 2 BLOCKED, 3 otherwise. Workdir deleted unless `--keep`.
Live-side checks the copy would mask (forced 0600/0700): journal mode/parent mode, pacing exactly 0600, research dir not group/other writable, existing `paper-scheduler.lock` 0600 and owned by the user → blockers `LIVE_*`. A missing activated journal → `JOURNAL_ABSENT`; a missing stage → `<STAGE>_MISSING`.

## Limitations (honest)
- Needs Linux `unshare`+`mount` (root or user namespaces). Not available → refusal; tests that need it skip, guard tests still run.
- Reading a WAL-mode source with `mode=ro` can create/refresh `-wal`/`-shm` beside the live DB (SQLite behaviour, contents unchanged). The tool reports `live_sidecars_created`; it cannot avoid it. A quiesced source set is better.
- Stores are copied sequentially; if a live writer moves, the run is `BLOCKED` (`LIVE_SOURCE_CHANGED_DURING_RUN`) but cross-store consistency is otherwise not proven. Use against a quiesced or fresh store set.
- Device/inode identities of copies differ from live files, so identity drift cannot be reproduced; `_validate/_check_records` (unresolved intents, orphan results in the journal) is not run.
- The scheduler lock is only checked by lstat on the live file; the lease itself runs on a copy.
- Audit hook gaps (documented, matter only for hostile release code or `--no-namespace`): `os.open(..., dir_fd=)` write targets, `ATTACH DATABASE`, xattr/ctypes. Read-only opens outside the workdir are not blocked.
- Test run needs the repo's dependencies (`solders` via requirements-live); the dispatcher fixtures were run here only in the cloud worker venv.
- Cleanup relies on `rmtree`; `workdir_removed` is reported but SIGKILL leaves copies behind (use `--workdir` under a dedicated 0700 parent).
