Branch `cloud/C4`, BASE `origin/integration/r1` (8aee162). Owned files: `lean/backfill.py`, `tests/lean/test_backfill.py`,
`tests/lean/test_e2e_backfill.py`, plus the delimited, additive hooks the task allows in `lean/runner.py` and `lean/__main__.py`
and an OFF-by-default `backfill` block in `config/lean/lean.example.json`. `desk/**` untouched; none of M1/M2's files touched.

## What it does
`lean.backfill.BackfillSource` is one more `lean.sources.Source` (name `backfill`) polled by the existing `SourceSet`:
1. Every `interval_s` (default 120 s) on the LOW lane: `getSignaturesForAddress(<migration authority>, {until, limit, commitment: confirmed})`.
   The address is `discovery.continuous.AUTHORITY` (`39azUY…`), the one the discovery listener filters on; max `max_pages` pages per poll.
2. Oldest first. A signature younger than the screen's `min_age_seconds` stops the pass (same rule as the discovery scan).
   A failed transaction is counted and skipped.
3. A signature already in the discovery DB (`raw_events.source_id = 'confirmed:<signature>'`, the listener's own key) is counted
   `seen_by_feed` and is NEVER fetched. Every other one costs one `getTransaction(jsonParsed)` (max `max_tx_per_poll`).
4. The transaction is decoded by `lean.candidates._frame_candidate`, i.e. the SAME migration test as a discovery frame (exactly one
   decoded CompletePumpAmmMigrationEvent as the depth-2 child of `migrate`/`migrate_v2`, canonical pool, valid addresses), so the
   `Candidate` has exactly the discovery shape (test compares it field by field against `scan_new`'s). `migrated_at` is the on-chain
   `blockTime`.
5. The candidate row's meta carries `source='backfill'`, `latency_s` (now - blockTime) and `beyond_max_age`. A graduation whose latency
   exceeds `screen.max_age_seconds` is still handed to the runner: the screen's own `TOO_OLD` rejects it (no provider call), so it is
   recorded and never entered.
6. `health.json` → `sources.backfill`: per UTC day `authority_txs`, `seen_by_feed`, `missing_from_feed`, `missed_migrations`,
   `not_migration`, `failed_tx`, `fetch_failed`, `overflow_polls`, `beyond_max_age`, calls, a credit estimate and
   `gap_rate = missing_from_feed / authority_txs` (None when no signature that day).

Cursor: `SourceSet` persists the int cursor (highest processed SLOT) in `cursor-backfill.json`; the exact resume point (`until`) and
the counters live in `backfill-state.json`. A new `until` is committed only after the runner persisted a cursor at/after it, so a crash
between "batch returned" and "batch handled" re-fetches the overlap (the runner dedupes by mint) instead of losing it. The counted-signature
books are persisted too, so a restart does not double count an overlap. A corrupt state file is refused, never reset.

Config (`backfill`, strict at load, absent/null = OFF; the example config carries it with `enabled: false`): `interval_s` 120, `limit` 100,
`max_pages` 3, `max_tx_per_poll` 40, `max_attempts_per_signature` 5, `lookback_s` 21600 (first start / no `until`), `authority`,
`credits_per_signatures_call` 1, `credits_per_transaction` 1, `day_history` 14.

## Budget (estimate, the coordinator verifies against the plan)
- One `getSignaturesForAddress` per `interval_s` = 720/day at 120 s (more only when a poll pages), all on the shared LOW lane, shed = skip
  and retry in <= 15 s without spending a whole interval.
- One `getTransaction` per signature MISSING from the feed, <= 40 per poll. With a healthy feed this is ~0.
- Credit costs are config (`credits_per_*`, default 1 each); `health` multiplies them by the real call counts.

- `lean/runner.py`: `# --- C4 hook ---` in `_handle_candidate` merges `candidate.meta` into the candidate row meta (2 lines); `_sources_health()`

## Limitations (honest)
- Verified only against fakes built from the desk's synthetic migration fixture. The coordinator must check live: that
  `getSignaturesForAddress` on the authority returns the migrations the listener sees (the authority is "a dynamic discovery hint" per
  docs/operators/bounded-continuous-discovery.md and can rotate), that `jsonParsed` `getTransaction` decodes to the same candidate as the
  websocket frame (the decoder accepts both forms; a real capture was not available to me), and the real credit cost per call.
- `migrated_at` is the block time while a feed frame's is the local receive time, so a backfilled candidate looks a few seconds older.
- If more than `max_pages * limit` signatures arrive between two polls (a long outage with a busy authority) the oldest are NOT examined;
  this is counted (`overflow_polls`) and visible in health, never silent. Raise `max_pages` / lower `interval_s` if it shows up.
- Detection latency is at least `min_age_seconds` (300 s) by construction; backfilled graduations are older than feed ones when screened.
- The feed-gap rate is over authority signatures, not over migrations only (a feed-seen signature is not decoded); `missed_migrations` is
  the migration-specific count.
- Time-based: `lookback_s` bounds the first-start walk; a backlog older than that after a very long outage is not recovered.

## For the coordinator
- Enable by setting `"backfill": {"enabled": true}` (optionally tune `interval_s`/`max_pages`) in `lean.json`; nothing else changes. No new unit,
  no migration. State files appear in the lean state dir: `cursor-backfill.json`, `backfill-state.json` (do not delete one without the other).
- The LOW lane is shared with paths/features/etc.; backfill is shed first like any low-priority work.
- Commit trailer uses the session's model (Sonnet 5.5), not the Opus 5.5 string in WORKER_PROMPT.md.
