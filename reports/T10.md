## What changed
`tools/research/forward_eval.py` — `python -m tools.research.forward_eval --ledger L1 [--ledger L2 ...] [--holdout-from UTC|epoch] [--now N] [--resamples N] [--seed N] [--single-experiment]`.
- Every ledger is first replayed/validated by the existing `desk.experiment_report.experiment_report` (imported, not edited). Any `RecoveryRequired` → the whole run is REFUSED (exit 2), never a partial report.
- Closed trades are rebuilt from the `fill` outcomes (BUY opens; the trade closes when the sold quantity exhausts the position, same 1e-20 threshold as the engine). Trade return = summed realized PnL / (buy amount + buy fee).
- Rows are keyed by `config_hash` (ledger metadata); different hashes are never in one row. Same-hash ledgers are pooled into one row. The same ledger passed twice (same inode, including hardlinks) is refused; symlinked ledgers are refused. `--single-experiment` refuses a mix outright.
- Per block (`all`, plus `train`/`holdout` split by trade close time when `--holdout-from` is given): trades, wins/losses/flat, net PnL (SOL, after the recorded fees/slippage assumptions), mean/median return, mean/median hold, exit-reason breakdown (reason of the final sell) and count of partial TAKE_PROFIT fills, max drawdown of the closed-trade equity curve, seeded percentile bootstrap 95% CI of the mean return.
- Fewer than 30 closed trades → explicit `INSUFFICIENT_SAMPLE` warning in the JSON block and on stderr (also for an empty train/holdout side).
- Everything is labelled `EXECUTION_UNVERIFIED`, `paper_only: true`, `profitability_verdict: NOT_ASSESSED`; data provenance from the validator is passed through.
- No `desk/` file touched (runtime hash unchanged); no `__init__.py` added under `tools/research/`.

## Limitations (honest)
- **MFE/MAE are NOT produced.** The journal stores per-fill outcomes only, not a per-event held-mark series; reconstructing marks would need quote books that are not recorded for non-fill held events. The report states `mfe_mae.available=false` with the reason instead of inventing numbers. Closing this needs the held-mark series to be journaled (a `desk/` change, T14/T16 territory).
- The validator does not verify the `reason` string on sell outcomes (it replays quantities, costs, PnL, checkpoint), so exit-reason counts are journal declarations, not independently proven. PnL tampering is caught (test); reason tampering is not.
- Max drawdown is over closed-trade realized equity (ordered by close), not mark-to-market intra-trade; the engine's saved drawdown is not used.
- Opening a WAL-mode ledger `mode=ro` can make SQLite create `-shm`/`-wal` sidecars next to it (the validator already did this); the main db file bytes/mtime are unchanged (tested).
- Returns are per trade on entry cost (incl. fee); no compounding or time-weighted return, no multiple-comparison correction. n<30 results are not evidence.
- Pooling same-hash ledgers does not check that they cover disjoint time windows.
