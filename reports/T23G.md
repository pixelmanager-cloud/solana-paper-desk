## What changed
1. **(HIGH) Release only after a successful commit.** New `Pacer._commit_release`: `finish()` and `throttle()` COMMIT first,
   retrying a busy commit up to 6 times with growing backoff (0.05 s doubling to 0.5 s, via the injectable `sleep`) while the
   holder flock stays held; only then is the lock released. If the commit never succeeds the error (`PACING_DATABASE_BUSY`)
   propagates and the lock is KEPT until process exit, so a live owner is never reclaimed and a throttle's Retry-After is not lost
   (the row is simply still pending; the owner can finish later). Consequence handled: a new grantee that wins the slot in the
   instant between the previous owner's commit and its release now retries `flock` for up to 20 x 5 ms instead of failing with
   `PACING_HOLDER_LOCK_UNAVAILABLE`.
2. **(MED) Read before write.** `reclaim_orphans()` reads in a deferred transaction first (table present? any pending row
   older than max(60 s, 30 x cadence)?) and takes `BEGIN IMMEDIATE` only when one exists, re-proving inside the write
   transaction. Any `sqlite3.Error` (busy) returns `[]`; it never raises for contention (the clock-invalid error is unchanged).
3. **(MED) Validate at load.** `desk.model.validate_version_flags` runs inside `load_config`: `paper_exit_only_recovery_version`,
   `paper_entry_latch_version`, `paper_regime_version`, `paper_portfolio_risk_version`, `paper_watchlist_version` and
   `paper_concurrent_entries_version` must be `int` 1 when present (bool, "1", 1.0, 0, 2, lists refused), and the concurrency
   flag additionally needs paper mode and 2..8 `max_positions` (`paper_concurrency.selected`).
4. **(MED) Latch on every entry path.** The config key `paper_entry_latch_version: 1` selects the latch policy.
   `tools/paper_scheduler.py` entry mode now runs the T07 read-only `entry_latch.latch(..., apply=False)` BEFORE the other
   gates: `WOULD_PAUSE_ENTRY` (a persisted BUY whose latch is not applied) or any non-zero code refuses with
   `ENTRY_LATCH_REQUIRED`; any exception refuses with `ENTRY_LATCH_UNAVAILABLE` (0 requests, `entry_authorized: false`).
   An applied latch followed by a deliberate operator RESUME (`NOOP_ALREADY_LATCHED_ONCE`) is not undone. Without the key nothing
   changes. This covers manual or other invocations, not only the dispatcher's ExecStartPre drop-in.
5. **Example config.** `paper-kraken-fresh.example.json` sets `paper_exit_only_recovery_version: 1` and `paper_entry_latch_version: 1`
   (the latter is the key item 4 needs; the RUNBOOK already installs the latch drop-in for this experiment). Validated with the real loader.
6. **(LOW) Docs.** Module docstring: never delete a holder lock file (the owner proof is its inode); a forked child inherits the lock.

## Limitations
* The busy-commit retries use the Pacer's `sleep`; with a long-running reader the pass can still end in `PACING_DATABASE_BUSY` (by design: lock kept).
* Reading while the writer holds PENDING is impossible for other processes (SQLite); the retry window is therefore short (about 1 s total).
* `ENTRY_LATCH_REQUIRED` only exists when the config selects the latch; an experiment without the key keeps relying on the systemd drop-in.
* The scheduler check consults the ledger via `cycle._state` (config/runtime identity); a mismatch refuses (fail closed) rather than proceeding.
