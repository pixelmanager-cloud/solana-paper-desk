# T27 — Shadow strategy variants (parallel virtual A/B)

Branch `cloud/T27`, base `origin/cloud/T26` (e811bc3). Research only; no provider calls, keys, live stores or ledger; fixtures only. No file under `desk/` was edited.

## What changed and why
- `tools/research/shadow_strategies.py`: loads priced counterfactual paths (T26 store, `mode=ro`), expands a `shadow-grid-1` file (explicit variants + cross-product grid, validated against `config/paper.json`), synthesizes strict-mode market events from the sampled vault reserves and calls the REAL `desk.engine.transition` for every decision (entry gates, sizing, stop, ladder, trailing, time-stop, max-hold, costs). Nothing is reimplemented.
- Strictly causal, bracketed paths (see `docs/research/SHADOW.md`): `samples` and `carry` models plus an analytic best case for STOP/TRAILING_STOP fills. All statistics are `[worst, best]` intervals; ambiguous trades are counted.
- Leaderboard per variant with train/holdout split by migration time, bootstrap CI with Bonferroni alpha, holdout-only ranking, variants-tried disclosure. Everything labelled `SIMULATED_SHADOW`.
- `config/experiments/shadow/{live-baseline,exit-grid,window-grid}.json`, `docs/research/SHADOW.md`, `tests/test_shadow_strategies.py` (17 tests).
- Design correction during development: a first draft interpolated reserves between samples while holding, which used the NEXT sample in a present decision (look-ahead). It was replaced by the causal model above before the first commit; test `test_no_decision_uses_a_sample_taken_after_it` spies on every engine call and mutation M2 proves it catches the reintroduction.

## Tests
`python -m unittest tests.test_shadow_strategies` -> 17 OK (about 0.5 s); with T26: `python -m unittest tests.test_shadow_strategies tests.test_counterfactual` -> 36 OK.
Fail-first: the tool is new, so on BASE every test fails at import (nothing to run).
Mutation evidence (each applied, tests red, reverted via git): M1 carry deadline events never fed -> time-stop test; M2 timer event uses the next sample (look-ahead) -> no-look-ahead spy test; M3 stop best-case bound removed -> bracket test; M4 pool death treated as a normal liquidation -> pool-death test; M5 overrides ignored -> 3 tests; M6 holdout leaks train rows -> run test; M7 no Bonferroni -> 2 tests.
Covered: known-answer paths (stop, time-stop, profitable path to LIQUIDATE, pool death, engine reject reasons, age window moves entry), engine parity (manual `engine.transition` replay equals the tool for every path; variant equal to live config reproduces; a changed stop changes the outcome), no look-ahead (spy on every event + corrupting the future leaves earlier decisions identical), timer events never open positions, summary/drawdown/win-rate known answers, deterministic bootstrap, holdout-only ranking and counts, grid validation (unknown key, wrong type, duplicate name, empty), read-only loader that skips dead/missed/failed samples, static check that the module has no network/ledger/write path, CLI exit codes.

## Remaining limitations (honest)
- Price paths contain no signal features, so by default all candidates get the same neutral features; variants compare structure, not signal quality (`--features` accepts real evidence per mint, untested against production data).
- The take-profit ladder is hard-coded in `desk.engine` and cannot be a grid axis without editing `desk/` (out of scope).
- With 6 samples per candidate the intervals are wide by construction; a tight interval needs finer sampling (T26 horizons) or a different data source.
- Isolated per-candidate states ignore portfolio limits; market cap/liquidity depend on explicit assumptions (`sol_usd`, supply, decimals, pool fee).
- T14 latency drift is not applied; no data on this base.
- Runtime is dominated by `engine.transition` (roughly 1 ms per event per model); a few hundred candidates times a few dozen variants is seconds to minutes.
