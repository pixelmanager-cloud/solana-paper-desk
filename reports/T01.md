## What changed and why
New `desk/paper_cycle_no_entry.py` (typed outcome `paper_cycle_no_entry_v1`, table `paper_cycle_no_entry`, trigger-guarded: unique per pass and scan, no UPDATE/DELETE, 8192 cap).
- `desk/paper_cycle.py::run_once`: for a lone, control-free, non-monitoring candidate whose charged pass ends in an allow-listed blocker, `publish()` writes the record and fills `paper_observation_passes.outcome_hash` in ONE evidence transaction (template: `history_preparation_rejection`). Any failure to prove leaves the NULL latch (fail closed). The returned dict is unchanged (`evidence_hash` = original result hash) so the dispatcher journal grammar still verifies.
- `desk/paper_terminal_reconciliation._gate`: calls the new `gate()` after the preparation-rejection gate. `gate()` re-proves every record on each call and keeps a two-way inventory (non-NULL passes of this kind == table rows), so dropping/editing the table cannot erase a retirement and a forged row cannot clear a pass. A rejected scan returns `REJECTED_SCAN_RETIRED` (never retried); charges stay charged.
- Proof per record: pass/intent binding; single-candidate intent; result shape (BLOCKED, one blocker, no events/outcomes, monitoring 0, budget); admission before/after consistent with `charged`; complete, unique, HTTP-200 `paper_read_attempt_v1` inventory for every charged index and result refs ⊆ inventory; per-code necessary conditions (`_consistent`); live admission unchanged; ledger bound by event/outcome counts plus a bounded (first 256 rows) immutable prefix hash (counts may grow, so later legitimate ledger events never resurrect the pass).
- No change to `paper_history_preparation.py`, `paper_observe_cli.py` (see limitations), nor to any existing receipt kind or policy file.

## Remaining limitations (honest)
- Only `run_once` (the entry path) is covered. `paper_observe_cli.observe` (operator diagnostic) and `paper_history_preparation.prepare` still leave a charged non-preparation-rejection stop NULL; prepare's `FEATURE_HISTORY_PAGE_LIMIT`/history `CycleBlocked` codes are not yet typed. Not on the unattended entry path; follow-up task suggested.
- Blocker codes with only self-asserted evidence (`MARKET_PRODUCER_BLOCKED`, `RETAINED_MIGRATION_WITNESS_REQUIRED`) are proven structurally (diagnostics retained, charges/attempt inventory, ledger untouched) but the gate does not re-run the market producer. Budget and page-limit codes have unit-level consistency tests but no end-to-end positive fixture.
- A hostile writer who also rewrites pass, receipt, result and attempt pages consistently is outside the threat model (same as the existing receipts).
- Ledger anchor covers counts + first 256 rows only; later rows are guarded by the ledger's own checkpoint validation.
- Retrospective receipt (optional item 2) not implemented as a CLI; `publish()` could be called for a legacy NULL pass but no entry point is wired.
