asks for an own e2e scenario). `desk/**` and `lean/runner.py` untouched.

## What changed
1. **Entry timing (the task).** `replay.EntryTiming` + `ReplayConfig.entry_timing`:
   `first_mark` (the L08 behaviour, default), `pullback` (first mark at least X% below the highest mark since the path start;
   the first mark is the initial high; the threshold is inclusive), `momentum` (first mark where the minute samples t, t-60 s, ...,
   t-N*60 s are strictly increasing, which needs N minutes of history). Causal (only past marks), `max_wait_s` (default 3600 s)
   and path end drop a never-triggered candidate as `ENTRY_TIMING_NO_TRIGGER`; a triggered candidate is considered once, like live.
2. **Grid.** `tune` grid keys `replay.entry_timing` (`'first_mark'`, `{'kind':'pullback','pullback_pct':'0.1'}`,
   `{'kind':'momentum','momentum_minutes':3}`) and `replay.entry_delay_s` expand alongside strategy keys. Every variant is replayed
   walk-forward (older 70% / newest 30%) and ranked out-of-sample only, `INSUFFICIENT` below `min_oos`. Invalid specs are reported,
   value-duplicates dropped. A proposal that wins by timing alone has an empty `diff`, lists `replay_overrides` and
   `requires_runner_change` (entry timing is not a runner setting yet), `PROPOSAL_NOT_APPLIED` as before.
3. **Conflicts against L09's real modules (found while resolving, fixed in my own L08 code).**
   - L09's `strategy.py` moved to raw-integer token units, exact sell-leg size and a required `mark_at`; replay now converts only
     through `lean.adapters` (`roundtrip`, `strategy_quote`, `strategy_position`, `sell_qty_raw`, `paper_config`, `entry_features`)
     and sells with `paper.sell(qty_raw=...)`.
   - L07's real record layout differs from what L08 assumed: features are in `path_start.raw`, `liquidity_sol` is TWO-SIDED (replay
     uses half as the SOL reserve), marks carry `status`. `ACCOUNT_MISSING` / `EMPTY_POOL` are DEAD marks (rug signal): no entry or
     exit at them, an open position is valued 0, and a position still in a dead pool when the path ends is closed as
     `RUG_WRITEOFF` (whole remaining cost lost) so rugs are never censored out of the statistics. `MALFORMED` / unknown statuses are skipped and counted.
   - L09's live trail: exit reasons live in `decisions(kind='exit', action='SELL')`, buys in typed `fills`, initial cash in `meta`.
     `calibrate` / `tune` read those (and default the replay's starting cash to the live store's).

## Limitations (honest)
- Quotes are still synthesised (constant product, `--pool-fee-bps`, default 30; fakeworld uses 25). The e2e agreement is on a
  fake world whose pools are exactly constant-product, so it proves wiring and semantics, not real-route fidelity.
- Entry timing is replayed only; the runner has no such setting. Entry delay counts from the path start and the trigger must hold at
  that mark. Screen features (market cap / liquidity band) stay at their start values.
- Walk-forward is a single split; N configs ranked on one OOS set is selection-biased (stated in every report).
- Marks every 15 s: stops can only fire at recorded marks (live checks every <= 10 s); gaps are not filled.
- A write-off assumes nothing was recoverable; a partial exit before the pool died keeps its realized PnL.
