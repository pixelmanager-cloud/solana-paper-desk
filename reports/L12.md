# L12 — Entry feature capture

Branch `cloud/L12`, base `origin/cloud/L09` (the integrated lean desk).

## What
`lean/features.py` writes ONE `observations(kind='features')` row per screened candidate, entered or not (`code_version` and
`strategy_version` on the row). Payload (canonical JSON): `{features_version: 1, mint, entered, not_entered_reason, screen_passed, fields, missing}`.
Schema invariant (tested for every row): `fields[name] is None  <=>  name in missing`, and every reason is non-empty. A missing field is never an error.

Free, from what the screen already loaded: market cap, liquidity, price, SOL/USD, age at screen, top-10 / top-1 holder share, token program,
mint/freeze authority state (False/False when the mint stage passed, True when the screen reasons say so, else missing), the Token-2022 extension
list and the transfer-fee bps (parsed from the mint account bytes the screen retained; legacy mints give `[]`).

At most 3 extra Helius calls per candidate, on a LOW-PRIORITY lane (`LowPriorityBucket`, own non-sleeping bucket, default 2 req/s, all-or-nothing
for the 3 calls; a candidate that finds it empty gets `LOW_PRIORITY_SHED` and still its free fields):
1. `getSignaturesForAddress(mint, 1000)`: creation time (oldest signature, only when the history is complete), `seconds_creation_to_graduation`,
   successful tx count in the first 10 minutes;
2. `getTransaction(oldest)`: `creator_wallet` (fee payer of the mint's first transaction; NOT a proven creator);
3. `getTokenAccountsByOwner(creator, mint)`: `dev_holding_pct` of supply.
Hazard rejects keep their free row and spend nothing (`NOT_ENRICHED_HAZARD_REJECT`); soft rejects (market cap, liquidity) are enriched.

The enrichment runs on its own thread (`FeatureRecorder.run`, bounded queue of 500, drains on stop). `submit` never blocks and never raises; a full
queue writes the free row at once (`QUEUE_FULL`).

Runner hooks (`lean/runner.py`, +29/-2, outside OWNS, minimal): `features_recorder=None`; `_handle_candidate` now splits at the end of the screen into
`_after_screen` (the old body, unchanged except for recording `track['entered']` / `track['reason']` at its exits) under a `try/finally` that calls
`_track_features` (exception-safe). A transient provider error that will be retried writes no row (the retry does); any other error leaves the row with
`not_entered_reason='ABORTED_BY_ERROR'`. A `features` thread is started in `run()`.

Report helper: `feature_outcome_table(rows, realized, buckets=4, min_total=30, min_bucket=10)` plus `feature_rows(store)` and `outcomes(store)`: per numeric
feature, rank-quantile buckets x (n, win rate, mean pnl in lamports), with `insufficient` per feature and per bucket. Only entered AND closed positions have an
outcome (not-entered candidates need L07 paths).

## Not available inside the budget (recorded as missing with the reason)
* `holder_count` (`REQUIRES_FULL_HOLDER_SCAN`): needs a full holder scan.
* buys / sells / unique buyers / buy volume in the first N minutes (`NEEDS_PARSED_TRANSACTIONS_OVER_BUDGET`): needs parsed transactions; L13 owns it. I only give the successful transaction count.
* twitter / telegram / website (`METADATA_RPC_NOT_ALLOWED`): needs DAS `getAsset` or the off-chain JSON; `lean.providers.READ_ONLY_RPC` does not allow `getAsset`.
* The top-10 share excludes the pool vault only (the screen's definition), not the burn address.

## Limitations
* Never run against live RPC; request shapes follow the public Solana JSON-RPC (jsonParsed transaction, token accounts by owner). The scripted Helius mirrors them.
* `creator_wallet` is the first-transaction fee payer, a heuristic. A token with 1000+ signatures at screen time has no creation data (`HISTORY_TRUNCATED`).
* Rows are not written for a candidate whose screen failed with a typed provider error and is never retried successfully (no screen result exists).
* Token-2022 transfer fee bps reads the NEWER fee entry only.
