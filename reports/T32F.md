## Items
1. **Drop-in archive.** `cutover archive-dropins [--name systemd-archive-<label>] [--fresh-units DIR] [--archive-root]`
   MOVES every `desk-*.d` directory and the desk unit files the rendered fresh set replaces into a new `0700` archive with
   `manifest.json` (type, mode, uid/gid, sha256, symlink target per entry; sha256 of each rendered fresh unit). The copy is
   verified against the manifest before any original is removed; refuses an existing archive, an active unit, hard links,
   special files; dry run by default. `cutover rollback --restore-archive DIR` first VALIDATES (archive intact; no hand-written
   file in a drop-in directory; rendered units unchanged since installation; nothing is touched on refusal), then removes the managed
   drop-ins and the rendered units/empty directories this flow created, copies the archive back and verifies byte-for-byte
   (type, mode, sha256). The e2e seeds the exact production tree (all unit/drop-in names from the task, plus ExecStart reset,
   Environment, WorkingDirectory, ConditionPathExists overrides, modes 0644/0640, a stray `.bak`), proves that after cutover
   the fake `systemctl cat` shows only our files (all with our markers; no Codex-era Environment/ExecStart), and that rollback
   restores the original tree byte-for-byte (`tree(unit_dir) == snapshot`), including a harmless second rollback.
2. **Inventory.** `cutover inventory --out DIR` (RUNBOOK step 2, before any change) saves an `ls -la`-style listing of every
   `desk-*` entry INCLUDING `*.d` directories, `systemctl cat` of each unit, and sha256s, to a new `0700` directory. The old
   `cp -a` backup (which skipped `*.d`) is gone from the RUNBOOK; the archive replaces it.
3. **Old units.** Step 2 `systemctl disable`s every old unit (including `desk-discovery.*`, `desk-recorder`, old monitor/entry
   timers) after stopping them, then `is-enabled` must say disabled (the e2e executes both through the fake systemctl). Units reused by
   the fresh set are enabled again only by `cutover --enable` after they are healthy. `desk-discovery.service` keeps its unit file
   (not replaced), its stack is archived too.
4. **Archive quiesce.** `--require-quiesced` now includes `desk-dashboard.service`; continuous discovery was already in it.
   Discovery restarts in step 7b against the SHARED discovery DB (the DECISION keeps that input shared).
5. **Rotate** disables the entry timer first and stops the watchdog units, so "a reboot fails closed" is true.
6. **Dashboard pacing.** `DESK_PROVIDER_PACING_DB` is in the manifest's dashboard environment (`fresh_start.py`) and the unit
   template, and the pacing DIRECTORY is writable for it (rollback journal). The e2e asserts it.
7. **Run as the service user.** Every read-only tool in the RUNBOOK is prefixed `runuser -u solana-desk --` (healthcheck, status,
   verify_cycle snapshot/compare, entry_latch); the e2e strips the prefix, records it, and a doc-wide test fails if any `$PY -m tools.ops.<readonly>`
   lacks it. Snapshots go to the service-owned state dir instead of `/root`.
8. **Archived store permissions.** New `cutover seal-archive --root OLD --shared-path PACING --shared-path DISCOVERY`: files
   `root:root 0444`, directories `root:root 0555`; the two directories that hold a shared database (old root, `discovery/`)
   are `root:solana-desk 1775` (group write lets the service create the rollback journal, the sticky bit stops it deleting or
   renaming any root-owned archived file); the shared databases are untouched; symlinks/hard links/special files abort.
   **Decision: the shared pacing DB is NOT moved** to `/var/lib/solana-desk-shared/`: its migration receipt binds the
   path (see the e2e fixture comment), so a move would invalidate the pacer. The sticky model gives the same protection in place.
   Health/notify units mount the archived root `ReadOnlyPaths=` (new `<ARCHIVED_ROOT>` placeholder, `render-units --archived-root`);
   the healthcheck no longer needs the pacing directory writable (rollback-journal DBs need no write for a read-only open).
   The e2e checks modes, the fake chown layer records `root:root` / `root:solana-desk`, and that shared files were not touched.
9. **Healthcheck watchdog.** New `desk-notify-watchdog.timer/.service` (5-min period, own state file) runs `notify alert` on
   `health.json`; `notify.check_freshness` already turns a report older than 2 x 300 s into CRITICAL, so a dead healthcheck timer
   is reported within 600 + 300 = 900 s (15 min). A test asserts that arithmetic from the unit files and the constant. It is in
   the cutover `--units/--enable`, rollback and rotate lists.
10. **Rollback docs.** The RUNBOOK and `OPERATIONS_24x7.md` state that rendered units stay installed after a plain rollback and
    that `--restore-archive` removes them; the command's JSON note says so.
11. **Unit check.** RUNBOOK step 7a runs `systemd-analyze verify` on every installed desk unit. The e2e cannot run it (no
    systemd in the sandbox; it asserts the files exist) but checks the backup unit's quoting itself: `%` always doubled, `$` only as
    `$$`, and the `python -c` drop-in command, unquoted with the repo's systemd word parser, is valid Python equal to the
    manifest argv. (The base unit's `sh -c` line with `$$(date ...)` is also checked.)
12. **E2E realism.** `mkdir`, `cp` and `find ... chmod` no-ops are removed (the commands became real tool calls); unhandled shell
    commands fail the test; `is-active`/`is-enabled` are asserted, `disable`/`daemon-reload`/`install` act on the sandbox; `chown`
    is a recording fake (`Ops.chown`); the whole flow runs stage-less (stage has its own tests) through archive, seal, cutover,
    health, latch, entry enable and rollback with the seeded production tree. `cd`, `export`, `sha256sum` (tarball absent) and `ss`
    stay no-ops. The **rotate** section is not executed by the harness (it was not before either); only its text is updated.

## Limitations
* Not run on a real systemd/VPS: `systemd-analyze verify`, real `chown`, ordering of drop-ins with the real manager are untested;
  the fake `systemctl cat` lists the base unit then drop-ins lexically.
* `ReadOnlyPaths=<ARCHIVED_ROOT>` on the health/notify units relies on systemd's mount namespace: the fresh root is a separate
  tree (writable where listed). I did not add it to the scheduler units, which must write the pacing directory (same path).
* The sticky/group model assumes the service user is in group `solana-desk` and no process runs as that user with root-owned file
  deletion rights; a root-owned directory entry cannot be removed by it, but it can still append journals next to shared DBs.
* `archive-dropins` archives units named in `--fresh-units` and all `desk-*.d`; old units outside the fresh set keep their unit
  file (stack archived) and are disabled, not removed.
* The watchdog has no independent proof it fires on a real host; it reuses `notify`'s tested freshness rule.
* `OnFailure=` was not used; the separate timer is the mechanism.
