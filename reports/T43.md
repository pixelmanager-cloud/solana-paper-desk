## What changed
1. **Discovery is read from a persisted cursor (MED).** The capped `since=0` rescan (oldest 50k frames, `stats['truncated']` ignored) is gone for normal runs. `discovery.raw_events` is read in seq-ordered pages (`PAGE_ROWS`, at most `MAX_PAGES` per run) from an `ingest_cursors` position, with the same anchor rule as the other sources (anchor = first row's `seq/payload_hash`; a different anchor or a cursor past the end re-reads from zero and counts `CURSOR_RESET_SOURCE_CHANGED`; old rows are never deleted). Hints go to the carry (they still merge into a ledger page that shares `(mint, as_of)`); the cursor is committed in the same transaction as the leftovers in `flush_carry`, so a crash before that re-reads frames (idempotent) rather than skipping them. If the page bound stops a run with frames left, `PAGE_BOUND_HIT:discovery.raw_events` **and `DISCOVERY_TRUNCATED`** are recorded and the next run continues. A windowed run (`--since/--until`) still reads its received_at window whole, now passes an explicit limit (`DISCOVERY_WINDOW_LIMIT`) and records `DISCOVERY_TRUNCATED` when `stats['truncated']` (previously ignored); it neither reads nor writes cursors.
2. **False page bound (LOW).** `Paging.exhausted(source, more)`: the bound is HIT only when it stops a run that still had rows (`more()`); a last full page that drained the source exactly is not a bound. Applied to ledger events, counterfactual samples, decisions and the new discovery/journal reads.
3. **Dispatch journal is incremental (LOW).** `journal.intents` and `journal.results` have their own rowid cursors (a result is written after its intent). Only new rows are read; a result that arrives for an intent stored earlier is offered alone (its intent is not re-offered, so no `duplicate` noise); a result with no intent is counted `JOURNAL_RESULT_WITHOUT_INTENT`. Same unreadable-row rules as `funnel_report.read_journal`. Windowed runs read the journal whole as before.
4. The ingest report gains `rows_read` (rows actually read from the cursor-paged small sources: `discovery.raw_events`, `journal.intents`, `journal.results`) so incrementality is observable and testable.

Design note: the per-frame decode step is repeated in `features._frame_hint` (a seq page cannot be requested from `funnel_report.discovery_hints`, which reads a received_at window, and that file is off limits). A parity test runs both on every kind of frame (real migration frame, tampered hash, non-JSON, non-migration JSON, junk) and requires identical hints and counters, so drift is caught.

## Limitations
- Discovery hints are merged into a ledger page only within one run; a hint read in a later run than its ledger event becomes its own `(mint, migrated_at)` row (same as before T43 for small sources).
- A discovery frame whose payload changes in place is not re-read (the source is append-only and trigger-guarded; the anchor only covers the first row).
- Journal rowid cursors assume the tables keep rowids (they do: TEXT primary keys, not WITHOUT ROWID).
- `rows_read` covers only the three cursor-paged small sources, not the ledger/counterfactual/decisions pages (those are in `pages`).
- The fixture frames are a single real migration frame repeated under different source ids and times; no second distinct real mint exists in the fixtures.
