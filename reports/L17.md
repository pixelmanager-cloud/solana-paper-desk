# L17: Telegram trade notifier for the lean paper desk

Branch `cloud/L17` is based on `origin/cloud/L09`. `desk/` is untouched: `git diff origin/cloud/L09 -- desk/` is empty.
PAPER ONLY: the notifier reads the store and nothing else. It never trades and never writes the store.

## Result
`python -m unittest discover -s tests/lean -t .` in one process: **317 tests, OK, rc=0** (about 2.4 s). That is the
278 L09 tests plus 39 new ones in `tests/lean/test_notify.py`. No network is used: `socket.connect` is patched to fail,
and all HTTP goes through fake openers. No real token is involved.

## What was added
- **`lean/notify.py`.** A separate process:
  `python -m lean.notify --db … --config … --credentials DIR --state-dir DIR [--once] [--discover-chat]`.
  - **Store access.**
    - The store is opened read-only on every poll: `mode=ro` while the trader's `-wal` exists, `immutable=1` when the
      store is quiet, plus `PRAGMA query_only`.
    - It reads the real L09 schema: `fills` (lamports and raw units), `position_state` (`rung`/`closed` rows: stage,
      `initial_qty_raw`, `reason`/`last_reason`, `trade_pnl_lamports`), `events` (`halt`/`halt_cleared`), screen
      `decisions.features` (`sol_usd`, `supply_raw`, `decimals`) and the `marks` observations (vault bytes).
    - Positions, cash and realized PnL come from replaying the fills through `lean.paper.apply_fill`, the same
      accounting implementation `Store` uses.
  - **Cursors.** The last fill id and the last event id are kept in `notify-state.json` in `--state-dir`, written
    atomically (mkstemp, fsync, rename).
    - On the first start both cursors are set to the current maximum, so no history is sent.
    - If the store ids move backwards (a new store), the cursors reset to the new maximum.
  - **Outbox.** Cursors and the messages they produce are saved together before any send, and the state is saved again
    after every successful send. A crash can therefore repeat at most the one message that was in flight; nothing is
    lost.
    - The outbox is bounded (`max_outbox`). On overflow the oldest message is dropped, and an
      "⚠️ … N messages dropped" notice is sent first when Telegram is reachable again.
    - Failures back off exponentially (1 s doubling to 300 s). A 429 waits exactly its `retry_after`.
    - A 400 (unparseable entities) is retried once as plain text, then dropped and counted, so it can't block the queue.
  - **Telegram.** Plain HTTPS `sendMessage` and `getUpdates` via urllib, with `parse_mode=HTML`. All dynamic text is
    escaped with `html.escape`.
  - **Token safety.** The token is only ever in the request URL.
    - Errors carry a code only and are raised outside the `except` block, so there is no `__context__`.
    - Any URL or `bot<id>:<secret>` in error text is redacted.
    - The CLI adds a redacting log filter.
  - **Messages.** Every message is tagged `[PAPER]` or `[LIVE]` (config `mode`).
    - **BUY**:
      - 🟢 매수 <symbol | short CA>
      - the CA in `<code>`
      - entry price in SOL and USD
      - size and fee
      - market cap at the entry price (supply × fill price × SOL/USD from the trader's screen)
      - strategy_version
      - DexScreener and Solscan links
    - **SELL**: 🟡 for a partial, 🔴 for a full close.
      - The reason is mapped from the real codes: STOP, TRAILING_STOP, TIME_STOP, MAX_HOLD, LIQUIDATE, and DANGER as
        "rug write-off". TAKE_PROFIT becomes TP1/TP2/TP3 from the position_state stage.
      - fraction of the initial quantity sold, and what remains
      - exit price in SOL and USD
      - this fill's realized PnL in SOL and % (`realized_lamports / cost_sold_lamports`)
      - hold time
      - on a full close, the trade's total PnL including fees (`trade_pnl_lamports` / all buy cost of the lifecycle)
    - **HALT and clear-halt**: ⛔ with the reason, sent immediately even during quiet hours.
    - **Daily summary** at `daily_summary_at` (default 09:00 Asia/Seoul), once per day across restarts:
      - trades, win rate and realized PnL over the 24 h window
      - open positions with unrealized PnL from the latest stored `marks` observation, valued exactly like
        `lean.adapters.mark`
      - equity against the starting cash
      - the best and worst trade
  - **Quiet hours.** `quiet_hours` (it may wrap midnight) batches BUY/SELL into one 🌙 digest, sent when quiet hours end.
  - **Commands.** `/status`, `/today` and `/pnl` (by strategy_version), via a `getUpdates` long poll with a persisted
    offset.
    - Only `allowed_chat_ids` are answered (default: the telegram.json chat). Everyone else is ignored silently.
    - Commands pending at the very first start are skipped.
  - **Names.** A name from any stored payload is used if present. None exists in L09: `candidates.meta` only has
    `payload_hash`, and the screen features have no name.
    - Otherwise the notifier makes ONE Helius DAS `getAsset` call per mint and caches the result (failures included)
      in the state file.
    - If that fails, it shows the short CA `AbCd…WxYz`.
  - **Robustness.**
    - A fill that cannot be rendered produces a minimal message, and the cursor moves on.
    - A store read error is retried on the next cycle.
    - A cycle bug is logged and the loop continues.
  - **Setup helper.** `--discover-chat` calls `getUpdates` once and prints only
    `{"chats": [{"chat_id", "first_name"}]}` (the group title for groups). It never prints the token.
- **`lean/providers.py`.** New `Helius.get_asset(mint)` (DAS). It uses the same transport, limiter, retries and key
  handling. The `rpc()` allowlist is unchanged, because DAS takes object params.
- **`deploy/lean/desk-lean-notify.service`.**
  - `User=solana-desk`.
  - `LoadCredential=telegram.json:/etc/solana-desk/telegram.json` and `provider-keys.json`.
  - `ReadOnlyPaths=/var/lib/solana-desk-lean`, and its own `StateDirectory=solana-desk-lean-notify` (0700, the only
    writable path).
  - The same hardening as `desk-lean.service`, plus `Restart=always`.
- **`config/lean/lean-notify.example.json`.** Strict: unknown keys are refused, every key is listed and the defaults
  apply. A test checks that the example equals the defaults.

`telegram.json` format: `{"bot_token": "123456:ABC…", "chat_id": "123456789"}`. It must be a regular file with mode
0400/0440/0600; a world-readable file is refused.

## Tests (`tests/lean/test_notify.py`)
The store is a real lean store, produced by running the L09 e2e fake-world scenario (`test_e2e_real` helpers: 20
candidates, a restart, an outage). The notifier polls after every trader tick, as a separate reader on the live WAL.
- **Notifier timeline.**
  - It starts at T+600 s, after 3 fills, and restarts at T+2900 s.
  - Quiet hours run 17:20–17:35 KST.
  - Telegram returns 502 from T+2700 to T+3100 s (spanning the restart), then a 429.
- **Exactly once.** Every fill after the first-start cursor is sent exactly once across the restart and the outage, and
  no earlier fill is ever sent. The final outbox is empty and nothing was dropped.
- **Numbers against the store.**
  - Every fill: the price equals `Fill.price_sol_per_token`. For a BUY, the USD price and the market cap equal the
    screen's `sol_usd` and `supply_raw`.
  - Every SELL: realized equals `realized_lamports`, and the % equals `realized/cost_sold`.
  - Every full close: the trade PnL equals `trade_pnl_lamports`, the % equals PnL over lifecycle buy cost, and the hold
    time is correct.
  - The sum of the SELL facts equals `store.realized()` exactly.
  - Parsed from the SENT text, the PnL matches to display precision.
- **TP stages.** TP1, TP2, TP3 then trailing; fractions 30/30/20/20 % of the initial quantity, with remaining 70/40/20/0 %.
- **Unrealized PnL.** At a tick with 4 open positions, it equals `adapters.mark` recomputed from the fake world's
  reserves. A position opened after the last marks read correctly shows "no mark".
- **Daily summary numbers.**
  - Trades, wins, realized PnL, equity, initial cash, best and worst all equal store values.
  - The window excludes older trades.
  - It is sent once at 18:00 across the restart, follows a daily schedule, and is skipped on a first start long after
    the time.
- **Cursor and restart.** The first start sends nothing, and a second process sends nothing either.
- **Crash.** A process killed mid-flush repeats nothing on restart. The outbox survives restarts.
- **429.** No request is made inside `retry_after`, and the send happens exactly at it. Exponential backoff on 502 goes
  1, 2, 4 s.
- **Outbox bound.** With `max_outbox=3` and 6 messages, the 3 OLDEST are dropped. The notice is sent first, then the 3
  newest in order.
- **400.** The message is retried as plain text, then dropped and counted.
- **HTML escaping.** The hostile symbols `<b>LAD&DER</b><script>x</script>` and `"><img src=x onerror=…>&amp;` are
  escaped in BUY, SELL and summary messages. Every tag in every sent message is one of `<b>`, `<code>`, or a
  DexScreener/Solscan `<a href>`.
- **Token never leaked.**
  - Errors whose text holds the full token URL (`URLError`, `HTTPError` with body, 401 description, `OSError`,
    `TimeoutError`, `ValueError`) leave no token in logs, `str`/`repr`, the description, or `__context__`/`__cause__`.
  - It is not in the state file, nor in the stdout/stderr of `--discover-chat` (success and 401) or of
    `main --once`.
- **Commands.** Pending commands at first start are skipped. Allowed chats are answered (`/pnl@bot` works). Chats 999 and
  31337 get nothing. Nothing is answered twice.
- **Separation.** With Telegram failing, the store file's sha256 is unchanged and no `-wal` is created. Inserts through
  the notifier connection fail, both on a quiet store and on a live WAL store (`query_only=1`).
- **Halts.** HALT is sent immediately during quiet hours, with the reason escaped. Clear-halt follows, and other events
  are not announced.
- **Strict config and credentials.** A typo key, a bad mode, time, timezone or chat id, or a 0644 token file is refused.

## Setup (BotFather, done by the user)
1. In Telegram, open **@BotFather**, send `/newbot`, and pick a name and a username ending in `bot`. BotFather replies
   with the token (`123456789:AA…`). Treat it like a password: never paste it into chat, Git or a ticket.
2. Optionally, set the command menu with `/setcommands` and the following lines:
   `status - 보유 포지션, 현금, 오늘 손익`, `today - 오늘 체결`, `pnl - 전략별 누적 손익`.
   Leave `/setjoingroups` disabled unless you want group use.
3. From YOUR Telegram account, open the bot and press **Start** (or send `/start`).
4. On the VPS, as root:
   ```
   install -d -m 0750 /etc/solana-desk
   umask 077; printf '{"bot_token": "%s"}\n' "$(read -rsp 'token: ' t; echo "$t")" > /etc/solana-desk/telegram.json
   chmod 0600 /etc/solana-desk/telegram.json
   ```
   Then discover your chat id. The tool prints only ids and first names:
   ```
   cd /opt/solana-desk && .venv/bin/python -m lean.notify --discover-chat --credentials /etc/solana-desk
   ```
   (Run it as root: the credential directory is root-only; systemd hands the file to the service.) Add the id:
   `{"bot_token": "...", "chat_id": "<id>"}`.
5. Copy `config/lean/lean-notify.example.json` to `/etc/solana-paper/lean-notify.json` and adjust it if needed
   (`quiet_hours`, `daily_summary_at`, `allowed_chat_ids`, `mode`).
6. Install the unit: `cp deploy/lean/desk-lean-notify.service /etc/systemd/system/`, then
   `systemctl daemon-reload && systemctl enable --now desk-lean-notify`, then check `journalctl -u desk-lean-notify -f`.
   The first start logs `first start: cursors set to fill N, event M` and sends nothing. The next fill, or `/status`,
   proves it works.
7. If the token ever leaks, send `/revoke` in BotFather, put the new token in `telegram.json`, and run
   `systemctl restart desk-lean-notify`.

## Limitations
- **Not run against the live services.** Not run against live Telegram or Helius DAS. The `getAsset` response shape
  (`content.metadata.name/symbol`, `token_info.symbol`) follows Helius docs; any other shape falls back to the short CA.
  The coordinator should verify on the VPS with the real bot (step 6).
- **No rug write-off code.** The lean-1 strategy has no rug write-off exit code. `DANGER` is labelled
  "위험 감지 청산 (rug write-off)". Any unknown code is shown escaped, as is.
- **USD is approximate.** USD figures use the SOL/USD the trader last used in a screen (no extra Kraken call). A SELL
  shows no USD if that value is older than `sol_usd_max_age_s` (1 h).
- **Marks.** Unrealized PnL uses the latest stored `marks` observation, valued at the current quantity with the
  configured `pool_fee_bps` (keep it equal to lean.json's). Mark ages over 5 min are shown. Like the trader's marks, it
  ignores virtual reserves.
- **Separate Helius bucket.** The notifier process has its own in-process Helius bucket (exit-lane share). It makes at
  most one DAS call per newly traded mint, so the extra load on the plan budget is negligible.
- **Summary boundary.** Trades and realized PnL use the 24 h window ending at the scheduled time. Positions and equity
  are as of when the summary is sent; a fill at the exact boundary second counts in the next day's window.
- **Quiet store read.** While the trader is stopped and no `-wal` exists, polls read the file with `immutable=1`. A
  trader starting in the middle of that one read could make it inconsistent; the next poll reopens and corrects it. The
  cursors are ids, so nothing is skipped.
- **Not run.** The full desk suite (about 25 minutes) was not run: `desk/` and the non-lean modules are untouched.
