## What changed, by finding

1. **`lean_config_hash` no longer covers the arms (MED).** It is the hash of everything but `arms`, always. `arms_config_hash` (sha256 of the arms
   block, None when off) is recorded in the `start` event and in `health.json` next to it. Turning the arms on, or editing them, is the same main run:
   the learner's default window (`latest_config_hash`) is unchanged. Tests: `ConfigHashes`.
2. **A low-lane arm entry gets the SAME L10 model (MED, data).** When the main arm did not quote a candidate the arm takes q0 (one low-lane call,
   shared by the arms), waits `exec_delay_s` (a pending state, no sleep), re-quotes q1 (one shared call), fills at the WORSE of the two, and drops the
   entry like `lean.execution.entry_requote`: q1 without a route = `ENTRY_ABORTED_LATENCY` (`Q1_UNAVAILABLE:<code>`), a worse q1 whose round trip breaks the
   cost cap = `ENTRY_ABORTED_LATENCY` (`LATENCY_<reason>`), a shed between q0 and q1 = `ARM_SKIPPED_SHED` (stage q1). ATA rent, the transfer fee and the
   latency-tax payload are `finish_buy`'s. `price_source` is `low_lane_entry_quote:q0` / `:q1` (`:single` only when the main arm has no execution model
   either); the entries no longer carry `LATENCY_MODEL_ABSENT`. The sell leg is M1's: the effective mark model on the pool AS THE BUY QUOTE SAW IT
   (the screen's base reserve; the quote reserve re-derived from the quote, so a price that moved since the screen moves the sell leg with it), the Pump
   fee program's market-cap tier from the schedule the main marks read, each fee rounded up; the configured pool fee only as a flagged fallback
   (`SELL_LEG_FEE_FALLBACK`). The fixed 120 bps estimator is gone. Tests: `LowLaneEntryL10`, `QuoteTests`.
3. **MARK_FILL (MED, data).** On a shed / transient failure after `exit_wait_s` the exit fills at the LATEST mark of the position (`fill_mark_sol`,
   `fill_mark_age_s` in the exit decision), never the decision-time mark; with no mark younger than the price ttl nothing is filled and the exit keeps
   retrying. `lean.report`: `exclude_flags` (default `MARK_FILL`, `LATENCY_MODEL_ABSENT`; `--arms-exclude-flags a,b`, empty = none; `build(...,
   arms_exclude_flags=)`): the headline (stats, equity curve, paired) leaves out every trade with such a fill and shows them under "Left out of the
   headline"; EV by `price_source` (entry and exit, all trades) is a table of its own. `LATENCY_MODEL_ABSENT` is now only set when the main arm HAS an execution
   model and the fill was priced without it. `/arms` notes how many trades were left out. Tests: `MarkFill`, `ReportExcludesFlaggedFills`.
4. **`live_copy` as a control (MED, data).** What I chose: (a) `mirror_main: true` on `live_copy` (config key, any arm can have it): it enters ONLY
   when the main arm bought that candidate (`MAIN_DID_NOT_BUY` otherwise), so its book cannot drift into trades the main arm never made; (b) the report
   does not compare main trades that ended by an exit the arms do not model (L11 `DANGER` / `RUG_WRITEOFF` / a rug trigger, L20 `SELL_UNVERIFIED`, L23
   `BOT_EXIT`, D2 `UNEXITABLE`): they are listed with their labels (`main_forced_excluded` per arm, "forced exits" in the HTML) and left out of
   `paired_vs_main`. I did NOT mirror the main exit reason into the arm: it would make the control equal to main by construction and hide whether the
   arm's own exit logic tracks it. Tests: `MirrorMain`, `ForcedMainExits`.
5. **`nocluster_hold2m` health (LOW).** `health()['arms'][name]['filter']` = `{evaluated, pass, reject, not_ready, not_ready_share, not_ready_why}` for
   an arm with an entry filter (a deferred candidate counts once). `wait_s` stays 0. When W2b makes the clusters row exist at decision time the share
   falls from 1.0. Tests: `FilterHealth`.
6. **Pinned mark model (LOW).** An arm position's `pool_info` carries the pin the main arm writes (`mark_model.pin()`: model + vault fee) and is marked
   with `MarkModel.pinned(...)`; the captured main accounts are used only when they hold the layout that pin needs. Tests: `PinnedMarks`.
7. **Per-mint guard (LOW).** `_refresh_marks`, `_read_low` (layout per mint), the per-position mark, the quote-mark and `_evaluate_arm` (per position)
   each fail alone: one corrupt position costs only itself (a position that cannot be laid out is valued by a sell quote, D1), counted in `failures`
   / `marks_layout_errors`. Tests: `PerMintGuard`.
8. **Reserve token on the low lane (LOW).** Every arm call (entry q0 / q1, marks read, quote-mark, exit quote) is made only while
   `arms.reserve_tokens` (default 1) more tokens stay in the bucket, like L13 / L24; a bucket that can never hold 1 + reserve (the Jupiter low lane,
   about 1 token) must be full. A yielded call is a shed (`ARM_SKIPPED_SHED`, the exit waits, the marks read is skipped) and counted
   (`lane_yielded`). Tests: `LaneReserve`.

## Config

`config/lean/lean.example.json`: `arms.reserve_tokens` (1) and `"mirror_main": true` on `live_copy`. Nothing else is required; an `arms` block
without them loads (reserve 1, no mirror).

## Limits that remain

- A low-lane entry's q0 and q1 are taken by the arm thread, so q1 is "one delay plus the wake-up" after q0 (up to about 0.5 s in the thread, one
  tick in the simulated world); the recorded `delay_s` is the model's. The pending state is memory: a restart between q0 and q1 drops that candidate
  (no row).
- Forced main exits are matched by mint (the first trade of a mint is the one compared).
- A mint whose arm positions disagree on the pinned layout is read with the widest one.
