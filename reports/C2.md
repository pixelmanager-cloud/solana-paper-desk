## Design
- **Call.** ONE program-accounts call per poll on the pump program on the shared Helius LOW lane (`providers.low`, never waits: a shed lane skips the poll and writes a `curve_poll_gaps` row; low-lane calls are never retried). `method` is configurable: `getProgramAccounts` (one huge response; the transport refuses over 8 MiB: a gap with `RESPONSE_OVERSIZED`) or `getProgramAccountsV2` (`limit`, `paginationKey`, `changedSinceSlot`). Both request shapes and the response shapes (list, `{context,value}`, `{accounts,paginationKey,context}`) are tested with fakes only; the coordinator verifies V2 live.
- **Filter.** The 8-byte discriminator at offset 0 only (every layout version). No `dataSize`, no server-side `complete` filter, so the graduation is seen.
- **Decoder.** `BondingCurve` in `desk/schemas/pump.json`, discriminator `17b7f83760d8ac60` = `[23,183,248,55,96,216,172,96]`: reserves at offsets 8/16/24/32, supply 40, `complete` 48, creator 49, mayhem 81, cashback 82, `quote_mint` 83, fee bps 115, 124 = holder reward flag, 125 bytes today. Older curves are 49, 81, 82, 83, 115 bytes (missing fields are None, a missing `quote_mint` means SOL), unknown appended bytes are ignored, a bad flag byte or discriminator is a typed error. A test derives the offsets from the schema file, so a schema change fails the test.
- **The account has no mint.** A curve is found by its PDA `["bonding-curve", mint]` (`curve_address`). `join_by_mint(curves.sqlite, paths.sqlite, mint)` merges the curve marks with the PumpSwap `path_marks` of lean.paths into one time-ordered series (curve prices from virtual reserves, pool prices as vault spot).
- **Tracking.** SOL-quoted curves with progress >= `min_progress` (0.5) from the first incomplete sight, at most `max_tracked`. progress = 1 - real_token / 793.1M tokens x 1e6, clamped. A mark is written only when a curve changes; so with no gap row between two marks, nothing changed. `GRADUATED` (the complete mark is written first) and `STALE` (no change for `stale_s`; a later change starts segment 1) end a path; absence from a V2 response is never an end.
- **Budget.** `max_credits_month` 500,000 / 720 = 694 credits per rolling hour = 69 calls/hour, checked BEFORE every call from the `curve_polls` table (a restart does not reset it), and `effective_interval_s` stretches the requested `poll_s` (10 s) to 51.84 s, more when V2 paging averages several pages. `estimate()`, `health.json` and `python -m lean.curves report` show requested vs effective cadence, calls/hour and credits/month (default: 69.4 calls/h, 500,000 credits/month).
- **Retention (L07R2 pattern).** Own WAL file, size rollover to `curves-YYYYMMDD[-n].sqlite` carrying the live paths and their last mark, a free-disk floor below which nothing is written.
- **Isolation.** Every public method swallows and counts its failures; in memory the state changes only after the write succeeded (no phantom path after a failed write); a partial V2 poll keeps what it fetched but never advances the cursor; nothing is written to `lean.sqlite`, and a test proves `lean.sqlite` is identical table by table with the recorder off.

Mutations tried (each turned at least one test red, then was restored): owner check removed; progress gate removed; graduation final mark/end removed; cursor advanced on partial polls; credit budget ignored; mark dedupe removed; stale sweep removed; SOL-only gate removed; price formula with wrong decimals; shed retried; `dataSize` added to the request (survived the first test set, so the request-shape test now pins the exact option keys); in-memory state applied before the write (survived, then the failed-write test got `live == {}` and the stats checks and killed it).

## Remaining limitations (honest)
- **Unverified live:** `getProgramAccountsV2`'s request fields (`limit`, `paginationKey`, `changedSinceSlot`) and its response shape follow Helius' documentation, not a captured response; `changedSinceSlot` is assumed to include accounts changed AT that slot (duplicates are harmless: unchanged curves write nothing). If the context slot is missing the old cursor is kept. With v1 the response is far over 8 MiB on mainnet.
- **No price before a curve reaches `min_progress`** and none for curves that graduate between two polls (~52 s by default): the last seen state may be below 1.0 and the `complete` mark is the first post-graduation state; analysis should join on `curve_ends.ts`.
- **Gap between curve end and the first pool mark:** lean.paths starts a pool path only after the candidate is screened (~300 s after graduation), so `join_by_mint` has no data for those first minutes.
- A curve that changes more than once between polls shows only the latest state per poll.
- The initial-real-reserve constant (793.1M tokens) is pump.fun's published figure, configurable; a different launch parameter would show a progress offset.
- 69 calls/hour is the budget ceiling for the default config; with V2 paging each page is a call, so a busy poll (many changed curves) can exhaust the hourly budget and produce `budget` gaps; the cadence adapts through the average pages per poll.
- `lean.paths` was not changed; it still marks only candidates that pass the screen.
