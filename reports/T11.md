## What changed and why
`python -m tools.ops.cutover [--apply] {stage,cutover,rollback}` replaces the per-release helper scripts. Default is dry-run:
reads (`systemctl show`, runtime digest) run, every mutation is only printed under `commands`.
All mutation goes through one `Ops` object (injectable runner), journaled to `--journal` (0600, append-only, fsynced) when applied.

- **stage**: sha256 verified first (constant-time), `--commit` validated hex, release root must be canonical and not
  group/world writable. Archive rules: no absolute/`..`/backslash/NUL names, no symlink/hardlink/device members,
  no duplicate members, member-count and total-size bounds. Extraction is manual (`O_EXCL|O_NOFOLLOW`, setuid/world-write
  bits dropped) into a temp dir, requires `desk/`, computes the runtime digest (`python -I`, cwd=release), then renames
  into place. Any failure removes the temp dir. Existing destination refused. `--expect-digest` optional.
- **cutover**: all validation precedes any write: unit-name pattern `desk-*.service|timer`, no overlap between
  `--units`/`--configure-only`/`--keep-off`, release must be a canonical direct child of `--release-root` containing `desk/`,
  timers require their same-named service in the cutover, entry-dispatcher units need `--allow-entry`, keep-off units must
  not already be active, every rendered ExecStart (store-env, base unit, drop-ins) is checked for off-loopback binding.
  Then marked `60-reviewed-release.conf` drop-ins, `daemon-reload`, effective WorkingDirectory/ExecStart check before any
  start, start only `--units`, post-start ActiveState/Result/WorkingDirectory check, keep-off still inactive.
  Any failure stops the units this run started (reverse order) and leaves drop-ins plus a `cutover-failed` journal entry.
- **rollback**: removes only drop-ins containing the marker (never follows symlinks), restores a recorded
  `.pre-cutover-<UTC>` backup of a replaced foreign drop-in, `daemon-reload`. Does not stop/start units.
- **RUNBOOK**: full fresh-start flow (stage → stop writers → T03 backup → read-only → T13 → T05 → cutover with entry OFF →
  T02 → enable + T07 latch → T06 snapshot/compare) and "rotate when flat".

## Limitations (honest)
- Never exercised against real systemd; the fake simulates only `show/start/stop/daemon-reload` and applies drop-ins on reload.
  First real use should be the dry run on the VPS, then `--apply` with timers off.
- Oneshot services started by `systemctl start` block until finished; health accepts `inactive`+`Result=success` only when `Type=oneshot`.
- Loopback detection is token-based on ExecStart text (bind flags, wildcard addresses, `ip:port`); it cannot know a program's
  default bind. `desk serve` hard-codes 127.0.0.1 (`desk/dashboard.py:164`), so this guards against ExecStart edits only.
- `fresh_start` (T13) output shape was not available; cutover accepts its own `cutover-store-env v1` JSON (documented in RUNBOOK).
- Rollback does not restore a running unit's previous release; restart is a deliberate operator step.
- Sibling-tool flags in RUNBOOK follow the TASKS.md specs, not merged code.
- Stage cannot detect a malicious but well-formed Python release; sha256 provenance is the operator's responsibility.
