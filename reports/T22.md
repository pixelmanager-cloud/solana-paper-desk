## Design
`desk/paper_pass_closure.py` (new) + table `paper_pass_closures` (trigger-guarded, append-only, <=8192 rows). Each closure
is a content-addressed record bound two ways: `paper_observation_passes.outcome_hash == closure_hash == digest(record)`.
* **FAILED_CHARGED** — written by the failing process (`run_once` end-of-pass and an outer `except BaseException`;
  `prepare()` for history preparation). Record: intent hash, per-scan charge window `{before, after}` (after >= before,
  <= ceiling, <= live counter — no refund), attempt-original refs that exist, monitoring reservation range (each must carry
  an outcome), an immutable ledger prefix anchor, cause, result hash.
* **ABANDONED_CHARGED** — `recover_abandoned`, run at the start of `run_once` and by the dispatcher while holding research →
  evidence → ledger locks. A held flock cannot outlive its process, so an unresolved pass seen under all three locks belongs
  to a dead process (no wall-clock age is trusted). It also appends an explicit `paper_monitoring_abandoned_v1` outcome for a
  dangling monitoring reservation (`MonitoringBudget.abandon_pending`, verified by `_accounting`; still charged, never refunded).
* **INTEGRITY_HOLD** — the owner finished with an integrity cause; the pass stays NULL (global latch holds) and the marker
  stops recovery from ever closing it.
* Eligible for recovery only: passes whose intent carries `closure_v1` (created by this code), not held, not certified by
  any reviewed receipt. Older NULL passes and receipt-certified passes are never touched, so existing receipts still verify.
* **Retirement:** a FAILED lone candidate that charged >=1 request and left the ledger unchanged has its scan retired
  (gate → `REJECTED_SCAN_RETIRED`, other scans unaffected). Held passes are never retired, ABANDONED never retires.
* **Dispatcher:** `dispatcher_failed_charged_v1` result closes an unresolved intent (in-process failure → FAILED_CHARGED;
  next execute after 900 s + lock → ABANDONED_CHARGED, only after the evidence store is clean). Replayed in `_check_records`.
  The mint stays unique in the journal, so the same candidate is never dispatched again; other candidates proceed. Dry run
  stays read-only and still reports "Unresolved dispatch". Refuses to label a mint with an open position.
* **Monitoring:** `SOURCE_FAILURE` now latches only for `CLOCK_INVALID`/`OUTCOME_PERSISTENCE_FAILED` (every provider failure
  is a charged, retained, non-latching outcome).

## Classification (cause → outcome)
* Held (INTEGRITY_HOLD): any code containing BINDING_INVALID, MISMATCH, PERSISTENCE_FAILED, LEDGER_INTEGRITY,
  OBSERVATION/MONITORING_RECOVERY_REQUIRED, ACCOUNTING_INVALID, EVIDENCE_INVALID, MUTATED, IDENTITY, CHECKPOINT,
  OUTCOME_PENDING, CLOCK_ROLLBACK, IMPLEMENTATION; `RecoveryRequired`; exceptions mentioning checksum/corrupt/evidence
  missing/encoding; sqlite `DatabaseError`, `JSONDecodeError`, `zlib.error`; any unclassified exception type (RuntimeError, TypeError, …).
* FAILED_CHARGED: everything else, e.g. TRANSPORT_ERROR, SOURCE_REQUEST_FAILED, SOURCE_RESPONSE_STALE, UNRESOLVED_QUOTE_DEMAND,
  UNRESOLVED_POSITION_EXIT, HELD_OBSERVATION_CONTENT_REJECTED, HISTORY_RECOVERY_REQUIRED, CYCLE_DEADLINE_UNAVAILABLE, budget
  exhaustion, OSError/timeouts, KeyboardInterrupt/SystemExit. T01's NORMAL codes still publish T01's NO_ENTRY first.
* ABANDONED_CHARGED: any closure-capable unresolved pass found under the locks.

## Limitations (honest)
* An INTEGRITY_HOLD is still a global latch (any scan, held monitoring included) — scan-scoped holds were not built.
* If the owner dies, or `store.save` fails, between an integrity exception and its hold marker, the pass is indistinguishable
  from an abandoned one and the next start closes it (closure_v1 passes only). Narrow, not eliminated.
* `close()` proves charge windows and monitoring outcomes, not one attempt original per charge; missing originals are visible
  (`attempt_refs` short) but not refused. Non-retired closures get a binding-count check at the gate, full replay only via `_verify`.
* Capacity: closures <=8192 and the existing 10000-pass hard latch (`terminal._passes`) are unchanged; held monitoring adds a pass
  row per run. Needs a retention/rotation rule (coordinator rotates stores on any desk/ change anyway).
* Pre-existing `blocked='SOURCE_FAILURE'/'CLOCK_ROLLBACK'` monitoring latches in old stores are not cleared.
* `paper_observe_cli` passes (diagnostic CLI) and the pacing-slot orphan (F6, T23) are untouched; pacing/waiter latches are separate.
* Dispatcher dry run does not recover (by design); recovery needs an execute tick.
