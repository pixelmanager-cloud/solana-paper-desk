# T02F — Coordinator review fixes for the status CLI

Branch `cloud/T02F`, BASE `origin/cloud/T02` (192d69a). Owns `tools/ops/status.py`, `tests/test_ops_status.py` only; no `desk/` change
(runtime hash unchanged, no successor pin).

## What changed (by finding)
1. **[Blocker] .pyc into `--release-dir`**: the release probe now runs `python -I -B`, its code sets `sys.dont_write_bytecode=True`
   before importing `desk`, `default_runner` always passes `PYTHONDONTWRITEBYTECODE=1`, and the tool sets
   `sys.dont_write_bytecode = True` before its own first `desk` import (so it also stops writing `__pycache__` into the repo/release it runs from).
2. **[High] `immutable=1` rule**: new `open_mode()`. `immutable` only when header byte 18 == 2 (WAL) **and** there is no `-wal`; every other
   database (rollback-journal `provider-pacing.sqlite`, anything with a `-wal`, non-SQLite junk) uses plain `mode=ro`.
3. **Tests**: live-WAL `mode=ro` test with an open writer holding committed pages only in the `-wal` (reader sees them, writes are refused, the
   main file hash is unchanged, the writer is never blocked and the reader sees its next commit); a real quote-execution BUY and BUY+SELL ledger
   built with `tests.test_quote_execution.QuoteExecutionTests` asserts `execution_label == 'EXECUTION_UNVERIFIED'` on every fill.
4. **Binding check**: `budgets.monitoring.binding` compares `paper_monitoring_budget.ledger` with `--ledger` and `config_hash` with the canonical
   digest of `--config`. Mismatch → blocker `MONITORING_BINDING_MISMATCH`; unverifiable (config unreadable) → `MONITORING_BINDING_UNVERIFIED`.
5. **Fail closed**: ownership exhaustion is an aggregate over all rows (`exhausted`, `missing_values`, `total`; the 50-row list stays a bounded
   sample with `budgets_truncated`); `os.walk(onerror=raise)` so an unreadable directory is `UNREADABLE_STORE_INVENTORY`; symlinked stores/dirs →
   `STORE_SYMLINKED`, hardlinked stores → `STORE_HARDLINKED` (those files are also not opened for `--check`); NULL ledger mode →
   `LEDGER_MODE_MISSING`, NULL ownership value → `OWNERSHIP_CEILING_MISSING` (no crash). A non-null pacing `pending` is now a
   **warning** (`PACING_PENDING`); with `--samples 2|3` (`--sample-interval`, default 3.0 s) a pending ticket unchanged across all reads is
   blocker `PACING_PENDING_STUCK`, a changed one is warning `PACING_PENDING_CHANGED`. The report gains a `warnings` list.

## Limitations (honest)
- Monitoring binding compares the stored ledger path string with `--ledger` verbatim (both must be canonical absolute paths, which `canonical_path` already enforces).
- `PACING_BLOCKED_OR_PENDING` keeps its old name for blocked-until/waiters (consumers unchanged); pending no longer feeds it.
- A rollback-journal database with a hot `-journal` cannot be rolled back by a read-only connection and will surface as an unreadable section (fail closed).
- The tool still has not run against production stores or real `systemctl`/`ss`.
- The live-WAL test proves behaviour for a committed-but-unflushed WAL; a writer mid-transaction is isolated by SQLite's snapshot semantics and is not separately exercised.

## For the coordinator
- New flags: `--samples {1,2,3}` (default 1) and `--sample-interval` (seconds, default 3, capped at 60). Use `--samples 2` when you want a pending pacing slot to count.
- Blocker names added: `MONITORING_BINDING_MISMATCH`, `MONITORING_BINDING_UNVERIFIED`, `OWNERSHIP_CEILING_MISSING`, `LEDGER_MODE_MISSING`, `STORE_SYMLINKED`, `STORE_HARDLINKED`, `PACING_PENDING_STUCK`.
- Decision: unverifiable binding blocks (fail closed) rather than being ignored.
