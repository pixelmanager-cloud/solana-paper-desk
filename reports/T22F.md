## The merge (not in the task text, but it decided the design)
T25F (integration) already resolves orphan monitoring reservations on the read path with strict rules: the orphan is older than
60 s, no OTHER process holds the evidence-invocation or paper-cycle flock (readable `/proc/locks`, lock files must exist), not
a handoff allowance. T22's `MonitoringBudget.abandon_pending()` closed orphans immediately. I kept T25F's stricter rules and
made `abandon_pending()` a bounded adapter over them (`MAX_ABANDONED = 64`, same `paper_monitoring_abandoned_v1` record, charged,
never refunded). The record is read back inside the write transaction and re-checked before commit. Consequence: pass-closure
recovery of a held pass with a dangling reservation now happens only after >60 s with the locks free, otherwise it fails closed
(`Monitoring reservations unresolved: MONITORING_OUTCOME_PENDING`, the pass keeps its NULL).
Test adaptations, each with its reason written in the test: restarts after `ABANDON_AFTER_SECONDS + 30` with the lock files
present; the injected source failure is a classified transient `ConnectionResetError` (a bare `OSError` is `UNCLASSIFIED_ERROR`,
which integration latches on purpose — pinned by the new `test_monitoring_unclassified_source_failure_still_latches_restart`);
forged-record variants forge through `_save_page` (abandonment no longer goes through `EvidenceStore.save`).
New: `test_young_or_owned_orphan_is_not_abandoned`.

## What changed
* **R1 (MED)** `desk/paper_cycle_no_entry.py`: `producer_blocker_is_normal` is a positive allow-list. Normal = 
  `MISSING_/STALE_WINDOW_MEASUREMENT:<known measurement>` or a hazard that is **declared on the intent's target**
  (`known_hazards`). `PRODUCER_INTEGRITY` codes and the prefixes `SOL_USD:`, `ORIGINAL_`, `COLLECTOR_`, `COORDINATOR_` and window
  prefixes with an unknown name stay category (b) even if an operator declares them as a hazard. Every retained diagnostic
  blocker must pass or the pass is not retired as a normal no-entry. The two T12 integrity `expectedFailure` tests now pass
  with the decorator removed.
* **R2 (HIGH)** `_index(store, scan, refs)` loads only the scan's bound attempt refs (<= 18). `publish` builds the refs from the
  result's `attempt_refs + usd_evidence_refs`; the gate rebuilds them from the retained row. The 4096-page / 256 MB whole-store
  bound is gone from the gate and from publish. Completeness is proven by the ref set covering exactly `before+1..after` with
  one attempt per charge (a missing ref fails closed). Both T12 bounds `expectedFailure` tests pass undecorated. New measurement
  test: gate page loads are identical (29 vs 29) with 1500 unrelated pages added, wall time bounded at 10x.
* **R3** `record_refusal` / `read_refusals`: a `publish()` refusal swallowed in `run_once` is logged (`publish_refused`) and
  appended to `<evidence db>.publish-refused.jsonl` as `publish_refused_v1` (pass, scan, blocker, exception class, <=200-char
  detail, time). Append-only, `fsync`, capped at 1 MiB, never raises (a write failure is logged). Fail-closed behaviour unchanged.
* **R4** `_guards(limit)` factory (trigger text for the default limit is byte-identical, pinned by a test). Warning at 80% of
  `MAX_ROWS` (log + `rotation_warning_v1` line in the same file). Hard stop at 100%: typed `RotationRequired(ValueError)` raised
  before the INSERT; that pass is then closed `FAILED_CHARGED` by T22's path, nothing is latched, every retained row still
  replays, so the store stays flat-rotatable. RUNBOOK "Rotate when flat" documents the warning, the file and the hard stop.
* **R5** `RETAINED_MIGRATION_WITNESS_REQUIRED` is retired only when the graduation diagnostic's blockers are exactly
  `['MIGRATION_WITNESS_ABSENT']` (conflicting timestamps, account-binding mismatch, regressing slot time, malformed raw
  transaction stay category (b)).
* **Addendum (history_first)** T22 already closed the prepare() NULL pass on any `BaseException`; I added tests for the normal
  blockers (`FEATURE_HISTORY_PAGE_LIMIT`, `INVESTIGATION_REQUEST_BUDGET_EXHAUSTED`): pass closed `FAILED_CHARGED`, gate clean,
  exception still propagates. These two tests are GREEN on BASE (T22 had covered the path); they are regression pins, not a fix.

## Limitations
* The gate is still O(R) in the number of retained rejections (each replay is O(<=18 refs) + a 256-event ledger anchor); it is
  flat in unrelated store size, not in R. Rotation at 80% of 8192 rows is the bound.
* Uniqueness of a charge is proven against the bound refs, not against every page of the store: an unreferenced duplicate page
  is ignored rather than detected (it cannot enter a retained row, because the row hashes its refs).
* `terminal._classification` and other gate stages not in T22F's files still scan passes; not measured beyond the flat-cost test.
* Pass-closure recovery of a held pass with a dangling monitoring reservation now needs >60 s and free locks (T25F rules).
