# T29F — Fix coordinator review findings in T29 (funnel report)

Branch `cloud/T29F`, BASE `origin/cloud/T29` + merge of `origin/integration/r1` (ccc0298; contains T01's `paper_cycle_no_entry`). Files: `tools/research/funnel_report.py`, `tests/test_funnel_report.py`, this report. Nothing under `desk/` touched (no hash impact, read-only tool).

## What changed (per finding)
1. **(HIGH) Latches no longer counted as normal deaths.** New `read_passes` (evidence DB, `mode=ro`) and `latch_verdict`: a non-COMPLETE `paper_cycle_v1` result is `OBSERVATIONS:<code>` only if its `paper_observation_passes` row has an outcome (T01's `paper_cycle_no_entry` fills it) or a NULL pass is covered by a `paper_cycle_no_entry` row (by pass or scan id). A NULL pass with no receipt, or a pass id missing from the table, is `UNRESOLVED:<code>`; a result without a pass id is `UNRESOLVED` when any NULL pass exists and requests were charged (the global gate latches on ANY NULL pass), normal when nothing is NULL or nothing was charged. `paper_cycle_no_entry_v1` result bodies are recognised as normal. `RECOVERY_REQUIRED` stays UNRESOLVED. JSON gets `unresolved{count,by_code}` and `latch_check{status,…}`; the HTML starts with a prominent UNRESOLVED section before the funnel. Without `--evidence-db` the latch cannot be verified: deaths keep `OBSERVATIONS:` but carry flag `LATCH_UNVERIFIED`, `latch_check.status=NOT_PROVIDED`, and the HTML says so (this is the only judgement call; the alternative of relabelling every blocker as unresolved would break the evidence-less report).
2. **(MED) Selection filter.** `discovery_hints` now calls the dispatcher's own `migration._hints('selection-only', …)` (imported, with `dispatcher.PROVENANCE`) and marks blocked hints `unselectable`; they die before `selectable` as `UNSELECTABLE:<reason>` instead of inflating `EXPIRED_NOT_DISPATCHED`.
3. **(LOW) Mint filter.** `classify_result(body, mint, …)` only counts fills/rejects whose `mint` equals the candidate's, so a held position's BUY or reject is never attributed to a candidate. Existing fixtures were retagged with the candidate mint (comment in `add_candidate`).
4. **(LOW) Docstring / dead-pool semantics.** The docstring claimed dead pools count as −100% while the code kept them out of the median. Fixed to the code's actual (and now explicit) rule: a dead pool is a separate bucket counted in `candidates`/`pool_died` and the new `share_pool_died`, never folded into median/share-positive. **T26F was not available on this branch, so alignment with it is NOT verified** — if T26F chose −100%, change the one docstring + `forward_returns` accordingly.
5. **(LOW) Real-store fixtures.** `RealStoreLatchTests` runs the report on real evidence/research/ledger stores produced by the T01 fixtures (`tests.test_cycle_no_entry.fixture()`: actual `run_once`, pass table and `paper_cycle_no_entry` receipt): published rejection ⇒ normal, legacy NULL pass ⇒ UNRESOLVED; also with category-(b) code `USD_ORIGINAL_BINDING_INVALID` (a label substituted on a REAL charged NULL pass — the stock fixtures cannot produce a genuine category-(b) blocker through `run_once`, so only the label is synthetic). `RealFlowTests` additionally checks the selection filter on a real discovery frame (passes) and with a patched blocking `_hints` (marked `unselectable`).
