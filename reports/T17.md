# T17 — Fix review findings in the live-execution design doc

Docs only (`docs/live/LIVE_EXECUTION_DESIGN.md`); no code, tests or config touched. Base `origin/cloud/T15`.

## What changed (by coordinator finding)
1. **Signer vs rent (§3).** Allow `CloseAccount` only for the desk's own ATA of the traded mint, zero simulated balance, hot wallet as owner and destination. Math: ~0.00204 SOL rent = 20.4% of a 0.01 SOL trade; 30 stranded round trips = 0.0612 SOL = 12.2% of the 0.5 SOL wallet cap. Rent is a recoverable lock-up in the PnL model; the close tx fee is a cost. Alternative offered: no closes, canary >= 0.1 SOL (rent 2%).
2. **CI basis (§4.3).** Bootstrap (10,000 resamples) on T14's +5 s fills with the real fee stack (base + priority + tip + close fee), not the instantaneous quote or `fixed_fee_sol`. Pre-measurement fallback: shadow-simulated fee and the highest fee the signer would accept.
3. **Size mismatch (§4.8, new).** Gate requires either PnL recomputed at canary size with fixed costs not scaled down (illustration: 0.003 SOL per round trip = 3% at 0.1 SOL vs 30% at 0.01 SOL, assumed values) or matching the 0.1 SOL paper size (recommended, wallet cap >= 1.0 SOL).
4. **Numbers (§4.4, §5 stage 3).** Shadow: >= 7 days and >= 500 attempts, build success >= 95%, simulate success >= 90%, fee within +/-20% of model, out-amount within min(1.0%, minimumOut tolerance) at p90, stage time p95 <= 3 s, zero reconciliation errors. Canary: >= 30 trades, landing >= 90%, mean realised cost within +1.0 pp of model, no trade > 3 pp over, all ATAs closed. Reconciliation defined for simulate-only mode (simulated account deltas vs intent; 1,000 lamports + 0.5% tolerance) and live mode (1,000 lamports dust).
5. **Risk acceptance (§4.3).** Capped at the canary wallet cap (0.5 SOL), max 30 days, one frozen config, auto-expiring; waives only the CI condition (not items 2, 4, 5, 6, 8).
6. **Reference.** `forJitoBundle` is at `providers.py:213` (verified with grep). Also made the ATA-rent figure in §2 consistent (2% of 0.1 SOL, was "4% of 0.05 SOL").

## Limitations / For the coordinator
- Every threshold is a proposal the developer must approve; none is derived from measured data (zero live-data fills exist). Fee and cost figures marked "assumed" are illustrations.
- Rent figure 0.00204 SOL is the standard 165-byte token account; Token-2022 with extensions costs more. Not checked against an RPC (no network by rule).
- The recommendation to match sizes (item 8(b)) raises the wallet cap and therefore the maximum loss; that is the developer's call.
- No production stores or credentials touched.
