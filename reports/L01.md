# L01 — lean/store.py + lean/paper.py (+ tests)

Branch `cloud/L01`, base `origin/integration/r1`. New files only: `lean/__init__.py`, `lean/paper.py`, `lean/store.py`, `tests/lean/{__init__,test_paper,test_store}.py`. `desk/` is untouched and not imported.
Paper only: no signing, broadcasting or funds; every fill is a quote-based simulation labelled `EXECUTION_UNVERIFIED` (the schema refuses any other label).

## API as built (for L02-L06)
`lean.paper` (pure, integers only: SOL = lamports, tokens = raw units, every division rounds DOWN)
* `PaperConfig(fee_lamports=50_000, slippage_bps=50)`, `Quote(mint, side, in_amount, out_amount, decimals, ts, source='jupiter', ref=None)` (buy: in = lamports, out = token raw; sell: in = token raw, out = lamports; `ref` = observation id of the retained raw response).
* `buy(quote, size_sol, cfg) -> Fill` (the quote must be for exactly that spend), `sell(position, quote, fraction, cfg) -> Fill` (the quote must be for exactly the quantity sold; average-cost basis, full sell takes all remaining basis).
* `apply_fill(positions, cash, fill)`: the ONE implementation of the rules (raises `AccountingHalt`); `to_lamports(size)`; `Position`, `Fill`, `PaperError`, `AccountingHalt`.
`lean.store.Store(path, *, initial_cash_sol=None, code_version=None, strategy_version=None, clock=time.time)` (a new file needs `initial_cash_sol`; an existing one keeps its own, a different value is refused)
* `record(kind, payload, *, code_version, strategy_version, ts=None) -> id` (generic `events` row); `add_candidate(mint, pool=, signature=, slot=, migrated_at=, hint_seq=, meta=)` (idempotent per mint), `candidate_id(mint)`; `add_observation(kind, raw_bytes, mint=, candidate_id=, meta=) -> id` and `observation(id)` (bytes verified against their sha256); `add_decision(kind, action, mint=, reasons=, features=)`; `add_error(code, transient=, scope=, mint=, message=)`; `add_fill(fill, candidate_id=)`.
  Version arguments fall back to the constructor defaults; with neither the call raises `StoreError`.
* `positions() -> {mint: Position}`, `cash() -> int lamports`, `realized() -> int`, `check_invariants()` (raises `AccountingHalt`), `counts()`, `rows(table, where=, args=, limit=)`.
* Credentials never reach the store: error messages and observation metadata pass through `redact` (`api-key=`, `x-api-key:`, `Authorization:`, `Bearer ...`). Thread safe (one connection behind an RLock, each write one `BEGIN IMMEDIATE` transaction).

## Design notes
* Identities (exact, integer): `cash = initial - sum(buy sol + fee) + sum(sell sol - fee)`; `cash + open_cost = initial + realized`; no negative quantity; no sell without a position; cash never negative. The buy fee is part of the cost basis.
* Positions/cash are DERIVED by replaying fills through `apply_fill`. Each fill row also stores `cash_after/qty_after/cost_after`; `check_invariants` replays everything, compares those columns row by row, and cross-checks with plain SQL sums, so an edited, inserted, deleted or reordered fill is caught even if the triggers were dropped, and a bug in the shared rule is caught by the independent sums.
* Every table is append-only (UPDATE/DELETE triggers); a trigger also refuses a sell larger than the running quantity; the schema is compared byte for byte on open (a lean store is never migrated).

## Evidence
* `python -m unittest discover -s tests/lean`: 48 tests OK (15 paper, 33 store), including 40 seeded random fill sequences (about 800+ accepted fills) against an independent plain-integer reference model, tamper tests with the guards lifted, thread test (8 threads), and the cases above.
* Mutation: 52 single-point mutants over both modules. First pass left 10 survivors; new tests (boundary cash, bearer redaction, unique mint, symlink/dir, cash-identity bugs injected into the shared rule, stronger thread test) killed all but 3 equivalent ones: the full-sell cost branch in `sell` (`cost*qty//qty == cost`), the `any(q<0)` check (subsumed by the following positions check) and `_cache = None` in `add_fill` (the cache is keyed on the last fill id).

## Limitations
* `positions()/cash()` replay all fills when the cache is stale (O(fills) per new fill); fine for thousands of fills, would need an incremental balance if a run reaches millions.
* `rows()` is a plain reader for reports; no pagination beyond `limit`.
* No migration path by design; a schema change means a new store file.
* Not run under a real process supervisor; the runner (L05) owns the halt-on-`AccountingHalt` behaviour.

## For the coordinator
* The package `lean` is not in `pyproject.toml`'s `packages.find` (`include = ["desk*"]`); units run it from the release directory (`python -m lean`), so nothing needs packaging, but `pip install -e .` will not expose it.
* Conservative choices: sells that would drive cash below zero are refused (a fee larger than the proceeds on a nearly empty account); quotes must match the requested size exactly instead of being rescaled.
