## What changed, by review item
1. **Failed/hung start.** A unit is added to the started set before its `start` call, so the failure path stops it. `Ops._run` wraps `TimeoutExpired` and every other runner exception into `CutoverError` (reads and mutations).
2. **Already-running units.** Every `--units` member must be `inactive`/`failed` before any write. After `start`, the new process is proven: `ExecMainStartTimestampMonotonic` >= cutover start (same CLOCK_MONOTONIC as `time.monotonic`), `MainPID` changed across the start call; oneshot: ran after the start with `Result=success`; timers: a next trigger is scheduled (or one just fired).
3. **Rollback with active units.** Refuses while any managed unit (marker drop-in) or its timer/service partner is active. `--stop` stops them (timers first), verifies they stopped, and only then removes drop-ins.
4. **Keep-off.** `is-enabled` is read and reported (`keep_off`); an enabled keep-off unit is `disable`d before any drop-in is written, re-checked, and the run is refused if it is still enabled. Rechecked after the settle window.
5. **Health settle.** `unit_ok` rejects `activating` and bad sub-states (`auto-restart`, start*, stop*, failed, dead). A second check after `--settle-seconds` (default 10, injectable sleep) requires health, unchanged `NRestarts` and unchanged `MainPID`.
6. **Old-store guard.** `--archived-root` (repeatable, default `/var/lib/solana-desk`) and `--allow-archived` (explicit unit list, empty by default). Checked on the planned ExecStart/Environment (store-env, unit file, all drop-ins, for `--units`, `--configure-only` and `--keep-off` services) and again on the effective `systemctl show` Exec*/Environment after reload, before any start. Word-boundary match: `/var/lib/solana-desk-fresh/...` is not archived.
7. **T13 format.** Accepts the manifest (`kind: fresh_start_manifest_v1`), the bare `unit_arguments` map, or a `{"version":1,"units":{...}}` wrapper that may mix T13 specs with hand-written v1 units (the RUNBOOK builds this with `jq`). Keys without `.service`, lowercase `environment`/`argv`, argv without interpreter (`--interpreter`, default `/opt/solana-desk/.venv/bin/python`). Rendered with systemd quoting (double quotes, `\`/`"` escaped, `$`->`$$`, `;` quoted, empty string quoted), `%`->`%%`, control characters refused. A `fresh_start_plan_v1` file is refused (placeholder scheduler identity).
8. **Partial store-env.** A store-env may cover a subset of `--units` (others get plain WorkingDirectory drop-ins) and may name more units than the cutover (extras are ignored and reported as `store_env_ignored`).
9. **Minor.** Hash and extract use one open fd (`O_NOFOLLOW`, regular file, `tarfile.open(fileobj=...)`); staging collisions and any OS error become `CutoverError` with cleanup (exclusive `mkdir` of the destination before the rename); all `Exec*` values from `systemctl show` are checked (argv extracted per struct, anchored on `; ignore_errors=` so a `;` argument cannot hide later flags); drop-ins, their directory (and a newly created parent) and removals are fsynced; the marker must be the first line (`is_managed`).
10. **RUNBOOK rewritten** for the fresh start: new roots under `/var/lib/solana-desk-fresh/<version>/` (outside the archived root), `--expect-count 14`, exact cwd for every `tools.ops.*` command (stage: reviewed checkout; others: the staged release), cutover/re-enable of discovery (long-running), held, monitor, decisions, dashboard (loopback) and backup (new root) with the entry timer kept off, T07 latch installed before enabling the entry timer, rollback `--stop`, rotation with both archived roots, and a "known gap" for T05.

## Remaining limitations
- `ExecMainStartTimestampMonotonic` vs `time.monotonic()` assumes Linux `CLOCK_MONOTONIC` on the coordinator host (true for systemd hosts); the cutover must run on the same host as systemd.
- A timer whose first trigger is legitimately far away still passes (a scheduled trigger is all that is required).
- The archived-root guard is textual: it sees paths written in ExecStart/Environment, not paths a program derives at runtime. Shared inputs are allowed under every archived root by name (`provider-pacing.sqlite`, `discovery/continuous.sqlite`, with `-wal/-shm/-journal`), so a lookalike with that exact name under a previous fresh root would pass.
- `EnvironmentFile=` contents are not read (only the directive text is scanned).
- Dry-run cannot verify post-reload effective values; those checks run only with `--apply`.
