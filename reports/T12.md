## Verdict

real defects need fixing before the fresh-start deployment is trusted unattended (R1, R2); the rest are lower-ranked.

## Ranked findings

### R1 — HIGH: category (b) integrity conditions are mislabelled as a normal rejection (nested blockers)
`MARKET_PRODUCER_BLOCKED` is a single top-level code (`desk/paper_cycle.py:383-384`) that `fulfill_quotes` raises whenever the market
adapter returns `event=None`, whatever the reason. The adapter's reasons include corrupt/contradictory/unbound supplied evidence:
`COLLECTOR_SOURCE_BINDING_OR_CONTENT_INVALID` (`desk/paper_market_adapter.py:73-74`), `COORDINATOR_TARGET_BINDING_MISMATCH` (:66-68),
`COLLECTOR_OBSERVATION_REJECTED` (:69), `SOL_USD_TRUSTED_INPUT_INVALID` (:113), `EXPERIMENTAL_EVENT_CONTRACT_INVALID` (:183), next to
ordinary `MISSING_/STALE_WINDOW_MEASUREMENT:*`. T01's `_check_result` (`desk/paper_cycle_no_entry.py:119-124`) only requires that *some* diagnostic
carries a non-empty list of strings, so every one of them validates and `publish()` retires the pass as `NO_ENTRY`, clearing the store-wide latch that a
(b) condition is supposed to keep. Reachable: charged reads return HTTP 200 (the attempt inventory passes) but the adapter's replay of the collected
originals fails, for example after a provider schema change or a binding bug.
Effect: no unsafe entry (that candidate is never entered or retried), but corrupt evidence stops forcing coordinator review, which AGENTS.md says must fail closed.
Evidence: `tests/test_review_t01_integrity.py` (2 `expectedFailure`): all five integrity blockers validate; `publish` succeeds and the NULL pass is filled.
Fix: allow-list the inner producer vocabulary (`MISSING_WINDOW_MEASUREMENT:*`, `STALE_WINDOW_MEASUREMENT:*`, declared known hazards) and require every blocker
in the retained diagnostic to be in it; anything else keeps the NULL latch. (Or make the product decision that integrity failures are terminal NO_ENTRY and say so.)

### R2 — HIGH: the new mechanism inherits the 4096-page hard latch, and its cost scales with the whole store
`_index` (`desk/paper_cycle_no_entry.py:68-86`) counts and decompresses every page in `evidence.sqlite`, not just those of the retired scans, on every
`publish` and on every `gate` call that has at least one retired record. Above 4096 pages it raises `Cycle no-entry attempt inventory bound`; the callers
turn that into `OBSERVATION_RECOVERY_REQUIRED`, so the whole desk stops, and the next rejection cannot even be published (pass stays NULL).
Measured: one rejected candidate costs 22 pages, so the bound is reached after about 186 rejected candidates (T09 F7 estimated 70-200). Gate time with a single retired
record: 0.018 s at 22 pages, 0.33 s at ~1000, 0.85 s at ~3000-4000; `tools/paper_entry_dispatcher.py` calls the gate at least eight times per dispatch (:315,:353,:392,:636) and the held path once per pass.
Evidence: `tests/test_review_t01_bounds.py` (2 `expectedFailure`: gate raises, publish raises with 4110 unrelated pages; plus a measurement test).
Fix: index only the attempt pages of the retired scans (typed lookup by scan id, or a per-scan page-index table written in the same transaction) and drop the global count bound for this gate.
This is the same defect class as T09 F7 / queued T24; it should not wait for T24 because T01 makes the unattended loop depend on it.

### R3 — MEDIUM: silent, permanent failure to publish
`run_once` swallows `ValueError/TypeError/KeyError/OSError/sqlite3.Error` from `publish` (`desk/paper_cycle.py:688-693`) and `ledger_snapshot` (:536-540). The pass then stays NULL
and the store is latched with no log, marker or counter saying why (for example R2). Fail-closed is right, but the operator needs the reason. Fix: log or record a typed
`publish_refused` reason (not an outcome) so healthchecks and humans can see it. No RED test (observability).

### R4 — MEDIUM: bounded table cap and O(R) replay
`MAX_ROWS=8192` is a trigger-enforced hard stop (the 8193rd rejection cannot be recorded, latching the store) and every gate call replays all R records (29 `_load` calls for one record). At 1000
admissions per day this is a fresh-store ceiling of days to weeks, not a design flaw by itself; combine with R2's fix and plan rotation (RUNBOOK "rotate when flat") before it is reached. No RED test.

### R5 — LOW: `RETAINED_MIGRATION_WITNESS_REQUIRED` is allow-listed but unreachable with a charge, and its validator accepts corrupt graduation witnesses
In `run_once` this blocker is raised before any charge (`desk/paper_cycle.py:561-566`), and `publish` needs `charged >= 1`, so the entry never reaches it; the existing zero-charge branch already resolves such
passes. If it ever became reachable, `_check_result` (:125-130) accepts any graduation status except `OBSERVED_MIGRATION`, including `CONFLICTING_MIGRATION_TIMESTAMPS`, `MIGRATION_ACCOUNT_BINDING_MISMATCH`,
`REGRESSING_SLOT_TIME` (`desk/graduation_witness.py:104-135`), the same mislabelling class as R1. Remove the dead entry or constrain it to `MIGRATION_WITNESS_ABSENT`.

### R6 — LOW (coverage, already declared by T01)
Only `run_once` entry is covered. Category (b) still includes every transport error, timeout and held-pass failure (queued as T22); `paper_history_preparation.prepare` and `paper_observe_cli.observe` are unchanged.

- **Charged request refunded?** No: `progress.admission(scan)` is unchanged by `publish` and `gate` (tested).
