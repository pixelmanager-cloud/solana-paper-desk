## What was built
- `tools/ops/held_watcher.py` (`run`, `latency`):
  - positions are read from the ledger **read-only** (`mode=ro`; `immutable=1` only for a WAL file without `-wal`, per the T02F rule, so it works under `ReadOnlyPaths=`);
  - vault addresses come from `desk.pools.parse_pool` plus the pool PDA check (one `getAccountInfo` per new pool, cached append-only), vault accounts are decoded strictly (owner, layout, initialised, mint);
  - Helius websocket `accountSubscribe` with a `CONNECTED` signal after all subscriptions are acknowledged, seed poll on (re)connect, periodic reconcile poll while streaming (default 30 s), HTTP `getMultipleAccounts` polling fallback (default 2 s), exponential jittered reconnect backoff capped at 60 s;
  - implied mark from vault reserves = `strategy.swap_quote` formula minus the fixed fee, over `cost_left`;
  - triggers: `STOP`, `TRAILING_STOP`, `TAKE_PROFIT` (by stage), `MAX_HOLD`, `TIME_STOP`, `LIQUIDATE`, with a configurable early margin (0.02);
  - trigger method default `path`: atomic replace of a request file watched by a systemd `.path` unit (no sudo, no polkit); `systemctl start --no-block` through an injectable runner; `none` for dry runs;
  - own store `watcher.sqlite` (append-only triggers on its tables): request log = its own allowance (default 3600/h rolling, charged before the call, failures included), spacing between requests persisted, resolved vaults, trigger log, health log; `health.json`;
  - `latency` report: trigger -> next SELL fill from a read-only ledger.
- `deploy/fresh/desk-held-watcher.service` (hardened, `ReadOnlyPaths=<FRESH_ROOT>`, `ReadWritePaths=<STATE_DIR>`, no shared pacing env) and `deploy/fresh/desk-paper-held-cycle.path`.
- `docs/ops/HELD_WATCHER.md`: thresholds table, rate limits, install steps, health codes, failure behaviour, limits.

## Decisions worth knowing
1. **Own pacing, not the shared pacing store.** T09 F6 showed that a kill while holding a pacing ticket blocks every provider call of the desk; a fast side process must not be able to do that. The watcher has its own allowance and spacing and never sets `DESK_PROVIDER_PACING_DB`. (The task text says "its own request allowance and pacing"; the shared Helius 2 s cadence is therefore not honoured, which is deliberate.)
2. **Path unit instead of sudo/polkit.** The task asks for a "polkit/sudo-free method". A `.path` unit keeps the watcher unprivileged. `systemctl` mode exists because the task names it, but needs privileges.
3. **Global minimum gap (5 s) and hourly caps** between requests: one held pass handles all positions, and the held service has systemd start-rate limits that repeated starts could trip.
4. **Engine constants are duplicated** (take-profit ladder 1.4/2/3, touched 1.15, trailing stage 3) because they are locals in `engine.manage_position`; a test parses the engine source (AST) and fails if they change.
5. `DANGER` exits depend on evidence the watcher cannot see; the timer remains the safety net.

## Remaining limitations
- The watcher's mark is an estimate; the held pass may see a different executable quote.
- PumpSwap pools only; unverifiable pools are reported and left to the timer.
- Slot wall-clock time is not recorded, so "event -> trigger" latency is only measurable from the local receive time.
- The 5 s gap and 30 s debounce add up to a few seconds of extra latency in bursts by design.
- `health.json` is not consumed by T21's healthcheck yet.
