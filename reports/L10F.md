## Review items
1. **HIGH, serial 3 s sleep per exit => two-phase exits.** `Execution.run_exits` replaces the runner's exit loop (one `# --- L10 hook ---` before `exits = 0`). Phase 1 runs the normal exit logic for every position; a triggered exit fetches q0 and defers (a `BaseException`, so the per-position `except Exception` isolation cannot swallow it). ONE sleep until the latest q0 + `exec_delay_s`. Phase 2 re-runs the normal exit logic for the deferred positions; its (existing) quote fetch IS q1, and a hook after it pairs it with q0. No extra quote calls: q0 and q1 are the same two calls as before. Positions that do not exit finish in phase 1, so they are never evaluated on a mark that someone else's delay made stale. The deadline comes from the decision (`_restamp` carries each mark's age over to the re-run), not from the pass-start mark, so the re-run decides exactly what phase 1 decided: a bounce during the delay cannot cancel a stop (that would bias results optimistically), and a pass slowed by provider rate limits does not turn exits into STALE blocks. Measured in the test: 6 simultaneous exits => 1 sleep (<= 3 s) and 6 fills in the same pass.
2. **A q1 ProviderError goes through D2's `_exit_failed`.** The old code retried inside its own helper. Now the q1 fetch is the runner's own quote call inside its existing `try/except ProviderError`: a non-transient failure starts `exit_failing_since` (persisted), transient errors retry on the next pass, and the write-off clock runs (`exit_requote_attempts/gap` config keys are removed). Test: q0 passes, every later sell quote has no route => state has `exit_failing_since`/`exit_failing_reason`, the position stays open, the other five exit normally, and with `unexitable_after_s=180` it is written off (`UNEXITABLE`).
3. **Rent and fee accounting.**
   - *Presentation.* `lean.execution.economic()` removes the refundable rent from buy fee / sell proceeds / `cost_sold` / `realized` per fill (the rent share is stored as `ata_rent_basis_sold_lamports`, telescoping so partial sells sum to the full rent). Hooked additively into `report.build` (fill events) and `notify.StoreView` (`fills_after`, `fills_between`, `fill`, `mint_fills`), so exit price, fee, per-sell return and trade cost shown to people are rent-free and per-trade PnL is unchanged. Cash/positions/`check_invariants` and `StoreView.replay` still read the raw rows. Test: prices, fees and returns in the report and in `notify.fill_event` equal the quote-derived numbers.
   - *D2 write-off clears the rent.* `_write_off` gets a hook that records `{'kind': 'write_off', 'ata_rent_written_off_lamports': rent}` in the closing state; the report shows `ata_rent_outstanding = paid - refunded - written off` (0 after a write-off) and the rent stays in the booked loss (it really is lost).
   - *Cost cap includes the priority fee + tip.* They now enter through the effective strategy config (`fixed_fee_sol += priority + tip`), so the paper fill fee, the net marks, the entry round-trip cap (5 fees) and the exit net check use ONE number (0.00025 SOL per transaction by default). `Execution.pcfg` is gone. The `start`-adjacent event `execution_config` records the effective fee; `config_hash` stays the file's.
4. **Non-additive edits restored.** Remaining non-insert diff vs `integration/r1` in `lean/`: the `Runner.__init__` signature (`, execution=None`) and the `build_runner` call (`, execution=exec_model`), plus a trailing comma in the example JSON. `adapters.py`, `report.py`, `notify.py` are pure insertions. Adapter changes wrap the existing functions at module end; the entry/exit/write-off hooks only add statements (the open state is extended through `features['_exec_state']`, the sell state through the existing `state` variable). D2's try/except is untouched.

## Limitations
- The delay is still real wall time inside the position pass (once per pass now). With the providers' exit-lane limit (25% of Jupiter) a pass with many exits is bounded by rate limits, not by the sleep; q1 is at least `exec_delay_s` after the LAST q0, so earlier exits wait a little longer than the configured delay (conservative).
- `_restamp` makes the re-run decide on the same mark age; it does not model the price moving between the decision and the fill (that is exactly the latency tax, measured by q1).
- Rent bookkeeping keeps using the average-cost split; the economic numbers are exact in total per trade, individual partial sells carry integer-rounding differences of a few lamports.
- `config_hash` is the strategy FILE's hash; the effective fee is in the `execution_config` event.
- Still no model for failed/dropped transactions, MEV or partial fills.
