# T13 — Fresh-start store bootstrap + ledger rotation

Branch `cloud/T13`, BASE `r1-base` (c1e22c2). No file under `desk/` changed, so the runtime implementation hash is unchanged by this task.

## What changed
- `tools/ops/fresh_start.py` (new, outside the hash domain): `python -m tools.ops.fresh_start {plan,apply,rotate}`.
  - `plan` is static (creates nothing). It validates inputs and prints the stores, the repo initialiser for each, the budgets, a `plan_hash`, and the environment/argv for `desk-paper-entry-dispatcher`, `desk-paper-held-cycle`, `desk-paper-monitor`, `desk-decisions` and `desk-dashboard`.
  - `apply` and `rotate` are dry runs unless `--execute` is given together with `--approved-plan-hash <plan_hash>`.
  - `apply` creates a 0700 root (it must not exist, no symlinks anywhere in the path, no `..`) holding: `research.sqlite` (JobPersistence + `upgrade_allowance`: 1000 admissions/day, queue 25), `evidence.sqlite` (EvidenceStore + HistoryProgress; admissions default to the 18-request lifetime ceiling), `paper-ledger.sqlite` (`paper_cycle.initialize`: its own implementation hash, no successor/extension rows), the monitoring budget (`provision` then `prepare_upgrade`/`activate_upgrade` to 3600 per rolling hour), `paper-decisions.sqlite` (`decision_runner._initialize_journal`), `entry-dispatch/dispatch.sqlite` (the dispatcher's own `plan` + `initialize`) and the `paper-scheduler.lock` file. It then runs the real dispatcher `_preflight` and the real terminal gate on the new set, and writes `fresh-start-manifest.json` (config digest, implementation hash, store identities, created UTC, scheduler lock identity, unit arguments).
  - `rotate --from OLD --to NEW` proves the old ledger is flat (no positions, mode RUNNING or ENTRY_PAUSED, valid checkpoint) read-only, then runs the same `apply`. The old root is never opened for writing.
- `config/experiments/paper-kraken-fresh.example.json`: `config/paper.json` parameters plus `paper_signal_policy_version` 3, `paper_quote_execution_version` 1, `paper_token_profile_version` 2, `paper_usd_valuation_version` 1 and version `2026-10-11.paper-quote-kraken.fresh.1`. It loads through `cli._config` and `cycle._config`. No keys were invented.
- Tests: `tests/test_ops_fresh_start.py` (16) and `tests/test_ops_fresh_start_lifecycle.py` (5, 1 expectedFailure).

## Remaining limitations
- `plan` is static; unlike `apply`, it cannot run the dispatcher grammar or preflight, because those need the stores. If `apply` fails midway, the partial root is left in place and never reused (the root must not exist). Pick a new root.
- `upgrade_existing()` cannot be used on an empty store: it requires at least one retained admission to prove its lock context. `apply` takes the same locks (research worker, evidence invocation, ledger) and calls `prepare_upgrade`/`activate_upgrade` directly instead. A reviewer should confirm this is acceptable.
- `verify_flat` uses SQLite `immutable=1` so the old root stays byte-identical. It refuses an old ledger with a non-empty `-wal`, so units must be stopped or checkpointed first. It checks the ledger only, not old pending observation passes or whether units are stopped.
- Rotation does not archive or mark the old root read-only. The coordinator does that.
- Unit output is argv/environment only; interpreter, WorkingDirectory and drop-in files are the coordinator's.
- Token profile 2 end to end is not exercised by the inherited fixtures.

## For the coordinator
- Required environment on the host for `apply`/`rotate`: `DESK_PROVIDER_PACING_DB` must equal `--pacing-db` (the shared pacing DB, with the reviewed Kraken pacing migration already applied). The tool only validates it and never writes to it. The discovery DB is only read.
- The dispatcher context pins the config file inode. Do not edit the config in place after `apply`; make a new root instead.
- Every unit using the scheduler needs `DESK_PAPER_SCHEDULER_IDENTITY=<dev:ino>` from the manifest (`scheduler_identity`). The dashboard uses `DESK_PAPER_SCHEDULER_LOCK=<root>/paper-scheduler.lock`.
- Decisions I made (conservative): `apply`/`rotate` need `--execute` plus the exact `plan_hash`; the ledger is named `paper-ledger.sqlite`; the default taker/amount/fee are the production unit's (6E2G…, 100000000, 25); the new root must not nest with the old one.
- Nothing here touches production stores. No `desk/` change, so no runtime successor pin is needed for this task.
