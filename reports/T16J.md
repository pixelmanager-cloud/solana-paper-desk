## What changed (item numbers from the task)
1. **Crash-restart test** (`tests/test_paper_concurrency_held_latency.py`): the abandonment step now runs under `nobody_holds_the_locks()` (lock files created, `LOCK_TABLE`/`PROC_ROOT`
   fixtures with no other holder, T25F style) and asserts `status == COMPLETE` before reading keys; both `attempted_requests` and `monitoring_attempted_requests` are checked (5, 5).
2. **Watchlist** (`desk/watchlist.py`, `docs/WATCHLIST.md`, `tests/test_watchlist.py`): the global `NOT_YET` is again exactly the spec's ten codes. The 11 checkpoint codes plus the new
   `PROVIDER_PACING_PENDING` live in `CHECKPOINT_NOT_YET` and are NOT_YET only as `CHECKPOINT:<reason>` minted by `reason_codes` for `dispatcher_checkpoint_no_entry_v1`; a
   `CHECKPOINT:` string from any other result kind becomes `UNTRUSTED_CHECKPOINT:...` (PERMANENT). Docs table added, `DocumentationTests` covers the new dict.
   Behaviour change: watchlist events now store `CHECKPOINT:<reason>` for these results (`test_watchlist_treats_a_held_side_cut_as_not_yet` updated with the reason).
3. **Post-intent typed terminals** (`tools/paper_entry_dispatcher.py`): `Provider pacing pending` after the intent -> `PROVIDER_PACING_PENDING`; the held guard's mid-phase
   `Held-position priority before I/O` -> `HELD_POSITION_PRIORITY` and `Held cycle or ledger busy` -> `CHECKPOINT_STATE_UNAVAILABLE`, in acquisition (the refusal is recorded
   only when the guard itself raised it, before any I/O) and in intake. Integrity messages (`Source/config changed before I/O`, context/identity changes) still raise and hold.
   Pre-intent pacing pending is unchanged (zero-cost refusal).
4. **SIGALRM during intake**: a test fires the dispatcher's own `_Deadline` handler from inside the charged `_SlotSource` call; the intent ends as `PHASE_CAP_EXCEEDED` at intake, the
   attempt stays charged, no alarm stays armed and the NEXT dispatch completes. No code change was needed.
5. **Docs** `docs/MULTI_POSITION.md`: the activation step now says what the code does (the flag is required for ANY after-mark rollover, batched marks included); a test pins it.
6. **Closed-vault confirmations** (`desk/portfolio_marks.py`, `desk/engine.py`): for the guarded marks (version 2) a null observation counts only >= `CLOSED_MIN_SPACING_SECONDS` (5) after
   the previous COUNTED one; closer ones are reported as unconfirmed. Version 1 is byte-identical (a test pins its old rule).
