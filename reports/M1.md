## #7 marks

### The fix

`lean/marks.py` adds `MarkModel`, which is used by the runner, the path recorder (`paths.sqlite`) and the labels.

**Reserves.** Under `effective`, each marks call reads each position's **pool account** next to its two vaults (one more account in
the same batched `getMultipleAccounts`, no extra request). It also reads the Pump fee program's **FeeConfig** once per call.

- The quote reserve is `vault + virtual_quote_reserves`, decoded with `desk.pools.parse_pool`. The decode is memoized by account
  bytes, because `parse_pool` re-hashes its schema on every call.
- **The accrued fees are NOT subtracted.** The task text said "vault − fees + virtual", and the data contradicts that. On the 486 live
  entries, the screen read the pool and the vaults seconds before the Jupiter quote, so the accrued fees are exact:
  - `vault + virtual` reproduces Jupiter to within 1e-5 on **170** quotes; `vault − fees + virtual` does so on **87**, of which 79 have
    zero fees.
  - One pool had 3.76 SOL accrued. `vault + virtual` matched it to 3e-6; `vault − fees + virtual` was 4 % off.
  - `desk/pools.py` prices the same way (`effective_quote = gross + virtual`).
  - The accrued fees are still recorded with every mark.

**Fee.** The fee is the **market-cap tier** of the FeeConfig (`desk.dynamic_fees.parse_fee_config`; the table is in
`fixtures/mainnet-dynamic-fees.json`):

- market cap = effective quote × supply / base reserve, the same as `desk.dynamic_fees.standard_sol_fees`.
- lp, protocol and creator bps are **each rounded up** on the gross output (pump-swap-sdk `sellBaseInput`).
- A per-coin **`creator_fee_bps`** in the pool replaces the tier's creator component.
- No coin creator means no creator fee.
- **Fallback:** if the FeeConfig is undecodable, missing or older than `schedule_ttl_s`, or the supply is unknown, the fee is
  `pool_fee_bps` as one component. The mark records it as `fee_source: "config"` and `fee_fallback: true`, and `health.marks_model`
  counts it.
- If the pool account is missing or unreadable, the screen's pool fields are used instead (`pool_source: "screen"`).

**Exactness on mainnet data:** the captured `SellEvent` (`fixtures/mainnet-sell-event.json`) is reproduced **to the lamport**. The
output is `quote_amount_out`, the tier fees 2/93/30 give `user_quote_amount_out`, and `desk.sell_fees.standard_sell_amounts` agrees.

### Persistence (reproducible marks)

- **Open position state:** under `effective`, it gets `pool_info`, the screen's virtual reserves, accrued fees and supply.
- **`marks` observation meta:** gets per-mint `marks` with model, base, quote, virtual, accrued fees, effective quote, total fee,
  `fees_bps` components, fee source and fallback flag, pool source, market cap and `net_lamports`. A mark can be recomputed even when
  `errors_only` drops the body. A test recomputes it.
- **Exit decision features:** get `mark_info`.
- **`paths.sqlite` `path_marks`:** additive columns `model, virtual_raw, accrued_fees_raw, fee_bps, fee_source`.
  - An older file gets them by `ALTER TABLE ADD COLUMN` on open. This is idempotent, marked `meta('mark_columns','m1')` and tested on
    a pre-M1 file.
  - The `paths.target` JSON gets `pool_info` under `effective` only, so a vault-model file is unchanged.
  - Under `effective`, the reference quantity of a non-entered path is what `ref_size` buys at the effective reserves and tier fee
    (`buyQuoteInput`).
- **Labels and learner:** `lean.labels` reads the new columns and reproduces an effective mark from them (`labels.mark_lamports` /
  `sell_quote_lamports`), so the learner labels with the mark the recorder used. Vault rows are unchanged.

## #10 outages, feed staleness, config hashes

**Outages.** At every start the runner writes an **`outage`** event with:

- `previous_health_at`: `health.json` `at`;
- `last_store_write_at`: the newest row of any table;
- `down_since`: the later of the two;
- `up_at` and `duration_s`.

A new store writes nothing. `health.last_outage` repeats it.

**Feed staleness.**

- The discovery scan also reads the newest frame's `received_at` (one indexed `ORDER BY seq DESC LIMIT 1`).
- **`discovery_stale`** is written once when the feed has been silent longer than `discovery_stale_s` (an unreadable discovery DB
  counts as silent).
- **`discovery_recovered`** (with `duration_s`) is written once when frames flow again. Only transitions are written.
- `health.discovery_feed` shows the state.

**Config hashes.**

- **`lean_config_hash`** is the sha256 of the whole loaded `lean.json`: every key with defaults filled, `_comment` keys left out, so a
  comment edit is not a new run.
- **`strategy_config_hash`** is `StrategyConfig.config_hash`. The old `config_hash` field is kept.
- Both go into the `start` event and `health`. The start event also records the marks settings, `raw_policy` and the throttles.

**Filtering.** Both new filters accept a prefix of >= 8 hex characters, matched against either hash.

- **Report:** `python -m lean.report --config-hash H`. The funnel, trades, P&L, exit reasons, errors and versions sections are
  restricted to the runs whose start event carries H. A trade belongs to the run of its opening buy, so a trade is never split.
  `summary.config_hash_filter` says which store-level sections are not filtered.
- **Learner:** `python -m lean.learn --config-hash H` keeps only candidates decided inside those runs; the others are skipped as
  `OTHER_CONFIG_HASH`.

The e2e test makes two runs with different `lean.json` files and checks that each hash selects its own trade and the learner skips
the other run.

## #12 storage

**The policy.**

- `raw_policy: "errors_only"` stores each successful provider body as an **empty kept prefix with `raw_truncated=1`**, plus `full_bytes`,
  `full_sha256` and `meta.raw_omitted`. These are the existing truncation columns, so there is **no schema change, no migration, no
  index, no DELETE**. Every reader already handles a truncated body.
- An old store opens under either policy (tested).
- Dropped kinds: `quote:*`, `marks`, `sol_usd`, `screen:*` except the two read back later, and `risk_external:rugcheck`.
- Always kept: `error:*`, `screen:accounts_mint_pool` and `screen:holders` (clusters, bot_exit and sell_evidence parse them), and every
  derived row (features, wallet_signals, flow, clusters and the rest).

**Consumers that read the dropped bodies.**

- `route_check` now gets the filled quote's body from runner memory (the last 64 quotes). With neither copy it records
  `INCONCLUSIVE RAW_NOT_RETAINED`, never a false `NOT_ROUTABLE`.
- `notify.latest_marks` uses the mark stored in the meta.
- Quote meta now also has `in_amount` / `out_amount`.

The e2e test runs the same trades as under `all` with less than a third of the raw bytes, and gets identical `route_check` verdicts.

**Indexes.** I skipped indexes and retention. Nothing here needed them, and adding any would need a versioned change to the exact
schema check (`store._validate`).

## #13 per-pass row spam

**BLOCKED decisions.** An exit decision row that is BLOCKED with the same reasons for the same lifecycle is written at most once per
`blocked_log_s`. The next row written carries `suppressed_since_last`; any other action resets it.

**Exit back-off.** After an exit attempt fails, the next quote waits 10 s, 20 s, 40 s and then 60 s (capped at `exit_backoff_max_s`).
A failed attempt is any of:

- a non-transient quote error such as no route;
- a BLOCKED `NO_ROUTE`, `STUCK_POSITION`, `SELL_QUOTE_INVALID` or `SELL_QUOTE_MISSING`;
- any quote error on a zero mark.

The back-off is reset by a HOLD (the exit is no longer wanted), a rung or a close. The **D2 write-off clock** (`exit_failing_since`) is
persisted and checked before the back-off, so the write-off is due on the first pass whatever the back-off phase. This is tested at
7200, 7210, 7230 and 7250 s.

**Peak-only state rows** (the other per-pass row found: 17,666 `update` rows, 99 % peak-only, a median of 10 s apart).

- They are written at most once per `peak_persist_s`, or at once on a >= 1 % rise.
- In between, the in-memory state is authoritative: `_manage` reads it, and every rung, close or failure row carries it.
- It is flushed on stop (`run()` and `--once`).
- A crash loses at most 60 s / 1 % of peak drift (tested).
- Trading within a run is identical. The persisted peak equals the every-change run's, including a dip inside the window (tested).

**E2E results** on a pool that collapses to dust, so its stop is STUCK for 2 h:

| | before (`blocked_log_s` 0, back-off 0) | after (defaults) |
|---|---|---|
| exit BLOCKED rows | 720 | **24** |
| exit quotes | 720 | **122** |
| D2 write-off | `UNEXITABLE` at +7260 s | `UNEXITABLE` at **+7260 s** (same failing-since) |

The test bounds are > 600 before, and <= 27 rows / <= 128 quotes after.

The same scenario with L10 two-phase execution on, as in production, also passes. Each attempt there is q0 + q1.

## Limitations and follow-ups

- **Pool-account cost.** Under `effective`, a marks call holds 33 positions instead of 50, and a paths call 33 pools instead of 50.
  That is +1 account per position and +1 FeeConfig per call, with no extra request at a few positions. At 700 live paths that is 22
  instead of 14 low-lane calls per 15 s.
- **Positions open at the switch** have no `pool_info`. They use the live pool account, but without the supply the fee is the flagged
  `pool_fee_bps` fallback until they close. Old paths resumed from `paths.sqlite` behave the same.
- **Labels** reproduce an effective mark with the total fee as one rounded-up component, which is within 2 lamports of the recorder's
  per-component rounding.
- **Learner on mixed data:** `--config` takes `pool_fee_bps` from `lean.json`. On paths recorded before the switch (vault rows), use the
  old value or `--config-hash` to stay on one model.
- **Report filtering** covers the event-based sections only. route_check, execution, sell_evidence, held_risk, bot_exit and sources
  read the whole store (stated in the summary).
- **The fee schedule** is the Pump fee program's current one (the fixture is slot 454,363,800). The runner reads the live account, so
  a change is picked up within one marks call. A new allocation size that `parse_fee_config` does not support falls back, flagged.
- **`errors_only` loses the quote bodies of fills.** The amounts, sha256 and route labels stay in the meta.
