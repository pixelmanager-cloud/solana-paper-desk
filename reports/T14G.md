## Findings -> changes
1. **(BLOCKER) The hook can raise inside the pass.**
   - `desk/quote_execution.py::config`: the realism key is now validated BEFORE the quote-execution early return, so an orphaned/malformed `paper_fill_realism_version` is refused with the rest of the config (`qe.config`, therefore `paper_cycle._config` / `run_once` start) before any pass row, lock or charge exists.
   - The in-pass hook is one call to the new `fill_realism.capture(...)`, which wraps flag check and job building and returns `[]` on any defect (only a real KeyboardInterrupt/SystemExit passes). `selected(cfg)` can no longer raise in the pass. The hook line in `paper_cycle.py` is now: `realism_jobs+=fill_realism.capture(cfg,result['outcomes'][before_outcomes:],event,collected,is_position)  # never raises`.
   - Tests: orphan/bad keys refused by `qe.config` and `_config`; a cycle with a bad key is refused with the admission unchanged and zero pass rows; `capture` never raises on broken configs/inputs; a cycle in which the in-pass `selected` is forced to fail (only inside `capture`) still ends COMPLETE with no NULL pass and a clear gate.
2. **Freshness tolerance.** A sample is valid only if its request was SENT within `--late-seconds` (default 1.0) of the due time and FINISHED within `--response-seconds` (default 2.0); otherwise `LATE` (`REALISM_SAMPLE_LATE` / `REALISM_RESPONSE_LATE`, counted, never stored with drift, so excluded from latency-adjusted PnL). The Jupiter client reports the real send time (after the pacing grant), `Age` and, when sent, the HTTP `Date` (a provider timestamp: older than the due second -> `STALE`). Documented in the worker docstring that Jupiter's JSON has NO provider timestamp, so `observed_at` is our receive clock.
3. **Pacing priority.** `desk/provider_pacing.py`: new lowest priority `research` (held < investigation < research), used by the worker. A SEPARATE small commit (`2c8c11a`) touching 3 lines: constant `PRIORITIES`, the constructor check, the waiters validation and the `ORDER BY CASE`. T23F also edits this file and is not merged into `integration/r1`: expect a trivial merge. `tests/test_fill_realism_pacing.py` pins the ordering (a later trading quote goes ahead of an earlier research waiter; research waits behind investigation and held) and that existing priorities are unchanged (`tests.test_provider_pacing` still passes).
4. **Early returns.** `fill_realism.enqueue` now sits right after `outcome = store.save(result)`, before the terminal-receipt and typed no-entry returns (the result page is durable at that point). Tests: an AST order test over `run_once`, a spy that sees the persisted result page at enqueue time, a COMPLETE pass with `no_entry.publish` patched.
5. **Single worker.** The worker takes an exclusive `flock` on `<store>.worker.lock`; a second instance returns `BUSY` (exit 0) without touching the store. The attempt INSERT is inside the try: a duplicate attempt is a recorded no-op (`None`), and a duplicate sample row is skipped instead of `STORE_ERROR`.
6. **Off-path identity.** `tests/test_fill_realism_identity.py` + committed golden `tests/golden/fill_realism_off_identity.json`. The golden was generated by code WITHOUT any hook (`origin/integration/r1`) running the very same fixture pass (`PaperCycleTests.run_cycle`, flag absent); the test runs it on the current code and compares the whole cycle result and the ledger `events`, `outcomes`, `state` rows. The random ids were found by running one tree twice and diffing; the mask is an explicit list of 15 field names (+ the scan-id dict key) and the test asserts both the exact masked list and the exact list of deterministic hex fields left visible (anything new must be classified on purpose). A second test asserts no realism file is created when off.
