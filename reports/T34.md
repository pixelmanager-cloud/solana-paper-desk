## What changed
**Shared options.** `--pacing-db PATH`, `--discovery-db PATH` and an absolute `--ledger PATH` now work in all three tools. Defaults are unchanged: with no option the old in-root behaviour applies and existing tests pass untouched.

- **status**
  - `--pacing-db` (default `<data>/provider-pacing.sqlite`) and `--discovery-db` (default `<data>/discovery/continuous.sqlite` when present, else the section is `SKIPPED`, an explicit but missing/bad path is an `ERROR` + blocker).
  - Both are read `mode=ro` (`immutable` only for a quiet WAL header, as before); a rollback-journal store is never immutable.
  - New `discovery` section (counts, latest completion/event and their ages; reported, not graded: thresholds belong to the healthcheck).
  - Shared stores outside the root appear in `store_inventory` (`external: true`, `role`) with the same symlink / hardlink / `quick_check` handling, so a symlinked or hardlinked shared store becomes `STORE_SYMLINKED` / `STORE_HARDLINKED`.
  - A healthy fresh layout reports `blockers: []` (test).
- **verify_cycle**
  - `--ledger` accepts a plain name inside `--data` or an absolute path; `--pacing-db` (alias of the old `--pacing`) accepts the same, and an explicitly absolute pacing store **must exist** (the old silent `{"present": false}` for a missing default was the failure mode in a fresh root); new `--discovery-db` adds an informational `discovery` block (in `NOT_STRICT`, because the feed grows continuously).
  - Absolute paths get the existing in-root checks when opened: canonical, regular, not a symlink.
  - Name-only validation (no directories, no `..`) is kept for relative values, with the old wording preserved.
- **preflight_dryrun**
  - An absolute `--pacing-db`/`--discovery-db`/`--ledger` outside `--data` is validated (canonical absolute path, no symlink or `..` component, regular single-link file, directory must not contain or sit inside `--data`/`--workdir`), copied with the backup API into `<workdir>/.external/<absolute path>`, and inside the private mount namespace each external directory is bind-mounted from its copy over the real directory. The child therefore reads the copies at the real absolute paths, while the rest of that directory (for example the archived old stores) is hidden.
  - Multiple binds go through a single `unshare` script (`while … mount --bind …; exec`); guard `allowed_roots` include the bound directories.
  - Same live checks as in-root stores: pacing mode `0600`, owner = expected service user (new finding names `external_<store>` for discovery/ledger), directory not group/world-writable. A changed sha256 of an external store during the run, or a `-wal`/`-shm`/`-journal` that appears beside one, is a blocker. Absolute paths inside `--data` are treated as the relative name (no mirror).
  - `_copy(data, work, sources)` keeps its signature (existing tests patch it); external copying is `_copy_external`.

## Findings / limitations
- **A ledger outside the experiment root cannot pass the production entry pre-check:** `tools/paper_scheduler.py:68` requires `ledger.parent == research.parent`. The tools accept an absolute `--ledger` (copied, gated, snapshotted), and preflight then reports `SCHEDULER_ERROR: Scheduler ledger context mismatch` (tested). That is correct fail-closed behaviour, not a bug; in the fresh layout the ledger stays in the root.
- `--no-namespace` still cannot reproduce stores that pin absolute paths; with external stores it fails closed (guard violation / blocked stages) instead of passing.
- The namespace tests need Linux `unshare` + `mount`; they ran here (root). On macOS only the always-run guard tests execute.
- Mount propagation relies on `unshare --mount`'s private default; a host with a shared root propagation override was not tested.
- `status` only reports discovery ages; alerting thresholds stay in `tools.ops.healthcheck` (T21).
- `live_sources_unchanged` is strict for the shared pacing store too: if a live writer touches it during the copy window the run reports `LIVE_SOURCE_CHANGED_DURING_RUN` and must be repeated (entry timer off makes this rare; not observed in tests).
