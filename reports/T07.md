## What changed and why
`python -m tools.ops.entry_latch --ledger L --config C [--apply]` (new `tools/ops/entry_latch.py`, namespace package, no `__init__.py`).
- Default is read-only: validates the ledger exactly like `paper_cycle._state` (marker, saved config == file config, runtime identity, verified checkpoint), then reports BUY-fill count, first BUY event id, fill labels (`EXECUTION_UNVERIFIED`), mode, open positions, whether already latched.
- `--apply`, only when >=1 BUY fill AND mode is `RUNNING` AND no latch exists: takes the existing `<ledger>.paper-cycle.lock` (non-blocking), re-proves state under the lock, delivers ONE operator `PAUSE_ENTRY` control via `Ledger.apply` + `qe.bind_transition` + `engine.transition` (same path as `paper_cycle` control delivery; no direct state writes), then re-reads the checkpoint and fails (exit 2) unless mode is `ENTRY_PAUSED`.
- Idempotent: event id is `entry-latch:v1:<first BUY event id>`; a second run is a no-op (mode already blocked, or latch event exists).
- Exit codes: 0 nothing to do/reported/latched; 2 unavailable or unsafe (fail closed); 3 ledger busy. Output is one JSON line with no paths or raw errors.
- `deploy/drop-ins/entry-latch.conf.example`: example ExecStartPre + ExecStartPost only (no existing unit changed).

## Remaining limitations
- Spec item "held position with exit_blocked still pausing": the engine already forces `EXIT_ONLY` whenever any position is exit-blocked (`engine.risk`), so entries are blocked and the tool deliberately does not convert that to `ENTRY_PAUSED` (would relax a stricter mode). Test documents this. A forged RUNNING+exit_blocked checkpoint is not reachable through valid ledgers.
- Mode `ENTRY_PAUSED` is sticky by engine design; only an operator `RESUME` clears it, and the tool will not re-latch after that (exactly one latch per ledger).
- The latch is per ledger (not per experiment version); a rotated ledger gets its own latch after its own first BUY.
- Control ts is the wall clock; if it is behind the ledger's last_ts the tool refuses (exit 2) instead of back-dating.
- Not exercised against production stores or systemd; unit wiring is an example only.

## For the coordinator
- Run from the same release WorkingDirectory as the entry unit: `Ledger.apply` and `_state` enforce the runtime implementation hash, otherwise the tool exits 2 (UNAVAILABLE) and writes nothing.
- Use both hooks: ExecStartPre (non-zero exit blocks the entry tick if a BUY exists but the latch is busy/unavailable) and ExecStartPost (latches right after the entry that produced the first BUY). Exit 3 = a held/cycle process holds the ledger lock; the next tick retries.
- Dry-run before enabling: `python -m tools.ops.entry_latch --ledger L --config C`.
- Judgement calls (conservative): only `RUNNING` is paused; no RESUME ever issued by the tool; no auto-retry; no reconciliation with old stores; nothing in `desk/` or hash domain touched, so no successor pin is needed for this task.
