# L16 — live-route check at entry and full exit (no signing)

Branch `cloud/L16`, BASE `origin/cloud/L09` (real lean modules, no stubs). Paper only: nothing is signed, sent or keyed.

## Design
The lean quote already calls Jupiter's `/swap/v2/build` with the public paper taker (`PAPER_TAKER`), so a *second* build call per
trade would only burn rate limit. `lean/route_check.py` therefore analyses the response of THAT call (kept as an observation) for
every paper BUY and every **full** exit: buildable = non-empty `routePlan` + a `swapInstruction`; it records route labels,
compute-unit limit, CU price and the priority-fee suggestion (decoded from the ComputeBudget instructions or top-level
fields), the swap program and only the *size* of the instruction data. When the quote call fails, the failure is the answer:
`NOT_ROUTABLE` with the provider's own `errorCode` (e.g. `COULD_NOT_FIND_ANY_ROUTE`).
Every row carries `signed=false, sent=false`. If the error says the taker needs funds/balance/simulation, the check records
`ROUTE_CHECK_UNSUPPORTED` **once**, disables itself (a `route_check_disabled` event, so it survives restarts) and does not work around it.
Rows are `decisions(kind='route_check', action ROUTABLE|NOT_ROUTABLE|UNSUPPORTED)`. Report: new section "Live-route check" with routable % at entry and exit and not-routable reasons.

## Files
New: `lean/route_check.py`, `tests/lean/test_route_check.py`, `tests/lean/test_e2e_route_check.py`.
Additive hooks (marked `# --- L16 hook ---`): `lean/runner.py` (~25 lines: constructor, buy-quote error, after BUY fill, exit-quote error for full exits, after full close),
`lean/__main__.py` (`route_check` config key, default `{}` = off), `lean/report.py` (one section), `config/lean/lean.example.json` (`"route_check": {"enabled": true}`).
Shared limiters are untouched (no extra calls), exits are not slowed.

## Tests / evidence
* `python -m unittest discover -s tests/lean -t .` → **293 tests OK in one process**, including `test_e2e_real` (now running with the check on).
* Units: build analysis (route, CU limit, CU price, fee, top-level fields, garbage budget, no route, no swap, malformed), error analysis, disabled-by-default,
  unknown-config-key refusal, side/flags on every row, summary math, UNSUPPORTED once + persisted, missing observation.
* **No-signing test:** an AST walk of every `lean/*.py` (names, attributes, imports, non-docstring string constants) fails on `sign*`, `send_transaction`/`sendTransaction`,
  `Keypair`, `SigningKey`, `secret_key`, `private_key`, solders/nacl/solana-rpc imports; a second test proves the walker fires on a synthetic offender.
* E2E on `fakeworld` with real modules (only HTTP faked): A entry+exit routable; B the exit route vanishes → repeated `NOT_ROUTABLE` exits with the provider code, position stays open,
  then `ROUTABLE`, report % = 100 entry / exit checked = failures+1; C funded-taker answer → exactly one `UNSUPPORTED`, restart does not re-probe, screening keeps working;
  D disabled by config records nothing; E a failed PARTIAL take-profit quote is not counted as a full-exit check.
* Mutations killed: exit hook removed; unsupported does not disable; buildable ignores the swap instruction; entry-error hook removed;
  partial exits counted as full (needed scenario E — it initially survived); disabled flag not persisted.

## Limitations / for the coordinator
* The real `/swap/v2/build` response shape was taken from the repo's fakeworld/fixtures (instructions + `computeBudgetInstructions`, not a serialized transaction); if live responses differ
  (e.g. a serialized `transaction` instead of `swapInstruction`), `analyze()` reports `NO_SWAP_INSTRUCTION` — adjust the one predicate. Not verified live.
* "Would a transaction be built" is judged from the same call that produced the paper quote; a second independent build call per trade was deliberately not added (rate limit). The check also cannot see on-chain landing, only buildability.
* Quote *sell-leg* failures at entry and failed partial exits are errors, not route-check rows (only BUYs and full exits are checked, as specified).
* `lean/` and `desk/` pins are unaffected; `desk/` untouched.
