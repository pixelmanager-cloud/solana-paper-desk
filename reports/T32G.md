## What changed, per item
1. **(BLOCKER) Seal and live lock files.** `seal-archive` now changes only an explicit allow-list: the sqlite family
   (`*.sqlite`, `-wal`, `-shm`, `-journal`) plus per-run `--seal-pattern` globs (a pattern that names a lock is refused). Every
   `*.lock` file (`*.discovery.lock`, `provider-pacing.sqlite.holder-*.lock`, `*.paper-cycle.lock`, `*.ownership-invocation.lock`,
   `paper-scheduler.lock`, `.daily.lock`, dispatcher locks), the two shared databases and every file outside the allow-list are left
   exactly as they are (owner, mode and mtime asserted) and reported (`untouched_locks`, `untouched`, `unlisted`). The e2e seeds the
   lock files, and after the seal opens `discovery.continuous.worker(...)` (the real function from `discovery/continuous.py:61`).
2. **(MED) Seal permissions + manifest + unseal.** Files `root:solana-desk 0440`, directories `0550`, shared directories `1770`
   (no world access). Entries that are already root-only (uid 0, no group/other bits) stay `0600`/`0700` root. Before the first
   change `--manifest` (mandatory; new file, `0600`, outside the root, exclusive) records path, type, uid, gid, mode and sha256 of
   every entry it will change. New `unseal --manifest` restores the exact numeric owner/group/mode and refuses, changing nothing, on a
   missing/retyped entry, a file modified while sealed, a path escaping the root or a malformed manifest. RUNBOOK rollback runs it.
3. **(11b) Research units.** `render-units` now renders `.path` units too and writes the optional research units
   (`desk-counterfactual.service|.timer`, `desk-held-watcher.service`, `desk-paper-held-cycle.path`) to `<out>/research/`, so the RUNBOOK's
   default `install $UNITS/*.service $UNITS/*.timer` can never pick them up; a missing research template is refused. The
   counterfactual service template was hard-coded to the old layout (`/var/lib/solana-desk/exp-FRESH/...`, `/opt/solana-desk`) and is
   now fully placeholder-based (`<FRESH_ROOT>`, `<RELEASE_DIR>`, `<DISCOVERY_DB>`, `<PACING_DB>`, `<PACING_DIR>`, `<DISCOVERY_DIR>`), with
   `--evidence-db` added to `ingest` (read-only) and `WorkingDirectory=<RELEASE_DIR>`. New RUNBOOK step 11 installs, initialises
   (`counterfactual init`) and enables them explicitly; their write scope and the pacing-directory requirement are documented.
4. **(Step 0)** The RUNBOOK no longer tells anyone to make `/var/backups/solana-desk` service-owned: it is `root:root 0755` and
   "never chown or chmod it"; `apply` creates only `$BK` in it. Tested twice (RUNBOOK text; owner/mode of the parent unchanged by the flow).
5. **(Step 2)** `systemctl reset-failed 'desk-*'` after the stops; expectation is "disabled or static" (a `static` unit stays static
   under `disable`). The e2e seeds two `failed` units and several `static` ones like the VPS and asserts all end `inactive`.
6. **Watchdog grace.** `desk-notify-watchdog.timer` used `OnBootSec=300`, which fires immediately when the timer is started
   mid-uptime (its elapse is in the past), i.e. before the first `health.json`. It now uses `OnActiveSec=600`: counted from the moment
   it is started at cutover (or activated at boot), >= the 600 s staleness limit; the healthcheck timer keeps `OnBootSec`
   so it still fires at once. A missing report stays CRITICAL (no silent pass).
7. **Archive verification.** `verify_records` compares uid/gid too (symlinks are `lchown`ed best effort when copied). A crash while
   removing the originals is resumable: re-running `archive-dropins` with the same name verifies the archive again, requires every
   original still present to equal its manifest record (nothing edited, nothing extra in a directory about to be removed), then
   removes what is left (`resumed: true`). An archive without a manifest (copy never finished, originals untouched) is refused as
   incomplete. `rollback --restore-archive` no longer refuses a half-removed state that the manifest fully describes (leftover
   originals equal to their record, or an original unit file that was never removed); foreign files are still refused.
8. **RUNBOOK note.** "Every tool invocation runs with cwd = $REL", why (stale `desk` in site-packages would shadow it) and the
   optional `$PY -m pip uninstall -y solana-desk`.

## Remaining limitations
- Not run against real systemd, a real root, or the real VPS (no access): `chown`/`lchown` to `root:solana-desk`, `/proc`-independent
  but root-dependent behaviours are exercised through the injectable `Ops.chown` and numeric uid/gid assertions. The sandbox runs as uid 0, so
  the "root-only" rule is tested by patching `cutover.ROOT_UID`.
- `unseal` restores recorded owner/mode but cannot restore content: it refuses on any modified store. It does not re-create
  deleted files and does not know about files the operator added after sealing.
- Files outside the allow-list (and non-matching extras such as `.json`) remain writable by the service user after seal; they are
  listed (`unlisted`) so the operator decides, instead of being changed blindly.
- `systemd-analyze verify` for the research units is part of RUNBOOK step 11 but is faked in the sandbox; the `ReadWritePaths`/`ReadOnlyPaths`
  nesting for the counterfactual unit is the pre-existing design and still "not executable-verified without systemd".
- `cutover rollback` does not remove research units installed by step 11 (not in the archive manifest); step 11 documents undoing them first.
- A manifest from a second `seal-archive` run records the already-sealed state; use one manifest per run (the RUNBOOK's `$SM` is exclusive).
