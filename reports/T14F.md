## What changed and why (each coordinator finding)
T14 slept and re-quoted inside `run_once`'s `finally` while the pass row was NULL. Now the trading pass only ENQUEUES; a separate worker measures.
1. **The pass only enqueues, after the outcome is durable, and cannot raise.** `desk/fill_realism.py` keeps only `selected`, `collect`, `enqueue`, the store schema and the drift math. `collect` is pure and wrapped (returns `[]` on any defect); `enqueue` appends to a SEPARATE file `<ledger>.fill-realism.sqlite` and swallows every error (a real `KeyboardInterrupt/SystemExit` still propagates). No sleep, no requote, no charge, no lock, no ledger write. Hook in `desk/paper_cycle.py` (exact lines, all behind the flag): (a) `from . import engine, quote_execution as qe, fill_realism`; (b) `attempt_refs=[]; terminal_hazards=(); realism_jobs=[]`; (c) `before_outcomes=len(result['outcomes'])` before `deliver(event,quotes)`; (d) `if fill_realism.selected(cfg): realism_jobs+=fill_realism.collect(result['outcomes'][before_outcomes:],event,collected,is_position)` after it; (e) `if realism_jobs:fill_realism.enqueue(path,realism_jobs,digest(cfg))` immediately before the final `return {**result,'evidence_hash':outcome}` (i.e. after the pass-row UPDATE). Nothing else in the file changed; T14's `finally` measurement block is gone.
2. **Separate worker, own allowance, shared pacing.** `tools/ops/fill_realism_worker.py` (timer-driven one-shot, or `--follow-seconds N` service mode). It opens ONLY the measurement store (a test spies every `sqlite3.connect`), never the ledger/research/evidence stores. Samples are scheduled by absolute due time across ALL jobs (`ORDER BY decision_at + delay`), so simultaneous fills keep their +2s/+5s samples while the shared Jupiter pacing (2s cadence) allows; anything that cannot start within `--late-seconds` (default 4) is recorded `LATE` with its actual lag and NO request. Own rolling-hour allowance (default 60/hour) recorded in an append-only `fill_realism_policy`; an exhausted allowance records `REALISM_ALLOWANCE_EXHAUSTED` (charged 0), never a silent partial.
3. **Freshness.** A sample is valid only if the quote's `observed_at >= floor(decision_at + delay)` and its `Age` header is <= 1s; otherwise `STALE`/`REALISM_STALE_QUOTE` (charged 1, no drift number stored, excluded from stats, counted). A response completing more than `late + 8s` after its due time is `LATE`/`REALISM_RESPONSE_LATE`.
4. **Error handling and restart.** Every sample outcome is exactly one row; the per-sample catch-all maps client errors, invalid bodies (`REQUOTE_INVALID`) and anything unexpected (`REALISM_INTERNAL_ERROR`, message never stored) to charged FAILED rows. An `attempt` row is committed BEFORE the request; a kill leaves it, and the next start records `REALISM_INTERRUPTED` (charged) and never re-requests it (tests: kill on the +5s request; kill before the first request costs nothing; restart is idempotent). The worker cannot touch NULL/outcome pass state: it never opens those stores, and a test shows the trading stores byte-identical (sha256) after a worker crash and the terminal gate still clear.
5. **Byte-identical when off.** With the key absent the hook is `if fill_realism.selected(cfg)` -> False: `collect/enqueue` never run, no file is created (test). Differential evidence against `r1-base`: the same deterministic fixture cycle (`PaperCycleTests.run_cycle`, flag off) run under both source trees gives an identical cycle result and ledger `events`/`outcomes`/`state` once the random ids are masked (71 distinct ids in each tree, structure equal after masking; the only raw difference was the first-appearance numbering of two random hashes).
6. **Coverage.** `fill_realism_report` now reads the ledger and the store (both `mode=ro`), binds every job to its ledger fill (`record_json` must equal the fill's `quote_execution`, `decision_ts` must equal the event ts), re-verifies every sample and reports, per side (entry/exit) and delay: fills, enqueued, `not_enqueued`, and per delay measured / late / stale / failed / pending with the non-measured codes, plus lag statistics. `coverage_complete` and a `PARTIAL_COVERAGE` warning make partial data impossible to miss; latency-adjusted PnL is computed only for trades whose every leg is measured.

## Remaining limitations (honest)
- A re-quote is not a fill (no landing time, priority fees, MEV, partial fills); real latency is probably worse than this measures.
- The shared Jupiter pacing allows one request per 2s across ALL units: four simultaneous fills need 12 samples in 10s and cannot all be on time. That shows up as LATE rows and lower coverage, by design (never as a silent bias).
- Jupiter responses carry no provider timestamp: `observed_at` is our clock at response completion. Staleness protection is therefore the fresh request itself, the `Age` header and the lag checks; a cache that strips `Age` cannot be detected here.
- `decision_at` is the wall clock at fill delivery (float), `decision_ts` the ledger event second; both stored.
- The real `JupiterQuoteClient` and the pacing integration were not exercised against Jupiter (no provider calls allowed).
- The typed mint used for parsing is rebuilt from the stored decimals (the decision-time mint was already validated by the cycle).
- A fill whose job could not be enqueued (disk full, kill between outcome and enqueue) is reported as `not_enqueued`, never imputed.
