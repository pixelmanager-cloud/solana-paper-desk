# T44 — Lean-desk simplification inventory (analysis only)

Branch `cloud/T44`, base `origin/integration/r1` (`b89864c`). Only `docs/design/LEAN_DESK_INVENTORY.md` (and this report) were added; no code, test, config or unit was touched.

## What the document contains
Sections 1-7 of the task, each with file:line references on the base tree: 13 global-latch sites (L1-L13) with what they protect and a per-candidate replacement; the identity pins
(`implementation_hash`, runtime chain, 180 KB of config pins, dispatcher context, scheduler inode); a table of 25 legacy/reconciliation/retirement/successor modules with lines, own
tests, callers and a delete / replace / keep verdict; the places that re-prove history on every gate with cost classes; the minimal core (65 modules / 13,493 lines vs 86 / 19,630 with
the gates, and the 17 import edges that drag the legacy machinery into it); size totals and risks; a migration path that keeps the current desk running.

## Numbers and how they were obtained
* Static import graph over `desk/`, `tools/`, `discovery/` by AST including function-local imports; reachability from the `deploy/fresh` entry points. Scripts were scratch files (not committed).
* Delete set: 20 modules, 6,289 lines, 18 own test files, 4,679 test lines, 349 test defs (static `def test_` count; `test_empty_history_successor*` not counted). 47 other test files (754 defs) mention
  a deleted/replaced module and need edits. Replace set: 5 modules, 1,834 lines.
* Measured: `implementation_hash()` 37 ms per call over 156 files / 3.6 MB; one `terminal.gate` on a fresh store with one receipt about 1.6 ms (cProfile, 5 calls). Costs that grow with history (O(R x P), O(N) blobs) are quoted
  from the T09 audit and the T24R benchmark, not re-measured here.

## Limitations
* "Reachable" is static: a lazy import counts even if a branch never runs on a fresh store. The run-time column of section 3 is a judgement from the module docstrings, callers and the gate profile, not a coverage run.
* The base is `integration/r1`; the T22 line (FAILED_CHARGED), T24R, T35/T16G+ and T16J live on branches and are only referenced.
* Test counts are static; the real suite size (about 2,900 per the coordinator) was not run.

## For the coordinator
* The cheapest, zero-risk first wave is the 7-module `common_bank_*` family (3,128 lines, 192 test defs, no operational caller) plus the two `tools/verify_*_originals`.
* The risky one is `ledger.py`/`paper_checkpoint.py` (dropping the code-hash comparison): it is the single file every number depends on, so it should come after the shadow run.
