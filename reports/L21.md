# L21: external risk rows (RugCheck, creator history, copycat)

BASE: `origin/integration/r1` (8c64fc8). `desk/` untouched. Paper only. The feature is **recording only**: nothing in it is read by `lean.strategy`,
and it changes no entry or exit decision. An e2e test runs the same world with it on and off, and the decisions, fills and cash come out identical.
The default is **OFF**: if `risk_external` is absent or null in lean.json, no client is built, no thread starts and no row is written.
`config/lean/lean.example.json` turns it on.

## What it records
There is one `observations(kind='risk_external')` row per screened, **hazard-free** candidate, using the same rule as `lean.features.hazard_free`: a PASS, or a reject only for the
soft market bands. Hazard rejects and failed screens cost nothing. A mint is collected once while it is soft-rejected, and once more after a screen passes, so a
watchlist re-screen does not buy a new row every 5 min. The row is canonical JSON in `raw`, and the same payload goes in `meta`:
`{version: risk_external_v1, mint, candidate_id, screen_passed, decision_ts, collected_at, late_s, calls, fields, missing, flags, identity, raw, source}`.
Every field is listed; a None value always has a reason in `missing`.

| # | fields | source |
|---|---|---|
| 2 | `rc_score`, `rc_score_norm`, `rc_risks` ([{name, level}] <= 20), `rc_danger_count`, `rc_warn_count`, `rc_total_holders`, `rc_graph_insiders`, `rc_insider_network_count`, `rc_insider_largest_pct` (largest network `tokenAmount` / `token.supply`), `rc_top10_pct` (top 10 `topHolders.pct` with the AMM / pool vault excluded: an owner or address of a `markets` entry or a `knownAccounts` AMM), `rc_lp_locked_pct` (max `markets[].lp.lpLockedPct`, so the `/report/summary` call is not needed), `rc_rugged` | `GET https://api.rugcheck.xyz/v1/tokens/<mint>/report` |
| 3 | `creator_tokens_7d`, `creator_tokens_30d` (the creator's OTHER tokens created before the decision), `creator_dead_30d` (`marketCap` < `dead_mcap_usd`), `creator_sampled`, `creator_rugged_sampled` (`rugged` of the newest <= 3 of the 30-day tokens, one report call each; a partial sample is a reason, not an undercount) | `creatorTokens` of the same report |
| 8 | `copycat_of_recent` (distinct tokens collected in the 24 h BEFORE the decision with the same normalized name OR symbol; also `copycat_name_count` / `copycat_symbol_count`), `same_image_count` (same IPFS CID, else the same URL without its query) | `tokenMeta` / `fileMeta` of the report + this recorder's earlier rows (reloaded from the store after a restart) |

Normalization is NFKC, case-folded, letters and digits only, so `$PEPE`, `Ｐｅｐｅ 🐸` and `Pe-pe.` are all `pepe`.

## Timing and the lookahead guard (item 4 and item 5)
* **Hand-over:** a delimited runner hook (`_l21_submit`, `# --- L21 hook ---`) runs right after the screen decision is written. It is a non-blocking `put_nowait`.
  The calls therefore run on the recorder's thread while the trader quotes the entry. In the e2e worlds `late_s` is a few seconds (asserted at most 10 s).
* `decision_ts` is the candidate's own `screen` decision, read from the store. It is the last one at or before the hand-over, so a later re-screen is never
  borrowed. `collected_at` is when the row's LAST call returned, and `late_s = collected_at - decision_ts`.
* RugCheck answers as of the call, so **every non-null field is flagged `AT_COLLECTION`**. `lean.learn` now reads `risk_external` rows (`RISK_FEATURES`,
  `risk_values`) under the same guard as the L12F rows:
  - `_pick`: the row's own `decision_ts` must be at or before the learner's decision;
  - `late_s <= max_late_s` (default 15 s);
  - a value with no flag, or with any other flag, is excluded and counted;
  - another version is skipped.
  Creator tokens created after the decision are not counted. Copycat compares only against rows collected at or before the decision.
* The recorder skips a candidate that is already later than `max_late_s` (default 30) when its turn comes, and records `COLLECTED_TOO_LATE`. The learner would
  exclude that row anyway.
* `runner_changes` proposes `wait_for_risk_external:<features>` for any rule that uses these features.

## Calls, budget and health (item 6)
* The provider client `providers.RugCheck` is additive. It makes a keyless read-only GET with no redirects, through the shared `Transport`, so it gets strict
  JSON, bounded reads and typed errors:
  - `UNKNOWN_MINT` (HTTP 400/404);
  - `HTTP_429` / `HTTP_5xx` / `TIMEOUT` (transient);
  - `RESPONSE_MALFORMED`, `RESPONSE_INVALID` (not an object for THIS mint), `RESPONSE_OVERSIZED` (> `max_bytes`, 4 MB);
  - `ARGUMENT_INVALID` (not a base58 mint; nothing is sent).
  It has its OWN token bucket (`rate_per_s`, at most 1/s, burst 1) and never touches a Helius or Jupiter lane. `max_attempts` is 1: a failure becomes a missing
  field. A 429 opens a back-off window of `max(backoff_s, Retry-After)`; inside it nothing is sent (`RC_BACKOFF`).
* `ops`: RugCheck calls are counted by the L15 tracker under `rugcheck` at **0 credits**. `DEFAULT_COSTS` gained `rugcheck`, and `merge_costs` now accepts the
  keys of `DEFAULT_COSTS`.
* **Health:** `health.json` has `risk_external = {enabled, alive, queued, rows, calls, errors, shed, queue_full, late, backoff, stopped, unknown_mint, http_429,
  raw_kept, dropped, last_error, backoff_s}`.
* **Thread:** the recorder runs on its own daemon thread, joined inside the existing LINT2b shared stop deadline. No lock is held during a call; a test proves
  `submit` and the store stay free while a call hangs. A full queue drops the candidate without a row. On stop, the queue is dropped with no call and no row.
* **Raw bodies:** a body up to `raw_max_bytes` (16 KB) is kept as `observations(kind='risk_external:rugcheck')`. Larger bodies are recorded by size and sha256
  only.

### Call budget at ~70 candidates/h (upper bound: all of them hazard-free)
| | calls / candidate | calls / h | req/s |
|---|---|---|---|
| typical (creator has no 30-day tokens: 19 of the 20 public reports probed had `creatorTokens: null`) | 1 | ~70 | 0.02 |
| expected (~5 % of creators sampled x 3) | ~1.15 | ~80 | 0.022 |
| worst case per row (report + 3 samples) | 4 | 280 | 0.08 |
| absolute ceiling (2 rows per mint x 4) | 8 per mint | 560 | 0.16 |
| hard cap of the bucket | | 3600 | 1.0 |

* Helius / Jupiter: **0** extra calls and 0 credits.
* Time per candidate at 1 req/s is about 1 s, or about 4 s with a sample, so `late_s` stays well under the learner's 15 s.
* Volume: a fresh pump.fun report was 10 to 45 KB in the probe, so about 1.8 MB/h is downloaded.
* lean.sqlite growth: each row is about 2 KB (about 3.4 MB/day). Kept raw bodies add at most 16 KB x 70 = 1.1 MB/h; most pump reports are larger than 16 KB,
  so in practice it is less. Set `raw_max_bytes: 0` to keep none.

## Config keys (`risk_external`, strict; unknown keys refused)
| key | default | meaning |
|---|---|---|
| `enabled` | `false` | absent / null = off |
| `rate_per_s` | 1.0 | 0.01 to 1.0: the RugCheck bucket |
| `timeout_s` | 10.0 | per request; the call deadline is `timeout_s * max_attempts + 5` |
| `max_attempts` | 1 | 1 to 3 |
| `max_bytes` | 4194304 | the largest report body accepted |
| `queue_size` | 200 | 1 to 10000 |
| `max_late_s` | 30.0 | a candidate later than this is not called |
| `creator_sample` | 3 | 0 to 3 report calls on the creator's newest prior tokens |
| `dead_mcap_usd` | 10000 | `creator_dead_30d` threshold |
| `copycat_window_s` | 86400 | how far back copycat looks |
| `raw_max_bytes` | 16384 | keep the raw body only up to this size |
| `backoff_s` | 60.0 | minimum silence after a 429 |

The production lean.json has no `risk_external` key, and it loads unchanged with the feature off (tested: the shipped example with the key removed loads to the
same config except `risk_external`, and `tests/lean/lean.baseline.json` loads off).

  - the learner guard on rows from the real `build_row`.
* `tests/lean/test_e2e_risk_external.py` (7 tests, fakeworld plus a fake `api.rugcheck.xyz`):
  - trading is identical with the recorder on and off, and off sends no RugCheck request;
  - one row per hazard-free candidate with real values, `decision_ts` equal to the stored screen decision, `late_s` <= 10 s, copycat and creator history,

  - `run()` starts the thread (`alive`) and stops it;
  - **learner on real rows:**
    - on time: `rc_score` is read and the planted rule is CONFIRMED, and the proposal says `wait_for_risk_external:rc_score`;
    - a world collected 60 s late: every value is excluded (`AT_COLLECTION_LATE` x 40), and only relaxing the guard brings them back;
    - a row stamped after the decision is skipped and counted.
* **Mutations:** `tests/lean/l21_mutate.py` kills **29/29**, covering the recorder and its decision lookup (20), the client (4) and the learner guard (5).
  `tests/lean/lint3_mutate.py` still kills **33/33**.
* **Full lean suite in one process:**
  `TMPDIR=/private/tmp/ .venv/bin/python -m unittest discover -s tests/lean -t .` ran **966 tests, OK (skipped=1), rc=0**. The baseline before L21 was 927.
* **Provenance:** the report bodies in the tests are synthetic. Their shape (keys, Go nulls, nanosecond times, pool vault in `topHolders`) was taken from a

  committed, and no test touches the network.

## Limitations
* **Snapshots, not history:** RugCheck figures (score, holders, insiders, `rugged`, and the creator's tokens' `marketCap`) are as of the call. The flag and
  `late_s` say so, and the learner enforces it.
* **`creatorTokens` coverage:** it lists only what RugCheck has indexed. A null value is taken as "none" (Go writes an empty list as null), and the row says
  `identity.creator_tokens = 'null'` so an analyst can separate it from `'listed'`.
* **No Helius DAS fallback:** pump.fun metadata has no `creators` array, and DAS assets have no creation time, so a fallback could not give 7 / 30-day counts.
* **No image hashing:** the image is compared by IPFS CID or URL. Hashing it would mean fetching arbitrary URLs.
* **Copycat scope:** it compares only against tokens this recorder collected, which are the hazard-free ones, not every screened token.
* **Rate limits:** RugCheck's public limits are undocumented. 1 req/s plus the 429 back-off is a conservative guess and should be watched in health
  (`http_429`, `backoff`).
* **Hand-over timing:** the hook runs before the entry quote. If a screen is followed by an entry, the row's `decision_ts` is the screen decision; it is
  never later than the learner's decision for the candidate.
